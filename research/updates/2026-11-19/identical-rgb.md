# 같은 영상 입력으로 브라우저와 PC 비교

[실험 요약](README.md)

## 무엇을 비교했나요?

같은 영상을 처리해도 실행 환경에 따라 관절 좌표가 달라지는지 확인했습니다. 보행 영상에서 고정한 10구간의 같은 RGB 픽셀을 브라우저와 PC의 MediaPipe 입력에 전달했습니다. 두 환경 모두 Full 모델을 CPU의 영상 모드로 실행했으며, 구간마다 새 추적기를 만들어 두 번씩 실행했습니다. 한 구간에서는 앞선 35프레임을 먼저 처리했을 때도 같은 평가 프레임의 좌표가 달라지는지 비교했습니다.

## 결과

| 확인한 항목 | 결과 |
|---|---|
| 같은 환경에서 반복 | 입력과 추적 시작 조건이 같은 22쌍에서 전체 관절 좌표 필드가 일치했습니다. |
| 브라우저와 PC의 관절 좌표 | 같은 RGB를 넣었을 때 10구간의 관절 좌표 거리 중앙값은 구간별로 5.00~7.23픽셀이었습니다. |
| 무릎 움직임 범위 | 영상 품질 조건을 적용한 뒤에도 환경 간 최대 차이는 왼쪽 6.99°, 오른쪽 3.30°였습니다. |
| 걸음 빈도를 계산할 수 있는지 | 환경 간 20쌍 중 4쌍에서 두 환경 모두 값을 얻었고 값이 같았습니다. 2쌍은 브라우저에서만 값을 얻었고, 나머지 14쌍에서는 두 환경 모두 계산 불가였습니다. |

한 구간에서 앞선 프레임을 처리했는지에 따라서도 같은 평가 프레임의 관절 좌표가 바뀌었습니다. 입력 직전의 픽셀은 일치했지만 MediaPipe 실행 버전과 내부 처리 경로에는 차이가 있어, 남은 좌표 차이의 원인을 한 가지로 좁히려면 추가 비교가 필요합니다.

## 다음에 확인할 점

개인 기록을 비교할 때는 관절 추출 모델과 실행 버전, 영상 시간 정보, 추적 시작 위치를 함께 기록하는 편이 좋습니다. 이번 실험의 범위는 브라우저와 PC에서의 재현성입니다. 실제 휴대폰에서는 같은 조건으로 다시 실행해 차이를 확인하고, 좌우 걸음 시간차는 양쪽 발의 관측이 충분한 구간에서 검증해야 합니다.

당시 독립 검산에서는 RGB 파일 675개의 지문과 실제 API 입력 2,956개의 픽셀·시각·순서·설정을 대조했습니다. 좌표에서 무릎 범위와 걸음 간격을 구하는 산식도 따로 확인했습니다.
