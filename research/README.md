# 보행 영상에서 걸음의 차이를 읽기까지

휴대폰으로 옆에서 찍은 영상 한 편으로 무엇을 알 수 있을까? 처음에는 걷는 모습을 보고 신체 기능검사 결과를 예측해 봤다. 그러나 균형을 잡거나 의자에서 일어나는 동작은 걷기만 찍은 영상에 담기지 않는다. 그래서 연구의 중심을 **걸을 때 관절이 어떻게 움직이는지, 그리고 같은 사람의 걸음이 이전과 얼마나 달라졌는지**로 옮겼다. ## 1. 정상적으로 걷는 사람에게도 모델이 낮은 점수를 줬다

보행 편차 지수(GDI)는 걸을 때의 관절 움직임이 정상 참조집단의 움직임과 얼마나 다른지를 나타낸다. 100점은 그 집단의 평균이다. 주로 뇌성마비 아동의 보행 자료로 학습한 모델을 다른 자료에 적용해 보니, 정상 집단의 평균 예측값이 79~83점에 머물렀다. 다만 이 사람들에게는 개별 실측 GDI가 없었다. 그래서 **정상 집단의 점수가 올라가는지와 실제 점수를 더 잘 맞히는지를 따로 확인했다.**

- **정상 보행의 예를 더 보여 주면 달라질까?** 정상 성인 64명의 영상 881편에 학습용 목표로 100점을 붙이고, 기존 환자 자료와 함께 다시 학습했다. 모델의 출력을 GDI 척도에 맞출 때는 환자에게서 실제로 측정한 점수만 사용했다. 그 결과 학습에 쓰지 않은 정상 집단들의 평균 예측값은 93~99점으로 올랐다. 같은 자료에서 비교한 뇌성마비 아동, 이상 보행을 흉내 낸 성인, 뇌졸중 집단의 상승 폭은 각각 더 작았다. 고령자 비교에는 3차원 측정 자료를 옆에서 본 좌표로 바꿔 사용했다.
- **100점이라는 가정이나 정상 영상의 비중을 바꾸면 어떨까?** 목표를 90점과 110점으로 바꿔 보고, 정상 영상에서 틀린 값을 학습에 얼마나 크게 반영할지도 바꿨다. CNN에서는 목표를 110점으로 올리거나 정상 영상의 비중을 네 배로 높였을 때 오히려 실제 점수가 높은 환자의 오차가 커졌다. [가정 점수와 학습 비중을 바꾼 실험](https://github.com/youngni05/gait-scoring/blob/codex/research-records-20261117/research/archive/studies/20261105-normal-label-sensitivity/README.md)
- **몇 사람의 영상만으로도 효과가 나타날까?** 정상 성인을 4명부터 64명까지 늘려 보니, 외부 정상 아동의 점수는 처음 4~8명을 추가했을 때 가장 많이 올랐다. 학습을 시작하는 난수를 세 가지로 바꿔도 상승 방향은 같았다. 한편 자료의 출처를 구별하도록 만든 대조 모델에서도 점수가 오르는 사례가 있었다. 따라서 상승 폭만으로 AI가 어떤 보행 특징을 배웠는지 단정하기는 어렵다.
- **점수 눈금만 바꿔도 같은 효과가 날까?** 기존 예측값에 수식을 적용해 정상 아동의 평균을 재학습 모델과 같은 98.8점에 맞췄다. 그러자 학습에 쓰지 않은 환자 222명의 평균 오차가 6.249점에서 13.714점으로 커졌다. 정상 영상을 추가해 학습했을 때의 오차는 6.375점이었다. 즉, 정상 집단에 낮은 점수를 주는 경향은 줄었지만 환자의 실측 점수를 맞히는 성능까지 좋아지지는 않았다.
- **별도로 측정한 관절 움직임과도 맞을까?** 3차원 관절각이 있는 자료에서는 그 각도로 GDI를 직접 계산해 비교했다. 건강 성인의 점수를 평균적으로 낮게 잡던 차이는 14.3점에서 5.4점으로 줄었다. 뇌졸중 환자 41명 중 마비된 쪽 다리에 더 낮은 점수를 준 비율도 65.9%에서 80.5%로 올랐다. 이 비교에는 건강 성인을 기준으로 계산한 GDI를 사용했으므로, 휴대폰 영상에서 개인의 점수를 얼마나 정확하게 맞힐지는 별도로 확인해야 한다. [자료별 결과와 비교 조건](https://github.com/youngni05/gait-scoring/blob/codex/research-records-20261117/research/paper-related/gdi-normal-calibration.md)

## 2. 집 안에서 찍으면 모델에 필요한 직선 보행 구간이 부족했다

복도를 왕복하는 영상은 길어도 돌아서는 순간을 빼면 한 방향으로 걷는 시간은 짧다. 세 사람의 촬영 영상에서 직선 구간 72개를 살펴보니, 기존 모델에 필요한 124프레임을 확보한 구간은 34개였다. 길이를 64프레임으로 줄이면 66개에서 점수를 계산할 수 있었다. 그래서 **점수를 낼 수 있는 구간이 늘어날 때, 그 점수의 오차는 어떻게 달라지는지** 실측 GDI가 있는 자료로 시험했다.

- 먼저 기존 모델을 그대로 쓰기 위해 짧은 구간의 중간 좌표를 채우거나, 양 끝 자세를 유지하거나, 관측한 움직임을 반복해 124프레임으로 맞췄다. 64프레임에서는 같은 구간을 반복한 방법이 세 방법 중 오차가 가장 작았다. 다만 반복해서 넣어도 새로 관찰한 걸음이 늘어나는 것은 아니다.
- 다음에는 모델이 짧은 입력 자체를 배우도록 했다. 길이가 다른 구간을 섞어 학습하는 방법과 64프레임에 맞춰 학습하는 방법을 비교했다. 개발자료 640명에서 64프레임용 모델은 같은 구성의 추가 학습 전 모델보다 평균 오차가 9.01점에서 약 7.4점으로 줄었다. 그런데 실제 점수가 낮은 사례에서는 오차가 더 커졌고, 원래 길이의 영상에서도 성능이 떨어졌다. [짧은 구간을 만드는 방법과 학습 결과](https://github.com/youngni05/gait-scoring/blob/codex/research-records-20261117/research/updates/2026-11-17/shortwalk.md)
- 마지막으로 낮은 점수를 놓치는 문제를 줄이려고 모델의 마지막 층만 다시 학습하거나, 실제 점수가 낮은 다리에서 발생한 오차를 세 배로 반영하거나, 같은 방문의 짧은 구간과 긴 구간을 함께 학습했다. 두 길이를 함께 쓰면 긴 입력의 오차는 일부 줄었지만, 낮은 점수를 평균 약 18점 높게 예측하는 경향이 남았다. 이 때문에 기존 모델을 교체하는 결정은 보류했다.

## 3. 다리가 보여도 관절 위치와 착지 시점을 잘못 짚었다

- **상체가 잘리면 다리도 놓칠까?** 같은 전신 영상 9편에서 위쪽 절반만 가려 다시 비교했다. MediaPipe로 GDI를 계산할 수 있는 구간이 나온 영상은 8편에서 0편으로 줄었다. 이어 한 사람의 영상 4편을 골반이 보이도록 잘라 다른 추출기인 YOLO Pose와 비교했다. YOLO는 직선 구간 8개 모두에서 걸음 빈도를 계산했지만 착지 12개를 놓쳤고 24개를 더 잡았다. 골반까지 잘랐을 때는 YOLO도 빈도를 계산하지 못했다.
- **옆에서 찍어 한쪽 무릎이 가려지면 어떻게 볼까?** 왕복 영상에서 갈 때와 돌아올 때 각각 잘 보이는 다리를 골랐다. 두 사람의 영상 24편에 같은 추적 품질 조건을 적용하자, MediaPipe Full로 양쪽 무릎 움직임을 관찰할 수 있는 영상이 1편에서 13편으로 늘었다. 다만 두 다리를 서로 다른 걸음에서 봤기 때문에 두 각도의 차이를 한 걸음의 좌우 비대칭 점수로 쓰기에는 근거가 부족했다.
- **발이 닿는 순간을 너무 일찍 잡거나 한 걸음을 두 번 세면 어떻게 고칠까?** 사람이 영상에 표시한 착지와 모델의 표시를 겹쳐 보고, 뒤꿈치가 내려갈 때 시점을 늦추는 방법을 시험했다. 또 같은 발을 연달아 잡았을 때는 앞뒤 걸음 간격과 좌표의 갑작스러운 변화를 보고 의심스러운 표시를 보류했다. 한 사람의 촬영에서는 잘못 추가한 표시가 18개에서 15개로 줄었다. 반면 다른 사람들을 촬영한 MoVi 자료에서는 보정 후 착지 시점 오차가 커져서 공통 규칙으로 채택하지 않았다.

## 4. 점수 차이가 실제로 무엇을 뜻하는지 확인해야 했다

- **천천히 걸어서 점수가 낮아진 걸까?** 각자의 진료 방문에서 측정한 평균 보행 속도가 비슷한 사람끼리 짝을 지었다. 속도 차이가 초당 0.05m 이내이고 실측 GDI가 10점 이상 다른 146쌍에서, 실제 점수가 더 낮은 사람을 속도만으로 맞힌 비율은 50.0%, 영상 모델로 맞힌 비율은 85.6%였다. 이 조건에서는 비슷한 속도로 걷는 두 사람의 보행 차이를 영상에서 일부 구별할 수 있었다.
- **그 차이로 보행에 도움이 필요한 사람도 찾을 수 있을까?** 속도가 비슷하고 대근육 기능 등급이 다른 53쌍을 살펴보니, 예측 GDI가 더 낮은 사람이 실제로 기능 제한도 더 큰 경우는 71.7%였다. 이는 기능 등급이 기록된 일부 사람을 다시 분석한 결과다. 별도의 보행 도움 등급 자료 21명에서는 속도에 GDI를 더해도 도움이 더 필요한 등급의 사람을 놓치는 일이 줄지 않았다. 점수만 보고 촬영 중 부축이 필요한지 판단할 근거는 아직 부족하다.
- **같은 사람을 다시 찍었을 때 생기는 차이는 얼마나 될까?** 세 사람이 평소처럼 걸은 영상을 각각 세 편씩 찍었다. 한 편을 나머지 한 편과 비교할 때보다 나머지 두 편의 평균과 비교할 때 차이가 작았다. 한편 똑같은 영상 프레임을 넣어도 브라우저와 PC에서 계산한 왼쪽 무릎의 움직임 범위는 최대 약 7도 달랐다. 그래서 이전 기록과 비교하려면 촬영 조건뿐 아니라 영상을 처리한 환경과 관절 추적을 시작한 지점도 맞춰야 한다. [평소 기록을 몇 편 쓸지 비교한 실험](https://github.com/youngni05/gait-scoring/blob/codex/research-records-20261117/research/updates/2026-11-19/personal-baseline.md) · [같은 영상을 브라우저와 PC에서 처리한 실험](https://github.com/youngni05/gait-scoring/blob/codex/research-records-20261117/research/updates/2026-11-19/identical-rgb.md)
- **방문 사이의 작은 변화를 걸러 내면 더 믿을 만할까?** 반복 방문자 229명의 연속된 방문 369쌍에서 같은 다리의 예측 변화와 실측 변화를 비교했다. 실측 변화가 10점 이상일 때는 모델이 매번 ‘변화 없음’이라고 답할 때보다 오차가 작았지만, 5점 미만에서는 오히려 오차가 컸다. 작은 예측 차이를 표시하지 않는 방법도 시험했다. 한 조건에서는 표시한 변화의 방향이 약 81% 맞았지만, 실제로 10점 이상 달라진 경우도 약 58%가 가려졌다. 가정에서 찍은 영상에 적용할 변화 기준은 아직 정하지 않았다.

## 어떤 모델로 실험을 시작했나?

Stanford 자료에서 695명의 기록 1,064개를 사용했다. 각 기록의 처음 124프레임에서 관절 좌표를 읽고 왼쪽과 오른쪽 다리의 GDI를 따로 예측했다. 같은 사람의 기록을 한데 묶어 전체를 다섯 그룹으로 나눈 뒤, 매번 556명으로 학습하고 나머지 139명으로 평가했다. 아래 오차는 예측값이 실측값에서 얼마나 벗어났는지를 사람별로 먼저 평균하고, 다시 전체 사람에 대해 평균한 값이다.

| 같은 자료에서 비교한 방법 | 사람별 평균 절대오차 |
|---|---:|
| CNN이 관절 움직임을 처음부터 학습했다. [CNN 실험](2026-10-30-cnn-baseline695/README.md) | 8.683496점 |
| 사전 학습된 MotionBERT에서 움직임 특징을 뽑고, 그 특징으로 점수를 예측했다. | 8.526630점 |
| MotionBERT의 마지막 단계도 보행 자료에 맞춰 다시 학습했다. [MotionBERT 실험](2026-10-30-motionbert695/README.md) | 8.354702점 |

초기 비교에서는 별도로 남겨 둔 최종 평가 후보 223명과 기존 검증용 37명·평가용 38명의 자료를 사용하지 않았다. 이후에는 학습을 마친 여러 모델의 예측을 평균하거나 서로 다른 모델을 결합해 봤다. 별도 환자 222명에서는 CNN 24개의 평균과 모델 54개를 결합한 결과의 오차 차이가 약 0.02점이어서, 복잡한 결합이 더 낫다고 판단하기 어려웠다. [후속 모델의 구성과 평가](selected/README.md)

### 초기 CNN과 MotionBERT로 점수를 다시 계산하는 방법

1. 각 실험 폴더의 `requirements.txt`를 참고해 NumPy와 PyTorch를 설치한다.
2. 초기 모델 배포 페이지에서 원하는 모델의 압축 파일을 받아 푼다. 각 파일에는 서로 다른 556명으로 학습한 모델 다섯 개가 들어 있다. MotionBERT는 마지막 단계를 다시 학습한 모델 다섯 개를 배포했다. [초기 모델 다운로드](https://github.com/youngni05/gait-scoring/releases/tag/research-initial-models-20261101)
3. 각 실험 문서의 명령에 따라 `predict.py`에 전처리를 마친 관절 좌표 배열을 넣으면 양쪽 다리의 GDI가 나온다. 입력의 세 번째 값은 해당 관절이 얼마나 확실하게 관측됐는지를 나타낸다. 휴대폰 원본 영상은 먼저 관절을 추출하고 좌표 형식을 맞춰야 한다.

`run.py`와 설정 파일에는 당시의 학습 절차가 남아 있다. 전체 학습을 다시 실행하려면 공개 범위에서 제외한 개인별 좌표와 정답, 데이터 분할 명단, 캐시 등도 필요하다. 원자료에는 제공 기관의 이용 조건이 적용된다. [공개 파일과 원본의 대응 관계](source-files.json) · [Stanford 원자료 안내](https://github.com/stanfordnmbl/mobile-gaitlab)

### 배포한 모델로 다시 계산해도 원래 점수가 나오는가?

초기 CNN과 MotionBERT를 배포할 때는 학습을 이어가는 데 쓰는 정보를 빼고, 예측에 필요한 값만 파일에 담았다. 먼저 원본 파일의 내용이 맞는지 SHA-256으로 대조하고, 옮긴 모델의 가중치가 원본과 같은지 확인했다. 그런 다음 **배포할 모델로 기존 보행 기록 1,064개의 GDI를 다시 계산해 원래 저장한 예측값과 비교했다.** 두 모델 모두 차이가 0.0001점 이내였다.

원래 학습에는 RTX A6000과 Python 3.8.10, PyTorch 2.4.0+cu121, NumPy 1.24.4를 사용했다. 배포 파일은 필요한 라이브러리가 이미 설치된 CPU 환경에서 확인했다. 새 컴퓨터에 처음부터 설치하는 과정은 당시 확인 범위 밖이었다. [모델별 재계산 결과와 실행 환경](publication-verification.json)
