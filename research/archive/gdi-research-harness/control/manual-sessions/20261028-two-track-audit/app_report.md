# 앱 점검: 화면과 측정 기술은 있으나 실제 연결과 저장 형식을 바꿔야 한다

2026-10-28. 기존 앱 원본을 수정하지 않고 두 작업본의 현재 코드와 기존 검사를 확인했다. 이 보고는 코드 조사와 합성·모의 검사 결과이며 실제 서버·휴대폰 시험은 아니다.

## 재사용할 수 있는 부분

| 부분 | 확인한 구현 | 판단 |
|---|---|---|
| 로그인·대상자 | 2026-ITEC0401에 인증 상태 관리, 담당자별 목록 조회, 대상자 등록 요청 코드 | 재사용 후보. 실서버 연결은 이번에 재검증하지 않음 |
| 기록 조회·이전 기록 비교 화면 | 날짜 정렬, 최근/직전 선택, 개발 기록 분리, 오류·대기 표시 | 화면과 처리 구조 재사용. SPPB 점수와 하락 판단은 교체 필요 |
| 저장 재시도·계정 변경 처리 | 같은 요청의 재확인, 중복 제출 방지, 계정 변경 시 상태 정리, 세션 초안 복원 | 구조 재사용. 저장 데이터 형식은 SPPB 전용 |
| 실제 카메라·관절 추정 | ai-measurement-review에 getUserMedia, MediaPipe, 대상 선택·추적, 프레임 시각·미검출 처리 | 추출 기능 후보. 관리 앱에는 아직 연결되지 않음 |
| 저장 영상의 구간 분석 | 실험 앱에 파일 선택·프레임 시각 읽기·관절 추정·구간 재생·JSON 내보내기 | 짧은 영상 실험 도구로 재사용 가능 |

핵심 근거: 관리 앱의 `MeasurePage.tsx`는 useSimulatedRun을 호출하고 카메라 미연결·실제 영상 아님을 표시한다. `CameraStage.tsx`는 자리표시 그림이다. 실제 추정은 실험 앱의 `camera.ts` → `frameLoop.ts` / `VideoLabPanel.tsx` → `landmarker.ts`에 있다. 두 앱이 하나로 통합되어 있다고 말할 수 없다.

## 그대로 가져오면 안 되는 부분

1. `assessmentSave.ts:17`의 저장 요청은 균형 세 자세·보행 두 회·의자 다섯 회와 담당자 확인을 요구하고 simulation-v1로 저장한다. 보행만 찍는 새 앱에는 맞지 않는다. `saveAssessment.ts`의 응답 검사와 `assessments.ts`의 읽기 열도 같은 구조다.
2. `derive.ts:67`은 SPPB 총점 차이로 상태를 정한다. 날짜·기록 선택과 차이 표시 틀은 가져올 수 있지만 점수 경계와 좋음/나쁨 해석은 가져오지 않는다.
3. 실험 앱의 recording.ts가 저장하는 것은 영상 파일이 아니라 관절 좌표·시각·판정의 JSON이다. 조사한 두 web/src에서 MediaRecorder·영상 업로드 구현을 찾지 못했다. 카메라 미리보기나 기존 파일 분석이 곧 원본 영상 녹화·보관 기능을 뜻하지 않는다.
4. 실험 앱은 MediaPipe 33개 좌표의 x/y/z/visibility를 다루고, 현재 GDI 입력은 BODY25 x/y/confidence에서 17개 관절로 변환한다. 배열을 그대로 연결할 수 없다. 형식 변환 후에도 추정기 차이에 따른 성능은 따로 확인해야 한다.

## 실제로 실행한 검사

현재 두 작업본에는 미커밋·미추적 변경이 있다. 관리 앱은 codex/fe-ui-draft, 측정 앱은 codex/ai-measurement-review다. git_state.json에 HEAD와 변경 목록을 보존했다. 단순히 HEAD만 복사하면 현재 로컬 기능 일부가 빠질 수 있으므로 원본을 정리하거나 덮어쓰지 않았다.

관련 소스 150개를 하네스 검사 폴더에 복사하고 원본/사본 해시를 기록했다. 관리 앱의 인증·대상자 조회·저장·저장 흐름·초안·이력 계산 6개 테스트 파일에서 57개가 통과했다. 측정 쪽 4개 파일은 합성 좌표의 바닥선 통과·시간 보간·영상 시각·짧은 미완료 구간·프레임 선택을 검사했다. 최초 22개가 통과했지만 mediabunny 경로 때문에 한 파일을 수집하지 못했다. 사본의 의존성 경로만 기존 설치로 연결해 누락된 1개도 통과했다. 합계 80개 검사다. 처음 실패 기록은 보존했고 소스·검사 기준은 바꾸지 않았다.

브라우저 화면, 실제 MediaPipe 추론, 스마트폰 카메라, 영상 파일 저장, 실제 서버 통신, 측정 정확도와 전체 빌드는 이번 확인 범위가 아니다.

## 다음 앱 작업

권장 기준 작업본은 대상자·기록 화면이 있는 관리 앱이며 실험 앱에서 카메라·관절 추정 모듈을 가져오는 방식이다. 현재 로컬 변경을 포함할 범위를 확인해 하네스 안에 별도 개발 작업본을 만든다. 다음 구체 작업은 실제 카메라와 관절 표시를 연결할 지점을 정하고, SPPB와 분리된 보행 기록의 입력·결과 항목 및 원본 영상 보관 정책을 사용자에게 제시하는 것이다. 이후 합의된 촬영 기능부터 구현한다. 점수 모델 완성을 기다릴 이유는 없다.
