## 최신 정정 · 팀원 결과 대기 없이 우리가 1D-CNN 기준 실험 진행

2026-10-30 추가 사용자 설명: 팀원의1D-CNN·RF 비교는 아직 수행하지 못한 상태로 보인다. 기존 코드나 결과가 이미 있다고 전제하지 않는다. 원 연구를 근거로1D-CNN 쪽 가능성을 먼저 확인하고 싶으며, **우리가 직접 CNN 기준 실험 → 학습 설정 조정 → 시간 범위 변경 → MotionBERT 결합**을 진행한다. 우리 자료에서 CNN의 우위는 아직 미확인이다. RF 특징 결합은 후순위로 두며 CNN 착수의 선행 조건이 아니다.

- GPU 준비물 확인: `studies/20261030-gpu-motionbert-study/cnn-followup695/`에 코드·입력·실행ZIP과 로컬 검증 기록이 있다. 검증 기록은 실제자료 학습0회·실제GPU실행 없음으로 명시한다. 묶음 존재와 로컬 검사를 실제 성능 결과로 해석하지 않는다.
- 이번 기준은17관절의x/y/신뢰도 시계열 →1D-CNN →좌우GDI다. 원 공개 CNN 구조를 현재 입력에 맞춘 새 학습이며, 원 논문의 입력·전처리 전체 재현이나 사전학습 가중치 파인튜닝이 아니다. 같은695명·앞124프레임·기존 사람 분할로 Ridge/PLS/부분학습과 비교한다.
- GPU 담당: 준비 묶음의 최신 상태 확인 → 작은 GPU 실행으로 시간·메모리 확인 → 기준 CNN 학습·내부 검증으로epoch 선택 → 결과 회수·검산 순서다. 기존 GPU 실험·설정은 보존한다. 이 채팅은 GPU 담당의 코드나 실행 상태를 변경하지 않았다.
- 이 CPU 채팅: RF부터 새로 시작하는 제안은 미루고, CNN 결과가 들어오면 기존 PLS·부분학습과 사람별 오차·양끝 편향·점수 분포를 비교한다. GPU 구현과 중복 학습하지 않는다. 입력 사용량과 전처리 차이도 비교 해석에 포함한다.
- 최신 기존 결과:695명 부분학습 회수·검산 완료, last_stage MAE8.3547점. PLS와의50:50 결합은8.0209점으로 PLS 단독7.9749점을 개선하지 못했다. 결합 기록은 [CPU 상태](../../../studies/20261030-cpu-head-study/STATUS.md)를 확인한다.

## GPU 후속 순서 · 1D-CNN 개선에서 MotionBERT 결합까지

갱신: 2026-10-30 15:43 KST. 기존 GPU 실험을 유지하면서 CNN 학습 설정 조정부터 MotionBERT 결합까지 진행하는 방향과 인계 순서를 공용 기록에 남기기로 했다. 아래는 내가 정한 후속 방향이며, 새 CNN 코드·실행 묶음·학습 결과가 이미 준비됐다는 뜻은 아니다. GPU 담당의 열람과 팀원의 역할 조율은 아직 확인하지 않았다.

**기존 MotionBERT 부분학습을 비교 축으로 남기고, GDI를 직접 학습하는 작은 CNN을 개선한 뒤 MotionBERT의 시간별 특징이 추가로 도움이 되는지 확인하고 싶다.** 팀원의 CNN·RF 기준 비교를 우선 활용하고, 우리 GPU 작업은 CNN 학습·구조 개선과 결합 효과를 담당한다. RF 특징 결합과 예측 결합은 CPU 병행 후보이며 GPU CNN 준비의 선행 조건으로 두지 않는다.

### 유지할 작업과 새 작업의 경계

- 기존175명 GPU 결과와695명 확대 `expansion695/`의 입력·분할·설정·출력은 보존한다. 실행 중인 작업은 설정을 바꾸거나 중단하지 않고 정해진 조건으로 마무리한다. 현재 로컬 담당 기록은175명 완료·검산,695명 묶음 준비·실행 대기다. 실제 서버의 이후 진행은 GPU 담당이 확인한다.
- 새 CNN 작업은 GPU 담당 폴더 아래 `cnn-followup695/`에 분리해 준비한다. 이 경로는 앞으로 사용할 위치이며 이번 문서 갱신에서 생성한 실행 묶음이 아니다. 공용 현황은 이 문서, 실제 준비·실행 상태는 [GPU 담당 STATUS](../../../studies/20261030-gpu-motionbert-study/STATUS.md)에 기록한다.
- 작은 CNN은 CPU에서도 학습할 수 있지만 반복 비교에는 GPU를 활용한다. 기존 작업이 자원을 사용하면 입력 점검·코드·설정 준비부터 진행하고, 새 학습은 사용 가능한 자원과 예산을 확인해 순서대로 실행한다.

### GPU 담당이 이어서 준비할 순서

| 순서 | 입력 → 처리 → 출력과 확인 목적 | 준비·완료 근거 |
|---|---|---|
| 0. 기준 CNN과 입력 확인 | 팀원의 코드·설정·예측을 확인하고 같은695명 조건의 기준1D-CNN을 확보한다. 원 연구 구조만 가져와 새로 학습하는 것과 기존 가중치의 파인튜닝을 구분한다 | 관절·좌우·정규화·결측 처리·입력 구간·정답·사람 분할 대응표. 코드가 없으면 누락을 기록하고 원 공개 구현 기반 준비를 진행하되 팀원 재현 완료로 부르지 않는다 |
| 1. 학습 설정 조정 | 기준 CNN의 입력과 구조를 유지하고 학습률·종료 시점·드롭아웃·가중치 규제를 조정한다. 학습 부족과 과적합을 먼저 구분한다 | 기준 설정과 작은 후보표, 내부 검증 학습 곡선, 선택 근거, fold별 미학습 예측. 기존 MotionBERT의200갱신을 CNN 예산으로 그대로 적용하지 않는다 |
| 2. 관찰하는 시간 범위 변경 | 같은 입력에서 짧고 긴 움직임을 함께 보는1D-CNN을 비교한다. 커널 길이·시간 범위가 다른 구조의 효과를 확인한다 | 1단계 CNN과 같은 분할·입력·선택 절차로 비교. 한 번에 입력 특징까지 바꾸지 않아 개선 원인을 구분한다 |
| 3. 고정 MotionBERT + CNN | 관절 시계열 → 고정 MotionBERT의 프레임별 특징 →1D-CNN →좌우GDI. CNN만 학습해 사전학습 특징의 추가 효과를 확인한다 | 시간 축이 유지되는 특징 추출 코드·캐시와 사람/영상ID 대응. 원 관절을 받는 CNN 및 기존 MotionBERT+Ridge/PLS와 비교 |
| 4. 결합 모델 부분학습 | 3단계 구조에서 MotionBERT 마지막 블록과 CNN을 함께 학습한다. 고정 특징보다 GDI에 맞춘 특징이 유리한지 확인한다 | 우선3단계의 내부 검증에서 결합 가능성을 확인한다. 학습 대상 층·서로 다른 학습률·선택 근거·체크포인트·미학습 예측을 저장한다. 개선이 없으면 고정 모델도 결과로 남긴다 |

0단계의 기준 확인부터 순차적으로 준비한다. 각 단계의 성능 개선은 미확인이다. 2D-CNN은 이번 우선 실행 묶음에 넣지 않고 후순위 후보로 남긴다. 입력 좌표가 2D라는 이유만으로 2D-CNN을 선택하지 않는다.

### 같은 조건에서 비교하기 위한 입력·선택 규칙

- 기준은695명·1,064기록, 기존5분할, 앞124프레임, 좌우GDI다. 각 바깥 분할의 학습556명/평가139명을 유지한다. 학습 설정과 종료 시점은556명 안에서 사람 단위로 고른다. 기존 CPU와 맞추려면 나머지4묶음을 내부 교차검증에 사용한다(내부 학습417명/검증139명). 정규화와 특징 학습도 내부 학습 사람으로 제한한다.
- 설정 선택 뒤 바깥 학습556명으로 재학습한다. 최종 학습 길이는 내부 검증에서 정한 규칙으로 고정하며, 바깥 평가139명의 오차로 종료 시점이나 후보를 고르지 않는다. 같은 사람의 영상·구간·증강본은 항상 같은 쪽에 둔다. 기존37/38명과 최종예약223명의 역할은 유지한다.
- 준비된 GPU 입력은 `studies/20261030-gpu-motionbert-study/expansion695/train_only.npz`, CPU 대조자료는 `studies/20261030-cpu-head-study/followup/expanded695-pls-study/development695.npz`다(경로는harness 기준). GPU 준비 코드의 입력 모양은 `1064×1×124×17×3`, 요약 특징은 `1064×1×512`다. 3개 채널의 의미는 생성 코드에서 확인하며3D좌표라고 단정하지 않는다.
- 원 연구 CNN의 관절·각도 등 입력은 현재17관절 MotionBERT 입력과 다를 수 있다. 사용한 특징을 기록하고, 원 연구 재현과 현재 입력을 맞춘 비교를 구분한다. 더 긴 영상의 여러 구간을 사용하는 실험은 이후 별도 조건으로 둔다.
- 현재512개 요약 특징을 시간512칸으로 해석하지 않는다. 결합용 특징은 시간 평균 전 단계에서 추출하고, 관절을 합치는 방식·시간 길이·특징 수를 기록한다. 출력 형태와 캐시 용량은 실제 코드로 확인한다.
- 공개 CNN 가중치를 사용할 때는 학습 사람과 현재 내부 검증·바깥 평가 사람의 중복 여부를 확인한다. 확인할 수 없으면 구조만 가져와 해당 학습 사람으로 새로 학습한다. GDI로 부분학습한 MotionBERT를 내부 선택에 쓰는 경우도 해당 내부 학습 사람으로 학습된 가중치를 사용한다. 바깥 학습556명 전체로 학습한 가중치를 내부 검증에 그대로 재사용하지 않는다.

### 실행 묶음과 CPU로 넘길 결과

GPU 담당의 첫 준비 결과는 **기준 코드 확보 상태·입력 대응표·분할 검사·1단계 후보 설정표·작은 실행 명령**으로 둔다. 학습률 후보 숫자, 최대epoch, 조기 종료 조건, 배치, 반복seed, 총 실행시간 상한은 아직 미정이며 실행 전 설정 파일에 명시한다. 시간과 메모리는 기존 MotionBERT 측정값으로 대신하지 않고, 작은 실행으로 측정해 전체 예산을 정한다.

실행 묶음에는 입력/분할 지문, 실제 코드와 환경, 후보·선택 규칙, 중단 재개 방법, 학습 곡선, 체크포인트, 실행 로그를 포함한다. 입력·좌우 대응, 분할 간 사람 중복 없음, 유한한 손실·실제 가중치 갱신, 저장 후 예측 재현을 먼저 확인한다. 준비 검사와 실제 GPU 학습 횟수는 별도로 기록한다.

CPU 인계 예측에는 방법·설정·seed·fold·학습/평가 구분·사람ID·영상ID·좌우·실제GDI·예측GDI를 포함한다. 학습 사람과 평가 사람의 오차·분포를 따로 비교하되, 모델 순위는 같은 평가 사람의 예측으로 계산한다. 기존 집계 코드를 재사용해 다음을 확인한다.

- 사람별 MAE와 분할별 차이, 기존175명/추가520명 하위집단 결과.
- 낮은 점수의 과대예측과 높은 점수의 과소예측, 점수대별 인원·편향·오차.
- 실제/예측 점수의 범위·표준편차와 기존10점 구간 일치율. 예측이 넓게 퍼진 것만으로 개선이라고 판단하지 않는다.
- 같은 사람의 오차 차이와 불확실성. 여러 후보를 살펴본 개발 결과를 독립 최종 성능으로 표현하지 않는다.

**인계 상태:** 공용 기록 반영 완료. 새 CNN 구현·GPU 실행은 이번 갱신에서 수행하지 않았다. GPU 담당은 이 절을 읽은 뒤 자기 `STATUS.md`에 열람 시각, 현재 기존 작업 상태, 0~1단계 준비 상황과 다음 산출물 경로를 남긴다. 공용 파일의 존재만으로 열람·착수 완료를 표시하지 않는다.

## 현재 방향 · 기존 실험 보존과 기준 모델 중심의 비교

갱신: 2026-10-30 15:32 KST. 사용자가 기존 실험 기록을 남기고 GPU 실험과 보조를 맞춘 방향 전환을 공용 기록에 반영하도록 요청했다. CPU 담당 채팅에서 이번 공용 문서 갱신을 수행했다. 아래 판단은 개인 연구 방향이며 팀 전체의 합의·담당자의 실제 열람·새 실험 실행과 구분한다.

**같은 조건에서 1D-CNN·랜덤 포레스트가 얼마나 잘되는지 먼저 확인하고, MotionBERT가 그 성능을 더 높이는지 연구하고 싶다.** 지금까지의 Ridge·PCA·PLS·부분학습 실험은 그 판단에 사용할 비교 근거로 남긴다. 단일 카메라로 보행 정보를 정확하게 측정하고 해석하려는 목적은 유지하며, GDI 오차 감소를 관절 측정 정확도나 고령자 실사용 검증으로 바꿔 말하지 않는다.

### 완료한 실험과 현재 위치

| 범위 | 저장 기록으로 확인한 결과 | 현재 해석 |
|---|---|---|

- 기존 37/38명과 최종 평가 예약 223명의 용도를 자동으로 바꾸지 않는다. 동일인의 여러 영상·시간 구간·증강본은 항상 같은 분할에 둔다. 표준화·특징 학습·Ridge 학습은 해당 학습분만 사용한다.
- “약 1,000명을 학습에 쓰면 어떤가”는 검토 질문이다. 후보 1,363명 전원의 입력 사용 가능성이 확인된 것은 아니며, 1,000명 학습이나 새 검증 인원은 아직 확정하지 않았다.

근거: [초기 선별 집계](../../../../outputs/gdi-exclusion-audit-20261023/summary.json), [추가 자료 연결·고정 모델 결과](../../../studies/20261027-gdi-linkage/report.md), [GPU 현재 상태](../../../studies/20261030-gpu-motionbert-study/STATUS.md). 기록을 공유 폴더에 반영한 것이며 다른 채팅이 이미 읽었다는 뜻은 아니다.

## GPU·CPU 후속 역할

- GPU: 현재 환경 연결 → CUDA 기준 재현·가상 자원 측정 → 실제 학습 설정·예산 확정 → 마지막 특징변환과 마지막 Transformer단계의 제한된 부분학습 비교. GPU가 준비되었다는 전달과 실제 접속·할당·학습 완료는 구분한다.
- CPU: A와 B의 기존 예측을 동일한10점구간·사람집계로 비교하고, GPU예측을 받을 평가 코드와 저장된모델의 점수출력 예시를 준비한다. 새 모델·학습률 탐색은 시작하지 않는다.
- 이후 연결: GPU에서 fold별 학습모델의 특징을 준비하면 CPU에서 Ridge 재학습을 검토한다. 해당fold 평가사람을 학습한 모델의 특징이나 다른fold의 특징을 섞지 않는다. 아직 생성되지 않은 GPU결과를 완료로 표시하지 않는다.
- 조율: 상태 조회와 후속 지시는 계속 이 채팅에서 맡는다. 이 기록 갱신은 상시 예약 감시 설정을 의미하지 않는다.

## 확인 및 통합 절차

1. 분기의 진행 상태와 완료·중단 여부를 조회한다.
2. A의 사람 수·좌우·집계 방식·실제값과 평가 예측 대응을 확인한다. 폭 10의 구간은 탐색용 표현이며 임상 등급이 아니다.
3. B의 기준 재현과 CPU 측정, 평가 결과를 보기 전에 작성한 학습 설정을 검토한다. 기존 초안의 미정값을 임의로 채운 대규모 탐색은 하지 않는다.
4. 완료 후 실행 종료·모든 묶음의 예측·누락·저장 결과의 일관성을 확인한다.
5. 두 결과의 자료·예측 단위가 같을 때만 함께 해석한다. 개발자료 탐색 결과를 독립 최종 성능으로 표현하지 않는다.

## 이번에 확인한 결과

**기존 GDI 예측은 평균값 예측보다 낫지만, 낮고 높은 점수의 구분이 부족하다. 이번 CPU 출력부 추가 학습으로는 이를 뚜렷하게 개선하지 못했다.** GPU에서 특징 추출기를 조정하는 다음 실험의 비교 기준으로 남긴다.

공통 조건은 개발자료 175명·203기록, 사람별 5묶음에서 학습에서 제외된 사람의 앞·뒤124프레임 평가다. 오차·구간 비율은 사람 안에서 좌우·기록을 먼저 평균했다. 초기 별도38명/243프레임 평가의 8.87점과 직접 비교하지 않는다.

| 항목 | 기존 MotionBERT 고정 + Ridge | 고정 특징 + 선형 출력부 추가 학습 |
|---|---:|---:|
| 앞 구간 MAE | 8.276점 | 8.282점 |
| 뒤 구간 MAE | 9.034점 | 9.030점 |
| 앞뒤 예측 차이 | 3.960점 | 3.923점 |

실제 GDI 범위는 39.12~106.64점, 기존 앞 구간 예측 범위는 51.21~89.74점이었다. 단순 평균 예측의 앞 MAE는 9.538점, 정확 구간 일치율은 31.86%다. 기존 모델에 예측 정보가 있다는 근거는 있으나 10점 구간을 정확하게 구분할 수 있는 수준이라고 단정하기 어렵다. 구간은 폭10의 고정 표시 방식이며 임상 등급이나 허용오차가 아니다.

## CPU 실험 조건과 해석

- 조율에서 준비 검사와 설정안을 읽은 뒤 사용자에게 위임받은 실험 범위 안에서 실행 지시를 보냈다. 별도의 사용자 발언을 만들어 승인 기록으로 남기지 않았다.
- 기존 Ridge 초기값에서 선형 출력부 1,026개 매개변수만 학습했다. seed 20261028, 5묶음, 묶음당200업데이트, 배치32, 학습률0.0001, weight decay0, AdamW, CPU스레드2를 사전에 고정했다.
- 총1,000업데이트를 수행했으며 5묶음의 학습·체크포인트·예측 구간 합계는 약0.98초였다. 코드 준비·환경 확인·입력 검사·보고 시간은 포함하지 않는다. GPU 학습 시간의 추정값도 아니다.
- Python3.13과 기존 cp312 PyTorch의 호환 오류를 확인했고, 기존 Python3.12 런타임으로 맞춰 검사했다. 패키지 환경과 원본 묶음은 변경하지 않았다.
- 전체 학습자료 MSE도 5묶음 중4묶음에서 아주 조금 증가했다. 업데이트는 실제로 일어났지만, 이번 짧은 고정 조건을 출력부의 최적 성능이라고 볼 수 없다. 출력부 학습 일반이 무효이거나 MotionBERT가 병목임을 입증한 결과가 아니다.
- 앞뒤 차이는 소폭 줄었지만 GDI 정확도와 구간 구분은 거의 그대로다. 현재는 기존 Ridge를 교체할 근거가 부족하다고 판단한다. 학습률·반복 수를 평가 결과에 맞춰 재탐색하지 않았다.
