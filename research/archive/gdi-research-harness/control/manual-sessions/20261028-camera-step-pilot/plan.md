# 직접 요청 실행: 카메라 연결 준비와 공개 영상 걸음 추출

사용자의 2026-10-28 직접 요청으로 실행한다. 예약·감독 프로그램은 변경하지 않는다. 원본 앱과 기존 연구 증거를 보존한다.

## 앱
현재 관리 앱의 소스·설정과 로컬 변경을 하네스 app-development 아래 별도 사본으로 보존한다. 로그인 환경 파일, 서버 키, node_modules, git, 빌드 산출물은 복사하지 않는다. 카메라·관절 추정의 작은 모듈을 측정 앱에서 가져오고 관리 앱 타입 검사로 호환성을 확인한다. 화면·서버 저장·측정 판단 기준은 이번 연결 준비에 포함하지 않는다.

## 연구
공개 영상과 같은 영상의 걸음 시점 정답을 확보해 걸음 수·인접 걸음 간 시간의 오차를 확인한다. 소규모 탐색이며 허용 오차·임상 성공 기준은 정하지 않는다. 제공자 주석을 우선하며, 확보 실패 시 원본 영상 관측 가능성과 추출 준비까지 실제 진행하고 정답 없는 추정값을 정확도로 표현하지 않는다. 필요 시 AI의 영상 판독은 임시 참고로만 기록하며 전문가 정답으로 표현하지 않는다. 설정·자료·시각 단위·제외 항목과 실패를 보존한다. 기존 GDI 학습·평가 자료는 사용하지 않는다.

## 연구 단계 2: 확보 영상에 고정된 추출 절차 적용
TNT15 동일 걷기 한 회의 두 시점(각10.22초,50fps)을 CRC 검증 후 확보했다. 카메라03은 전신이 보이고06은 시작·종료 구간 발이 화면 밖이다. 이 영상 자체가 좁은 시야 문제를 시험한다. MediaPipe full 공식 모델,VIDEO,CPU,3poses,confidence0.5로 전 프레임을 추론한다. 앱과 모델 파일 계열·기준은 같지만 Python 라이브러리와 웹 실행 환경은 다르다. 모델 미세조정 없음.
우선 단순 비교 기준으로 두 발목의 화면상 거리를 몸통 길이로 나누고, 좌표 유효·visibility>=0.5인 연속 구간에서 5프레임 이동평균,최소0.30초 간격,prominence0.10의 국소 최대점을 찾는다. 이는 발 간격이 벌어진 시점 후보이며 발 접촉 정답과 같다고 가정하지 않는다. 두 시점에서 같은 시간창의 검출 수·간격을 비교한다. 설정은 결과를 보기 전 고정하고 이 영상에 맞춰 조정하지 않는다. 비교 창[1.5,3.5),[3.5,5.5),[1.5,5.5)초는 정지 구간을 피해 짧은 길이를 비교하는 탐색 조건이지 앱 최소 길이가 아니다. 자동 추정 결과와 무관하게 원본 화면으로 접촉 참고 구간을 확인하되 AI주석은 임시이며 임상 정답으로 쓰지 않는다.

## 연구 단계 3: 실제 짧은 입력과 사후 결과 자르기 구분
첫 단계는 전체 영상을 추론한 뒤 시간창으로 결과를 나눴다. 이는 짧은 입력 자체의 실험이 아니다. 각카메라의[1.5,3.5),[3.5,5.5),[1.5,5.5) 구간을 원본 프레임 그대로 별도의 새 추정기에 넣는다(2초/2초/4초). 매번 모델 추적 상태를 초기화하고 같은 고정 검출 설정을 사용한다. 임계값 튜닝 없이 모델 초기화와 구간 경계의 영향을 비교한다. 원본을 재인코딩·시간 늘림·보간하지 않는다. 원본 순차 디코딩 후 지정 프레임만 사용해 경계의 실제 입력을 보장한다.

## 연구 단계 4: 차이가 난 위치 확인
카메라03 첫2초 입력은2개,4초 입력 안 같은2초 구간은3개였다. 짧게 잘라서 모델 추적 상태가 달라진 것인지, 끝부분의 최대점을 확인할 이후 프레임이 부족한 것인지 구분한다. 전체 영상의 이미 추정된 좌표만 같은2초/4초로 자른 뒤 동일 검출기를 다시 적용한다. 이 결과와 새 추정기로 짧은 입력을 처리한 결과가 같으면 이번 건의 검출 차이는 주로 후처리 경계에서 설명된다. 새 임계값·학습은 사용하지 않는다.
