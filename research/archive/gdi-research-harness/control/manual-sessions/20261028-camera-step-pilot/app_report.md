# 앱: 카메라 연결을 위한 별도 소스 작업본 준비

원본을 보존하고 `app-development/camera-preparation/`에 관리 앱의 현재 소스·설정을 복사했다. 로컬 변경도 포함한 소스 사본이며 새 Git 작업트리나 배포본은 아니다.

## 무엇을 준비했는가

관리 앱의 로그인·대상자·기록 화면은 그대로 두고 `packages/web/src/prepared-camera/`에 기존 측정 앱의 카메라 열기/닫기, MediaPipe 생성/종료, 프레임별 관절 좌표 콜백을 준비했다. `index.ts`가 화면에서 사용할 연결 지점이다. 프레임 루프가 받아들이는 관절 배열과 시각 자료형만 따로 가져왔다. 전체 SPPB 측정 엔진이나 점수·실패 판정 기준은 가져오지 않았다.

흐름은 카메라 → MediaPipe → 프레임 시각과 관절 좌표 또는 미검출(null)이다. 이는 기존 모듈의 역할이며 이번에 관리 화면에서 실제 카메라가 동작한 것은 아니다. 원본 영상 녹화 기능도 아니다.

SPPB 저장과 모의 측정 화면은 아직 사본에 남아 있다. 연결 준비 단계에서 임의로 새 저장 형식·임상 판단·측정 실패 정책을 적용하지 않았다.

## 검사와 한계

- 관리 앱 전체 웹 TypeScript 검사 통과. 준비한 카메라 모듈도 검사 범위에 포함된다.
- 기존 관리·core 검사와 가져온 프레임 시각 검사에서 최초127개 통과. 보고서 화면 검사1파일은 Supabase 경로를 찾지 못해 수집 실패했다.
- 사본 검사 설정에서 기존 설치 경로만 연결한 뒤 실패 파일의5개 검사도 통과했다. 합계132개다. 첫 실패 기록은 보존했다. 소스·검사 조건은 바꾸지 않았다.
- 원본95개 입력 파일의 SHA256이 복사 전후 같음을 확인했다. Git 현재 상태는 app_git_state.json에 기록했다.
- 실제 카메라, 브라우저 연결, 서버, 영상 측정 정확도, 런타임 번들 동작은 검사하지 않았다. 이132개는 코드·합성·모의 검사다.

새 패키지는 설치하지 않았다. 로컬 검사 설정은 원래 측정 앱의 MediaPipe1.1.0과 관리 앱의 Supabase2.117.3을 읽는다. D_P 루트의 MediaPipe1.0.1과 섞이지 않게 경로를 명시했다. 환경 파일·서버키·node_modules·git·DB·빌드·잠금 파일은 사본에서 제외했다. 따라서 독립 설치/실행 준비가 완성됐다고 볼 수 없다.

## 다음 앱 작업

이 사본에서 기존 모의 측정 화면과 구분되는 카메라 미리보기·관절 표시 화면을 연결할 수 있다. 먼저 실제 사용할 MediaPipe 의존성과 잠금 파일, 같은 출처의 WASM 자산을 준비한다. 시작/중단 때 스트림과 프레임 루프·모델이 정리되는지 실제 브라우저에서 확인한다. 대상자 연결·영상 보관·측정값 저장 정책은 별도로 결정해야 한다. 점수 모델 완성을 기다릴 필요는 없다.

검사 명령: 번들 Node로 D_P/node_modules/typescript/bin/tsc --project packages/web/tsconfig.local.json --noEmit; D_P/node_modules/vitest/vitest.mjs run --config vitest.local.config.mjs; 의존성 수정 후 마지막 명령에 packages/web/src/data/report.test.ts를 지정했다. 작업 폴더는 위 사본 루트다.
