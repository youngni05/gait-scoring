# GPU 실험 준비 — 무엇을 비교하고 왜 하는가

## 이번에 답할 질문

**같은 보행 자료를 사용했을 때, MotionBERT 일부를 학습하면 정답 오차와 앞뒤 구간의 점수 흔들림을 함께 줄일 수 있는가?**

Kernel Ridge 비교에서는 명확한 교체 근거가 없었다. 이제 점수 계산식만 바꾸는 데서 나아가, 관절 움직임을 요약하는 MotionBERT 특징 자체를 제한적으로 조정해 볼 차례다. 성공을 보장하거나 MotionBERT가 문제의 원인이라고 확정한 것은 아니다.

## 필요한 비교: 기준 하나 + 실험 세 가지

| 구분 | 바꾸는 부분 | 확인할 것 | 실행 위치 |
|---|---|---|---|
| 기준 | 기존 MotionBERT + alpha1 Ridge 그대로 | 비교 출발점 | 저장한 결과 재사용 |
| 1. 추가 학습 대조 | 점수를 계산하는 선형 출력부만 | 단순히 학습을 더 해도 좋아지는가 | CPU 가능 |
| 2. 작은 부분학습 | 마지막 특징 변환 + 같은 출력부 | 특징을 조금 조정하는 효과가 있는가 | GPU 묶음에 포함 |
| 3. 마지막 단계 학습 | 마지막 Transformer 단계 + 특징 변환 + 같은 출력부 | 시간·관절 관계를 요약하는 부분까지 바꿀 가치가 있는가 | GPU 권장 |

학습 매개변수는 각각 1,026개 / 133,122개 / 3,293,188개다. 뒤 두 수에는 출력부 1,026개가 포함된다. 전체 MotionBERT 학습은 이번 묶음에서 제외한다.

출력부는 기존 Ridge 계수로 초기화한다. 추가 학습 후에는 Ridge의 닫힌 형태 해를 다시 계산한 모델이 아니라 **기존 Ridge에서 시작한 선형 출력층**이다. 세 실험 모두 동일한 출력부 학습을 수행하며, 추가로 MotionBERT를 바꾸는 범위만 달리한다. 이전 누락 연구의 16노드 비선형 잔차 모델을 재실행하는 구성이 아니다.

## 공정한 비교 조건

- 기존 개발자료 175명·203기록, 사람 기준 5묶음을 그대로 사용한다. 한 묶음당 학습140명/평가35명이며 같은 사람이 양쪽에 들어가지 않는다.
- 앞124프레임으로만 학습하고, 같은 영상의 앞·뒤124프레임으로 평가한다. 중간 구간의 원입력은 이번 묶음에 넣지 않았다. 이전 연구의 세 구간 평균 지표와 직접 섞어 비교하지 않는다.
- 같은 초기 가중치·사람 분할·샘플 순서·출력부 학습률·배치 크기·업데이트 수를 사용한다. 마지막 단계 학습은 매개변수가 더 많으므로 계산시간까지 같다고 주장하지 않는다.
- 모델 전체의 dropout은 꺼 두어 기존 기준과의 차이에 새로운 무작위 동작이 섞이지 않게 한다.
- 학습 손실은 좌우 GDI의 제곱 오차이며 기록마다 같은 비중을 둔다. 보고할 오차는 기존처럼 먼저 한 사람 안에서 평균한 뒤 사람 간 평균을 낸다.
- 학습률·업데이트 수·배치·weight decay는 `protocol.draft.json`에 미정으로 남겼다. GPU 계산량 확인 후, 평가 결과를 보기 **전에** 확정한다. 현재 초안으로 실제 자료 학습은 실행되지 않는다.
- 시드3개 × 사람분할5개 × 실험3개 = 최대45개 작업이다. 대조군은 저장한 특징으로 CPU 실행할 수 있다. 세 방법의 초기화와 입력 순서를 맞춘다. 잘 나온 시드만 골라 보고하지 않는다.
- 보호된 기존37/38명·새최종223명과 새520명은 읽거나 포함하지 않았다. 이미 여러 번 탐색한 개발자료이므로 독립 최종 성능이라고 주장하지 않는다.

## 결과를 판단하는 방법

1. **정답 오차:** 앞/뒤에서 GDI 정답과 얼마나 다른가?
2. **앞뒤 일관성:** 같은 영상의 앞과 뒤 점수가 얼마나 다른가?
3. **점수가 한 값으로 몰리는지:** 모두에게 비슷한 점수를 주면서 일관성만 좋아진 것은 아닌가?

사람 단위로 오차 차이와 재표집 구간을 함께 계산한다. 출력부만 학습한 대조군보다 2번이 좋아야 특징 조정의 근거가 된다. 3번은 2번보다 추가 이점이 있을 때만 더 큰 계산량을 쓸 이유가 생긴다. 어느 한 수치만 좋아졌다고 채택하지 않는다. 임상 성공 경계는 새로 정하지 않았다.

기존 기준값: 앞 MAE **8.276**, 뒤 MAE **9.034**, 앞뒤 차이 **3.960** GDI점. 이번에는 그 값의 재현만 확인했으며 새 학습 성능은 없다.

**같은 영상의 앞뒤 비교는 다시 촬영하거나 각도를 바꿨을 때의 안정성 검증이 아니다.** 이 비교가 성공해도 다른 각도·고령자·가정 환경에서 같은 성능을 낸다는 뜻은 아니다. 입력은 이미 추출된2D관절 좌표이며 원본 RGB 추정기 개선 실험도 아니다.

## 들어 있는 파일

- `train_only.npz`: 앞/뒤 관절 입력, 기존 특징, 좌우 GDI, 사람/영상 연결, 기존 fold. 원본 RGB 영상은 없다.
- `baseline_heads.npz`, `baseline_predictions.npz`: 기존 비교 기준.
- `MB_lite.bin`, `lib/`, `MOTIONBERT_LICENSE`: 기존 가중치와 변경하지 않은 모델 코드·코드 라이선스.
- `run.py`: 초기값 점검, 가상 입력 검사, GPU 계산량 점검, 한 실험 실행/재개.
- `batch.py`: 순차 실행 목록, 일괄 실행, 전체 결과 집계. 누락된 fold가 있으면 집계를 중단한다.
- `verify_synthetic.py`: 가상 자료로 전체 학습 루프의 강제 중단·재개를 검사한다.
- `manifest.json`: 묶음 내용의 SHA-256 지문. 내용이 바뀌면 실행을 중단한다.

원래 자료와 가중치의 이용조건은 코드 라이선스와 별도다. 이는 사용자 로컬 준비 묶음이며 외부 GPU로 전송하거나 공개 배포하지 않았다. Python/라이브러리 실행환경 자체는 압축본에 포함하지 않았다.

## GPU 연결 뒤 실행 순서

연결 전에 GPU 모델·VRAM, 운영체제, 접속 방식(SSH/Jupyter 등)을 알려주면 환경에 맞춰 진행할 수 있다. 지금 확인한 환경은 Python의 PyTorch2.14.1+cpu / NumPy2.3.5다. CUDA 환경의 설치·호환·메모리는 아직 확인하지 않았다. GPU 환경에 호환되는 PyTorch와 NumPy가 필요하다.

압축을 푼 폴더에서 먼저 검사한다. `profile`의 라벨과 관절 입력은 전부 가상 자료이며 실제 연구 학습이 아니다.

```bash
python -B run.py check --device cuda --output checks/gpu_replay
python -B run.py profile --device cuda --batch-size 1 --output checks/gpu_profile_b1
python -B verify_synthetic.py --output checks/cpu_resume
```

`profile`은 124프레임 입력의 전파·역전파·optimizer 갱신에 대한 최고 할당 메모리와 시간을 확인한다. 출력의 시간에는 체크포인트 저장이 포함되므로 순수 GPU 계산시간이 아니다. GPU의 전체 여유 메모리를 뜻하지도 않는다. 배치 크기를 올려 볼 때에는 별도 출력 폴더를 사용한다. `check`는 CPU와 같은 기준 점수를 재현하는지 기술 허용오차1e-4점으로 검사한다. 이는 임상 허용오차가 아니다.

확인 후 `protocol.draft.json`을 **새 파일 `protocol.ready.json`으로 복사**하고 미정값을 채우며 status를 ready로 바꾼다. 초안 파일은 묶음 지문에 포함되므로 직접 수정하지 않는다. 합의한 예산 밖의 자동 탐색은 없다.

```bash
python -B batch.py list --config protocol.ready.json --output runs/main --device cuda
python -B batch.py run --config protocol.ready.json --output runs/main --device cuda
python -B batch.py summarize --config protocol.ready.json --output runs/main
```

중단 시 같은 설정·출력 경로로 `run`을 다시 실행하면 마지막 저장 지점부터 이어간다. 기본 초안은10step마다 저장하며 마지막step에는 반드시 저장한다. 그 사이 중단되면 마지막 저장 이후 step을 다시 수행한다. 이미 완료된 작업은 예측파일 지문을 검사하고 재학습하지 않는다. 설정·모드·fold·시드·묶음 지문·PyTorch버전·CPU/CUDA 종류가 다르면 잘못된 재개로 보고 중단한다.

학습은 FP32 MotionBERT와 FP64 출력부로 준비했다. mixed precision·일관성 손실·전체 모델 학습·새 구간 증강은 이번 실험에 섞지 않았다. 좁은 공간의 실제 촬영 및 원본영상→좌표의 정확도는 별도 과제로 남는다.
