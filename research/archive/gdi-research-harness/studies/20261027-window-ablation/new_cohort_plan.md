# 새 사람을 개발용·최종 평가용으로 먼저 나누기

사용자는 검증37명이라는 작은 수를 우려했고, 질문에 ‘개발용·최종 평가용으로 먼저 나누기’를 선택했다. 이는 새 자료를 정답을 보기 전에 사람 단위로 분리하는 방향의 승인이다. 새 최종 평가 정답으로 모델·구간·정규화·임계값을 고르는 승인은 아니다.

입력 준비가 끝난743명을 대상으로,약30%인223명을 최종 평가용으로 먼저 보존하고 나머지520명을 개발 후보로 둔다. 목적은 기존37명보다 큰 사람 평가를 준비하면서 추가 학습의 여지도 남기는 것이다. 이 비율은 실용적인 설계 선택이지 검정력 분석이나223명이 충분하다는 임상적 근거가 아니다. GDI 연결이 아직 미확인이므로 유효 최종 평가 인원은223명 이하일 수 있다. 정답 누락이 있어도 정답값이나 예측 결과를 보고 평가 사람을 바꿔 채우지 않는다.

구체적 방법: 기존 고정 입력 검사 목록의prepared 사람ID를 정렬하고 numpy.default_rng(20261027)로 한 번 섞는다. 처음223명을 최종 평가용으로,나머지를 개발용으로 지정한다. 같은 사람의 준비·실패 기록 모두 같은 용도를 갖는다. 실제 평가 입력 목록은 이미 준비된 기록으로 고정한다. 입력이 준비되지 않은370명은 이번 대상에 추가하지 않는다. 기존 개발212명·평가38명과 겹침0을 다시 확인한다.

새 분리는 기존175명학습/37명검증과 이번 길이·정규화 실험을 바꾸지 않는다. 개발용520명은 아직 학습 자료로 합치지 않는다. GDI 정답이 연결돼야 실제 사용 가능한 표본이며,원본 자료의 이용 조건·기관 심의 확인을 대신하지 않는다. 신규 자료는 같은 배포 자료의 다른 사람으로 외부기관·고령자 가정촬영 검증이 아니다.

이번 실행은 분리 목록과지문·집계·재현 검사를 남기며 gdi.csv는 열지 않는다. 다음에는 고정된 목록을 기준으로 정답 연결의 누락·중복·좌우 완전성을 확인할 절차를 준비한다. 개발용 정답 확인과 최종 평가 정답 보존을 구분한다. 최종 점수 비교는 개발 방법을 고정한 뒤 한 번 수행한다. 새 후보는243장 준비0건이므로 이 평가만으로243장보다 정확하다는 직접 비교는 할 수 없다.
