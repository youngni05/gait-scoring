# SynthGait-19K 실제 배포 확인과 GDI 사전학습 검토

후속 확인 — 2026-11-01: [측면20개 실제 변환·검산 결과](sagittal20/README.md)를 추가했다.20개·1231프레임의기존12특징은생성했지만길이·시간대응·품질조건이남아기존124프레임CNN용사전학습파일럿은보류했다. 아래는최초배포조사시점의기록이다.


2026-11-01 · 상태: 공개 파일 조사와 실행 계획 준비. GPU 실행·새 학습 제출은 하지 않았다.

현재 판단은 **합성 영상으로 보행을 먼저 배우게 한 뒤, 실제 GDI 자료로 다시 학습하는 갈래를 검토할 가치가 있다**는 것이다. 다만 공개 가중치는 RGB 영상 모델용이며, 지금의 관절 좌표 CNN/STT에 바로 넣을 수 없다. 공개 자료에는 GDI 정답도 없다. 기존 학습·예약·GPU 할당은 이번 조사에서 변경하지 않았다.

## 실제로 무엇을 확인했는가

웹 소개뿐 아니라 공식 저장소의 고정 버전, 데이터 목록과 실제 표본, 가중치 파일의 내부 목록을 확인했다. 전체 데이터와 전체 가중치를 받은 상태는 아니다.

| 항목 | 확인 결과 | 아직 확인하지 못한 범위 |
|---|---|---|
| 데이터 | 공개 TAR 127개, 전체 파일 약 126.39GB. 배포 목록은 6,427개 움직임에서 만든 19,272개 영상이다 | 전체 TAR 무결성·모든 영상의 품질 |
| 실제 표본 | 첫 TAR의 앞 24MiB에서 `vid_00002_frontal`의 MP4·NPZ·JSON을 회수했다. NPZ에는 보행 지표 6개와 좌우 접지 시점 배열이 있다 | 영상 디코딩·관절 추출은 미실행. 측면 표본은 아직 회수하지 않았다 |
| 코드 | 공식 GaitXFormer 학습·추론·전처리·설정 소스를 고정 버전으로 보존했다 | 서버 설치·실행, 외부 의존성 전체 재현 |
| 가중치 | `gaitxformer.pth.tr`, 1,316,500,791바이트. 원격 ZIP 구조와 메타데이터에서 encoder·decoder·6개 출력층 관련 키를 확인했다 | 전체 다운로드·SHA256 대조·모델 로딩·추론 |
| STT 공개물 | 확인한 공식 코드 트리에는 GaitXFormer 구현이 있다 | 이 배포에서 바로 쓸 STT 사전학습 코드·가중치는 찾지 못했다 |

실제 NPZ의 `features`는 `[114.8936, 1.1840, 0.6613, 0.1297, -0.0199, 0.5787]`이다. 순서는 걸음 빈도·보행 속도·평균 한 걸음 길이·평균 보폭 너비·상체 기울기·팔 흔들림이다. 이 값들은 GDI가 아니다.

공개 구조와 확인한 표본에 **2D 관절 좌표, 3D 관절 각도, SMPL 배열, GDI, 원래 사람 ID는 없다.** 논문에서 활용한 원자료나 3D 생성 과정과 실제 배포 파일을 구분해야 한다. 이 파일만으로 실제 GDI를 계산하거나, 원래 사람을 기준으로 분할했다고 검증할 수 없다.

자료의 같은 `vid_XXXXX`는 동일 움직임의 여러 시점이다. 공식 분리는 이 시점들을 같은 쪽에 둔다. 이는 움직임 단위 분리이며 사람 단위 독립 검증을 확인한 것은 아니다. 파일명은 `saggital`, JSON의 시점 이름은 `sagittal`이므로 변환 시 둘을 연결해야 한다.

근거: [공식 데이터 카드](https://huggingface.co/datasets/SoroushMehraban/SynthGait-19K), [공식 코드](https://github.com/TaatiTeam/SynthGait-19k), [공개 가중치](https://huggingface.co/SoroushMehraban/GaitXFormer). 실제 회수 범위와 파일 지문은 [file-probe.json](file-probe.json), 소스 고정 내역은 [source-receipt.json](source-receipt.json)에 있다.

## 지금 입력과 무엇이 다른가

| 조건 | 현재 GDI 실험 | 공개 GaitXFormer |
|---|---|---|
| 입력 | OpenPose에서 만든 좌우 다리별 124프레임·12특징. 여러 구간 묶음은 `(windows, 2, 124, 12)` | RGB 영상. 공개 데모는 가운데 5초에서 최대 81프레임을 확보하고 32프레임을 선택 |
| 공간 처리 | 신체 길이로 정규화한 좌표·투영 각도·거리 | 사람 검출·정사각형 자르기 후 좌우 가장자리 제거. 높이 256 설정에서 실제 입력은 `(B, 3, 32, 256, 192)` |
| 시간 | 기존 원본 프레임과 구간 시작점을 유지 | 영상 16FPS. 접지 주석은 별도 30Hz 시간축 |
| 출력 | 좌우 GDI | 위의 보행 지표 6개 |
| 특징 추출 | 현재 CNN/STT 구조 | V-JEPA2 ViT-L + cross-attention. 코드상 `return_features=True`로 평균 1024차원 특징도 반환 |

RGB의 가중치를 관절 CNN/STT에 직접 불러올 수는 없다. GDI 학습에 사용 중인 좌표와 같은 기록의 원본 RGB 영상도 현재 이 검토의 입력으로 확보되지 않았다. 따라서 RGB 모델의 출력층만 GDI로 교체하는 방법은 즉시 실행할 수 없다.

공식 전처리에서는 256×256으로 자른 뒤 가로 양끝을 각각 32픽셀 제거한다. 설정의 `height: 256`만 보고 정사각형 입력이라고 가정하지 않는다. 코드 근거는 `source/utils/inference.py`의 `prepare_clip` 관련 경로와 `source/data/video_preprocessing.py`의 `crop_resize`다.

시간 변환은 접지 번호를 `번호 / 30`초로 바꾼 뒤 영상 시간에 대응시키는 방식부터 확인한다. 실제 시작 시점 차이도 점검한다. 16FPS를 기존 FPS로 보간해도 새 움직임 정보가 생기는 것은 아니다. **같은 시간 변환을 거친 무작위 초기화 대조군**을 두어야 사전학습 효과와 시간축 변경 효과를 구분할 수 있다.

## 현재 가능성이 있어 보이는 활용 순서

### 1. 영상에서 같은 관절 특징을 만들어 보행 사전학습

질문은 ‘합성 보행으로 먼저 학습한 CNN이, 같은 실제 사람 자료에서 GDI를 더 잘 예측하는가’다.

```text
합성 측면 영상 + 걸음 빈도 정답
          ↓
현재와 같은 OpenPose BODY25 관절 추출
          ↓
현재와 같은 다리별 12특징 + 명시적인 시간 변환
          ↓
걸음 빈도 예측으로 CNN의 시간별 특징을 먼저 학습
          ↓
마지막 출력층을 좌우 GDI용으로 교체
          ↓
기존 692명·같은 사람 분할에서 GDI 미세조정·평가
```

우선 CNN 한 갈래로 시작하는 편이 변화 원인을 확인하기 쉽다. 걸음 빈도는 시간 정보가 맞으면 좌표에서도 배울 수 있는 첫 보조 목표다. 다만 현재 모델의 걸음 박자 의존을 더 키울 위험도 있다. 따라서 보조 과제 성능만으로 채택하지 않고, GDI 고득점 오차와 속도 변화 민감도를 함께 확인한다.

팔 흔들림은 현재 다리 특징에 없고, 측면 영상의 보폭 너비는 관측이 약하며, 절대 속도·길이는 신체 크기 정규화와 충돌할 수 있다. 여섯 정답을 처음부터 모두 붙이지 않는다. 이후 입력에 실제로 담긴 정보와 정답 관계가 확인된 항목만 추가 후보로 둔다. 시간 늘이기·줄이기를 쓰면 걸음 빈도 정답도 같은 배율로 바꿔야 한다.

### 2. 공개 RGB 가중치를 ‘교사’로 사용하는 갈래

동일 합성 영상에서 고정 GaitXFormer의 1024차원 특징과 관절 CNN 특징을 뽑는다. CNN 쪽에 작은 변환층을 붙여 영상 모델의 특징을 따라 배우게 하고, 이후 GDI로 미세조정한다. 이를 지식 증류라고 한다. 실제 GDI 추론 때 RGB 교사가 없어도 된다는 장점이 있다.

비교는 `사전학습 없음 / 보행 정답 사전학습 / 보행 정답 + 교사 특징 학습`으로 나눈다. 이 단계는 우리가 새로 적용할 실험이며 공식 코드에 완성된 관절 모델 증류 기능이 있다는 뜻은 아니다. RGB 교사가 배경·체형 신호를 전달할 위험이 있고, 1024차원 특징이 GDI에 유용한지도 미확인이다.

공개 RGB 모델을 그대로 GDI 예측기로 미세조정하는 갈래는 **RGB와 실제 GDI가 연결된 개발 자료를 확보한 뒤** 검토한다. GDI 정답 없는 LJMU에 임의의 100점을 붙여 이 문제를 해결하지 않는다.

## 다음 실행을 위한 단계와 산출물

아래는 실행 후보 계획이다. 새 GPU 학습은 아직 시작하지 않았으며, 파일럿을 통과한 실행 묶음도 아직 없다.

| 순서 | 실제 작업 | 자원·우선 예산 | 다음 단계로 넘어가기 전에 확인할 것 |
|---|---|---|---|
| 1 | 서로 다른 움직임의 측면 표본 20개를 스트리밍 방식으로 확보. 영상·주석·시점·길이 확인 | CPU. 원본·캐시 합계 10GiB 상한으로 시작 | 실제 디코딩, 주석 시간 대응, 영상별 파일 지문. 충분한 측면 표본이 없으면 사용량을 임의 확대하지 않고 원인 기록 |
| 2 | 같은 OpenPose·기존 12특징 변환기를 연결. 원시 시간·관절 신뢰도·유효 마스크 보존 | 관절 추출 GPU 1개가 유리하며 CPU도 가능. 처리 시간은 20개로 측정 | 기존 공개 표본 재현, 좌우·관절 순서·정규화 일치. 124프레임에 필요한 실제 시간이 부족한 영상은 별도 표시 |
| 3 | 외부 사전학습용 후보 200개 움직임으로 확대. 같은 움직임의 시점은 반드시 묶음 | CPU 준비 후 CNN GPU 1개. 사전학습 3epoch·GDI 3epoch 파일럿 후보 | 유한 손실·가중치 갱신·재개·저장 모델 재추론·누수 검사. 200개는 새 사람 200명을 의미하지 않음 |
| 4 | 같은 전처리 대조군과 사전학습 CNN을 기존 사람 5분할로 비교 | GPU 1개짜리 독립 작업으로 분할 병렬화 가능. 우선 최대 3개 후보이나 실제 제출 전 자원·권한 확인 | 내부 검증에서만 epoch·미세조정 범위 선택. 전체 OOF와 고득점 오차·편향 검산 |
| 5 | 1~4의 입력 계약이 성립하면 전체 가중치와 통계 파일을 받아 고정 교사 파일럿 | RGB 교사 GPU 1개, A6000에서 batch 1로 먼저 메모리 측정. 모델 전체 재학습은 후순위 | 전체 SHA256, strict loading, 출력 정규화, 동일 입력 재추론. 특징 증류 효과를 보행 정답 사전학습과 분리 |

시간과 VRAM은 이번에 실측하지 않았다. 첫 환경·관절 추출·교사 검사에는 각각 30~60분의 실행 한도를 두고, 완료 속도와 최대 메모리로 본 실험 예산을 다시 산정하는 안이다. 이 한도는 예상 소요 시간이나 완료 보장이 아니다. 24시간 이상의 본 학습 할당도 측정 후 결정한다.

원본은 약 126GB이고 공식 RGB 전체 캐시는 약 350GiB 수준이다. 조사 당시 D 여유 공간은 132,639,461,376바이트여서 두 가지를 함께 만들 수 없다. 전체 다운로드 대신 필요한 표본을 순차 처리하고 작은 관절 특징을 보존한다. 대량 다운로드 전에 D 여유 공간을 다시 확인한다.

## 학습·평가에서 지킬 경계

- 실제 GDI 평가는 기존 692명·1,061기록·같은 바깥 5분할과 여러 구간·좌우 집계 방식을 유지한다. 참조 입력 계약은 `../20261030-gpu-motionbert-study/cnn-multiwindow695/bundle/input_contract.json`이다.
- GDI 정규화·보정·학습 종료 선택에는 해당 바깥 평가 사람을 쓰지 않는다. 내부 검증까지 미세조정 범위 선택에 포함한다. 보호된 최종 평가자료는 열지 않는다.
- 외부 사전학습 자료와 GDI 평가 사람의 중복 여부는 출처 조사로 확인해야 한다. 공개 사람 ID가 없어 완전한 대조가 어려우면 이를 한계로 기록한다. 무관한 자료라고 가정해 완전 독립을 주장하지 않는다.
- 외부 사전학습의 검증은 움직임 단위로 묶고 같은 움직임의 시점을 섞지 않는다. 사람 단위 분리는 원본 ID를 추가 확보하기 전까지 검증할 수 없다. 사전학습 길이는 외부 검증으로 정하며 GDI 평가 정답을 보지 않는다.
- 비교 조건은 입력·시계열 길이·사람 비중·추출 순서·보정·학습 선택을 맞추고 초기 가중치/사전학습만 바꾼다. 같은 조건의 무작위 초기화 모델을 주 대조군으로 삼는다. 기존 최선 결합과의 비교는 별도로 제시한다.
- 전체 사람 동일비중 MAE, 실제 90/100 이상 관측과 사람평균 기준 집단별 MAE·편향·인원을 구분한다. 고득점 개선과 전체 악화가 함께 생기는지 확인하고 사람 단위 재표집으로 변화의 불확실성을 본다.
- 걸음 빈도 사전학습이 박자 지름길을 강화하는지 시간 변화 민감도를 비교한다. 합성 데이터 증가가 실제 독립 평가 인원을 늘린 것은 아니다.
- 측면 영상에서 보이지 않는 3D 각도 정보나 정상 성인의 실제 GDI 정답은 이 방법으로 자동 확보되지 않는다. 고득점 수축·LJMU 점수 이동을 해결할지는 별도의 실험 결과로 판단한다.

## 실행 환경·사용 조건

공식 소스에는 Python 3.10 이상 문법이 있어 기존 서버 Python 3.8 환경에 그대로 설치하지 않는다. 별도의 3.10 이상 환경에서 CUDA/PyTorch·영상 디코더·관절 추출기를 확인하는 단계가 필요하다. 현재 설치된 환경은 변경하지 않았다.

`torch.hub`의 V-JEPA2 의존성이 고정되어 있지 않고 패키지 다수에도 버전 지정이 없다. 실행 전에 상위 저장소 commit과 의존성 버전을 고정한다. 전체 추론에는 공개 `data/gait_stats.pkl`의 확인도 필요하다. 이번에는 원격 체크포인트의 pickle 명령을 실행하지 않고 `pickletools`로 이름만 읽었다. 전체 파일 로딩 검사는 남아 있다.

데이터의 Research Use License는 비상업 연구를 허용하지만 제품 개발·운영·임상 사용에는 별도 조건이 있다. [보존한 원문](metadata/LICENSE)을 따른다. 공개 코드 트리의 독립 LICENSE와 모델 저장소의 명시적 가중치 라이선스는 이번 조사에서 찾지 못했다. 데이터 라이선스가 코드·모델 사용권까지 자동 부여한다고 해석하지 않는다. 코드 재배포·교사 가중치 활용 전에는 해당 범위를 추가 확인한다.
