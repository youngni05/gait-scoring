## 질문과 고정 조건

방문별 실제 GDI를 맞히는 학습에 같은 사람의 두 방문 GDI 차이를 맞히는 항목을 추가하면 변화 추적이 개선되는지 확인한다. 초기 상태 예측과 방향·좌우 결과도 함께 보고한다. 임상적 개선이나 최소검출변화량은 평가하지 않는다.

| 조건 | 방문별 손실 | 변화량 손실 비중 |
|---|---|---:|
| arm0 (`seed0/`) | 기존 구간별·기록별 균형 MSE+기존 정규화 | 0 |
| arm1 (`seed1/`) | 동일 | 1 |

폴더의 seed0/seed1은 전송·회수 도구의 기존 이름을 유지한 **손실 조건 ID**다. 초기값을 다르게 한 실험이 아니다. 두 조건의 초기값은 원래 20261028과 분할별 기존 규칙으로 동일하다. 같은 692명·1,061기록·11,261구간·124프레임·12특징·기존 CNN 구조·사람 5분할·각 내부 4분할·100 epoch 상한·배치32·RMSprop·학습률/감쇠·dropout·kernel L2·학습자료만의 정규화/OLS를 유지한다. 종료 시점도 기존 내부 방문별 보정 GDI의 사람별 평균오차로 선택한다. 변화 성능으로 좋은 epoch나 조건을 고르지 않는다.

변화 항목은 매 optimizer step에서 학습 사람을 같은 확률로 한 명 고르고, 그 사람의 서로 다른 보고 나이 두 검사를 같은 확률로 고른다. 두 영상의 **사용 가능한 모든 구간을 평균한 예측 차이**와 정답 차이의 좌우 평균 제곱오차를 계산한다. 정답 차이는 현재 학습 사람의 min-max 범위로 나눠 방문별 손실과 단위를 맞춘다. 가중치1을 고정하며 평가 정답으로 조정하지 않는다.

변화 forward는 실제 추론과 같은 평가 모드에서 기울기를 연결한다. 이 추가 경로가 기존 BN 통계와 dropout 난수를 바꾸지 않게 한다. 방문별 학습 경로와 optimizer step 수는 동일하지만 변화 항목의 계산이 추가되므로 연산량·시간이 같은 비교는 아니다. 상태 손실만 있는 조건이 기존 baseline과 정확히 일치하는지는 가상자료에서 확인했다.

한 조건당 내부학습20개+최종재학습5개, 두 조건 합계50학습·10바깥평가다. 기존 CNN/STT 결합의 변화오차7.5701점을 이번 새 단독 CNN의 기준 성능으로 쓰지 않는다. 두 단독 CNN 조건을 직접 비교한다. 최초 상태는 반복 검사에서는 보고 나이가 가장 작은 방문을 사용하며 실제 등록일·추적 일수를 뜻하지 않는다.

## 실행·검산

원본 기준 묶음은 읽기 전용이다. `build.py`로 새 두 묶음을 만들었다. CPU 가상 검산은 두 조건 모두 통과했다. 가상 중첩학습25개, 중단재개 일치, 검증 정답 변경에 대한 학습 불변, 변화 항목의 기울기 연결, 독립 손계산과의 일치, 추가 forward의 BN/난수 보존을 확인했다. 실제 개발 입력은 형식·연결만 읽었고 CPU 실제 GDI 학습은0회다.

서버에서는 각 GPU worker가 가상 검산→학습416명/내부검증138명·3epoch 파일럿→GPU64/CPU64 재추론 검산을 수행한다. 파일럿을 D로 회수해 지문·모든 epoch·로컬 CPU64 재추론을 확인한 뒤에만 `approve-main.json`을 만든다. 파일럿 점수는 성능 결과가 아니다. 두 worker는 서로 다른 GPU UUID를 확인한다. 실제 파일럿 시간으로 본학습 시간을 추정한다.

본학습 결과는 모든 epoch의 지문·방문별 학습정답만의 보정·학습 순서·사람 분리·epoch 선택을 검산하고, 조건당 최종5모델을 CPU64로 다시 추론한다. 계수/지표1e-10·재추론0.0001점 기준을 유지한다. 원자료·기존 모델·다른 채팅의 작업은 변경하지 않는다.

`manage.py`는 기존 두 worker 전송/회수 도구를 이 채팅 경로·등록부로 한정했다. 순서는 `deploy`→`submit`(보류 제출)→등록부/예약 확인→`release`→`fetch --kind pilot`→`approve`→전체 종료 후 `fetch --kind full`→`compare`다. `watch/registry.json`에는 실제 제출한 작업만 등록한다. 새 학습은 이미 승인됐으므로 각 단계의 검산이 통과하면 별도 반복 승인 없이 진행한다.

작은 코드·검산·요약은 이 C 폴더에 둔다. 가상 모델·원본 회수·체크포인트·대량 epoch 예측은 `D:/gait-research-data/D_P/gdi-research-harness/studies/20261101-gdi-pairloss-cnn`에 보존한다. 누적 예상은 약1~3GB이며 실제 크기는 회수 영수증을 따른다. 배정시간/서버부하에 따라 달라지고 오늘 완료를 보장하지 않는다. 다른 채팅의 기존 할당과 학습은 보존한다.

로컬 실행: 번들 Python에 기존 `outputs/motionbert-smoke-20261015/deps`·`outputs/gdi-ridge-experiment-20261016/deps`를 PYTHONPATH로 연결한다. 서버 Python은 `/usr/bin/python3.8`이다. CPU PyTorch와 서버 PyTorch 버전 차이는 파일럿 회수 재추론으로 확인한다.

현재 단계의 실제 제출/파일럿/본학습 상태는 `deployment.json`, `submission.json`, `watch/registry.json`, `watch/status-latest.json`, `checks/`와 `main-approval.json` 존재·내용을 따른다. 문서 준비만으로 학습 시작·성능 개선을 주장하지 않는다.
