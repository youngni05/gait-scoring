# 정상 LJMU 여러 구간 CNN 전처리 인계 결과

작성일: 2026-10-31 · 적용 계약: 팀원 전달 v2 · 처리 상태: 입력 생성·검증 완료

## 결과와 범위

정상 측면 보행 자료 **64명·987기록**을 요청 목록으로 처리했다. 제공된 v2 규칙에 따라 **64명·882기록·3,307구간**을 생성하고 **105기록**은 제외 사유와 함께 남겼다.

최종 `prepared_normal/prepared.npz`의 `x`는 **float32 `(3307,2,124,12)`**다. 축 순서는 구간·왼쪽/오른쪽·시간·특징이다. 모든 모델 특징값이 유한하다. GDI 정답은 넣지 않았다.

원본 수정, FPS 변환, 좌우 반전, 정상 자료의 GDI 추론, 학습, 보정값 재학습은 하지 않았다. 공개 샘플의 예측만 소프트웨어 재현 검사 목적으로 실행했다. 본 인계물은 시간축이 일치한 임상 검증 입력이 아니라 **원본 프레임 기준 탐색용 입력**이다.

## 먼저 확인한 재현 결과

팀원 ZIP의 manifest에 열거된 **684개 파일의 SHA-256이 모두 일치**했다. v1과 비교해 전처리 계산 코드와 모델 가중치가 유지됐음을 확인했다. 가상 입력 자체 검사도 통과했다.

실제 공개 개발 샘플 650프레임을 제공 코드로 처리해 예상값과 대조했다.

| 대조 항목 | 실제 결과 | 기준 |
|---|---:|---|
| 처리 구간·배열 | 12구간, `(12,2,124,12)` | 제공 예상값과 일치 |
| 특징 최대 절대 차이 | 0.0 | 0.000001 이하 |
| 시작·끝 프레임·결측 비율 | 정확히 일치 | 배열 단위 대조 |
| 5개 모델의 예제 예측 최대 차이 | 0.0 | 0.0001 미만 |
| 미확인 FPS 보존 | 확인 | FPS를 null/메타데이터 NaN으로 유지 |

이는 공개 개발 기록에서의 코드 재현이며 정상인의 예상 GDI나 임상 정확도를 확인한 결과가 아니다. 실제 실행 기록은 `public_sample_check/comparison.json`, `selfcheck.log`, `local_environment.json`에 있다.

## 원본과 실행 방식

기준 좌표는 `E:\Gait_Project\data\raw\gait_normal.zip` 안의 90도 기록이다. 이전 전수 점검에서 추출 폴더와 전체 기록별 파일명 목록이 같고 표본 본문 2,958개가 일치한 것을 확인했다.

작은 파일을 별도 드라이브에서 반복 여는 지연을 줄이기 위해, **파일 읽기 계층만 ZIP 스트리밍으로 연결**했다. 제공 `prepare.py`의 대상자 선택·입력 검증과 `preprocess.py`의 보간·평활화·정규화·특징·구간 계산은 수정하지 않았다. 코드와 가중치의 원본 해시도 유지했다.

ZIP 읽기와 기존 폴더 읽기를 공개 샘플 및 정상 `P1_E1T1_90_json`, `P1_E1T1_90_ALT_json`, `P45_E1T1_90_json`에서 대조했다. 특징 배열, 구간 위치·결측 비율, 품질 통계, 모든 프레임의 해시·선택 결과가 정확히 같았다. `zip_adapter_validation.json`에 기록했다.

최종 사용 기록의 원본 파일 **200,375개 해시**도 앞선 정상 ZIP 전수 점검과 모두 일치했다. 이는 최종 구간 프레임 수가 아니라 각 사용 기록에서 읽은 전체 원본 파일 수다. 같은 원본 프레임이 여러 겹치는 구간에 들어갈 수 있다.

입력 설정의 `json_dir`는 추출 폴더 경로를 유지하지만, 이번 실행에서는 `execution_summary.json`에 명시한 ZIP과 추출 루트의 대응으로 실제 ZIP 멤버를 읽었다. 재실행 시 이 읽기 방식을 구분해야 한다.

## 실제 적용한 전처리

**원본 BODY25 → 프레임별 대상 선택 → 전체 기록 보간·평활화 → 골반 중심·평균 허벅지 길이 정규화 → 좌우 12개 특징 → 여러 124프레임 구간**

- 여러 포즈에서는 수동 대상자를 지정하지 않았다. 한 포즈만 검출되면 사용하고, 0개 또는 여러 개면 시간축을 유지한 채 결측으로 둔다. 이것은 제공 코드의 기본 규칙이며 실제 동일 참가자 추적을 검증한 것은 아니다.
- 좌표 x/y의 0·NaN에 원래 보간 규칙을 적용하고, 전체 기록에서 Gaussian sigma=1프레임으로 평활화했다. 마지막 검출 뒤 결측 꼬리는 제공 코드대로 제거했다.
- 각 프레임의 양쪽 엉덩이 중점을 원점으로 옮기고 양쪽 허벅지 길이 평균으로 나눴다. 발끝을 포함해 좌우 12개 특징을 만들었다.
- 시작 위치 `0,31,...,372`의 124프레임 구간을 검사했다. 각 필수 x/y 열의 결측이 25%를 넘거나 구간이 짧거나 출력 특징이 비유한 경우 구간을 제외했다.
- 자동 뒤쪽 구간 검색이나 fallback을 추가하지 않았다. 실제 fallback 사용은 0기록이다.
- confidence는 원본 그대로 읽었고 범위 초과 값을 자르지 않았다. 해당 검증에 걸리는 기록은 v2 코드가 제외했다.

`excluded.csv`는 첫 실패 조건을 기록하므로 사유들이 모든 품질 문제를 열거하는 것은 아니다. 예를 들어 confidence로 먼저 제외된 기록에는 다른 문제도 있을 수 있다. `excluded_context.csv`에는 원본 길이·빈 검출·복수 포즈·신뢰도 범위 등 이전 전수 점검 정보를 연결했다.

## 처리 배열 검증

- 모든 특징은 유한한 float32이고, 각 구간은 원본 끝 프레임−시작 프레임=123이다.
- 구간→기록→참가자 연결, 요청/사용/제외 집합의 비중복·완전성, 기록별 구간 수를 검증했다.
- 골반 중점의 원점 오차 최대값은 약 **7.11e-15**, 정규화된 평균 허벅지 길이와 1의 차이는 최대 **1.19e-07**다.
- 좌우 발목 x 차이 특징은 부호가 서로 반대임을 확인했다. 각도 특징은 0~π 범위, 거리 특징은 음수가 아니었다.
- 일부 실제 처리 특징을 원본 골격과 시각 대조했다. 그림 `normalization_check.png`는 `P1_E1T1_90_json`의 원본 62번 프레임을 사용했다. 서로 다른 축 단위를 비교하므로 크기를 그대로 비교하면 안 된다.

이 검사는 배열·수식·연결 검증이다. 보간이 실제 움직임을 정확히 복원했거나 모델 예측이 정확하다는 검증은 아니다.

## FPS·대상자·촬영 조건의 확인 한계

사용자가 원본 영상이 없다고 확인했다. 따라서 모든 정상 기록에서 `fps=null`, NPZ 메타데이터에서는 NaN을 유지했다. 문헌상 30 FPS라는 설명과 개별 로컬 JSON의 실제 시간 간격을 구분했다. 특징 배열에는 NaN이 없다.

시간 정책은 `native_frames_exploratory`, 시간축 일치 상태는 `unverified`다. 30→25 또는 30→29.97 변환을 하지 않았다. 같은 124프레임의 실제 시간 길이가 학습 자료와 같은지는 확인되지 않았다.

BODY25의 좌우 인덱스와 영상 좌표축을 유지했고 좌우 교환·반전을 하지 않았다. 그러나 실제 해부학적 좌우, 거울 반전, 카메라 방향과 동일 참가자 여부는 원 영상으로 확인하지 못했다. 90도는 파일명 표시다. 이 조건은 `source_conditions.csv`에 전체 987기록별로 남겼다.

## 재실행과 다음 담당 작업

Python·NumPy·SciPy·CPU PyTorch가 있는 환경에서 제공 ZIP을 별도 폴더에 풀고, 입력 설정의 경로를 실제 자료에 맞춘다. 기존 결과를 덮어쓰지 않는다.

```powershell
python run_preparation.py --bundle PATH_TO_EXTRACTED_V2 --manifest records.json --out NEW_PREPARED_DIRECTORY --source-zip PATH_TO_NORMAL_ZIP --extracted-root PATH_TO_NORMAL_EXTRACTED_ROOT
```

추출 폴더를 직접 읽을 때는 `--source-zip`과 `--extracted-root`를 생략한다. 두 방식의 수치 동등성은 위 공개·정상 대조 사례에서 확인했다.

팀원은 v2 `infer.py`에 `prepared_normal/prepared.npz`를 입력해 예측할 수 있다. **정상 전체의 추론은 이 작업에서 실행하지 않았다.** 정상 GDI 정답을 임의로 부여하지 않고, 이후 모델별 예측 분포·좌우 차이·기록 간 변동을 전처리 품질과 함께 살펴보는 단계다.

현재 결과를 사용하는 데 추가 자료를 기다릴 필요는 없다. 다만 원 영상 기반 확인 한계는 남고, confidence 범위 초과로 제외된 기록의 재포함을 원하면 팀원과 규칙을 별도로 정한 뒤 새 버전으로 다시 처리해야 한다.
