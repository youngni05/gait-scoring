# 반복 기록 점검 결과

사용자는 현재 단계가 앱 개발·새 촬영이 아니라 알고리즘 개발 방향 테스트라고 정정했다. 직접 촬영 가능한 실용적인 앱은 최종 요구로 유지하되 지금의 선행 작업으로 강제하지 않는다.

개발용 연결 목록을 집계한 결과, 520명·861건 중 여러 기록이 있는 사람은 207명이다. 이 207명은 모두 둘 이상의 검사 번호를 가진다. 사람·검사 번호 조합은 861개이고, 같은 조합에 여러 영상이 있는 경우는 0개다. 영상 번호도 861개로 서로 다르다. 검사 번호가 다르다는 사실만으로 날짜·치료·상태 변화 여부를 알 수는 없다. 동일 상태에서 다시 촬영한 기록이라는 근거가 없으므로 점수 차이를 반복 측정 오차로 계산하지 않았다.

확인 범위는 이미 선택된 개발 입력 목록이다. 원본 공개 자료 전체에 반복 영상이 없다는 결론은 아니다. 원본 지문은 집계 전후 같았다. 기존 평가 38명과 예약 223명 파일은 열지 않았다. 새 학습·추론·점수 지표 계산은 하지 않았다. audit_result.json의 records_in_repeated_person_exam_groups는 빈 그룹에 대한 PowerShell 합계가 null로 기록됐으며, 그룹 수 0에 따라 해당 기록 수는 0건이다.

다음 실험 후보는 기존 입력을 이용한 모델 민감도 점검이다. 같은 원래 보행 기록에서 구간 선택이나 좌표 오차가 조금 달라질 때 출력 변화와 원래 GDI 정답에 대한 오차를 함께 비교하는 방법이다. 이는 새 촬영 반복 신뢰성과 구분한다. 이미 마친 프레임 길이 비교를 단순 재실행하지 않으며, 가능한 원본 구간·변환의 의미를 확인하고 구체적인 조건과 검사를 먼저 협의한다. 좌표 잡음이나 임의 변환을 실제 카메라 오차처럼 표현하지 않는다. 평균만 출력하는 모델도 안정적일 수 있으므로 안정성만으로 모델을 선택하지 않는다.

실제 완료한 작업은 반복 기록의 메타데이터 집계이며, 알고리즘 안정성 실험을 완료한 것이 아니다.
