# 노트20 울트라: 저장된 관절 특징으로 GDI 계산

기존 최종 평가에 사용한 54개 고정 모델을 휴대폰 안에서 실행하는 실험이다. 별도 앱 설치 없이 Android Chrome을 사용한다. PC는 모델과 저장 표본을 처음 전달한다. 점수 계산은 휴대폰 브라우저가 수행한다.

## 실행 순서

1. PC에서 이 폴더의 **`start-note20.cmd`를 더블클릭**한다. 실행 창과 PC 브라우저가 열린다. 실험 파일 준비가 끝날 때까지 실행 창을 유지한다.
2. 노트20 울트라와 PC를 같은 Wi-Fi에 연결한다.
3. PC 화면 아래 **「PC에서 휴대폰으로 열기」**를 펼친다. 휴대폰 카메라로 QR을 읽고 **Chrome에서 연다**. QR이 열리지 않으면 실행 창의 「휴대폰 주소」를 Chrome 주소창에 입력한다.
4. 휴대폰에서 **「실험 파일 준비」**를 누르고 「준비 완료」를 기다린다. 모델과 표본, 실행 엔진을 이 기기로 읽는 단계다. 파일은 약 25 MiB이며 실행 중 메모리 사용량과는 다르다.
5. 표본 A를 선택해 **「1회 계산」 → 「5회 반복 측정」**을 누른다. 화면을 켜 둔다. 첫 전체 실행과 반복 실행 시간을 구분해 기록한다.
6. 표본 B로 바꿔 **「1회 계산」 → 「5회 반복 측정」**을 진행한다.
7. **「실험 기록 저장 (.json)」**을 누른다. 한 파일에 A·B의 점수, PC와의 차이, 각 실행 시간과 기기 정보가 함께 저장된다. 이 파일은 휴대폰 다운로드 폴더에서 확인할 수 있다.
8. 실험이 끝나면 PC 실행 창을 닫거나 Ctrl+C로 종료한다.

「준비 완료」 뒤에는 PC 실행 창을 종료하고도 이미 열린 휴대폰 화면에서 두 표본을 계산할 수 있다. PC가 점수를 계산한 뒤 보내는 방식인지 구분하는 확인 방법이다. 페이지를 새로고침하거나 닫으면 다시 연결하고 준비해야 한다. 다른 주소로 이동하지 않고 현재 화면을 유지한다.

기기 이름은 기본값 `Galaxy Note20 Ultra`다. PC에서 먼저 확인할 때는 기기 이름을 PC로 바꾼다. 이 이름은 사용자가 적는 기록이며 기종을 자동으로 검증한 결과가 아니다.

## 화면에서 확인하는 값

| 값 | 의미 |
|---|---|
| 좌우 GDI | 휴대폰에서 54개 모델·기존 보정·결합식을 계산한 결과 |
| PC와 점수 차이 | 동일 입력의 기존 PC 결과와의 차이. 모든 회차에서 최대 차이 0.0001점 이하인지 확인 |
| 첫 전체 실행 | 파일·실행 엔진 준비를 마친 뒤 처음으로 전체 54개를 실행한 시간 |
| 총 실행 시간 | 모델 준비, 추론, 구간 평균·보정·결합, 해제를 포함한 시간 |
| 모델 준비 시간 | 한 번에 하나씩 실행 모델을 구성하는 시간. 파일 전송 시간과 다름 |
| 순수 계산 시간 | 모델 실행 호출에 걸린 시간의 합계 |
| 5회 중앙값 | 이번 다섯 번의 가운데 시간. 첫 실행을 자동으로 빼거나 준비 실행으로 처리하지 않음 |

속도에 새 합격 기준을 두지 않고 실측값을 기록한다. 실행 중 화면이 꺼지거나 다른 앱으로 이동하면 그 회차는 시간 비교에서 제외한다고 표시한다. 파일 전송과 실행 엔진 초기화는 별도 준비 시간이다. 스마트폰 전체 메모리·발열·배터리는 이 도구에서 정확히 측정하지 못한다.

## 입력과 계산 범위

**저장된 관절 좌표 → PC의 기존 전처리 → 휴대폰의 GDI 계산** 순서다.

표본 A·B는 기존 직접 촬영 영상 두 개에서 얻은 실제 저장 자료다. 같은 한 사람의 두 촬영이며 각 표본은 13개 구간이다. 한 구간의 입력 크기는 `[좌우 2, 시간 124, 특징 12]`다. 앞 8개는 발목·무릎·엉덩이·발끝의 xy 좌표이며, 나머지는 기존 각도·거리 특징이다. 보간·평활화·정규화·각도와 거리 계산은 이미 PC에서 수행했다. **원시 관절 좌표의 전처리나 영상 분석 전체가 휴대폰에서 실행된다는 뜻이 아니다.**

54개는 CNN 24개, STT 25개, 좌우 결합 STT 5개다. 출처 분할별 모델 평균 → 기존 CNN/STT 비율과 좌우 차이 결합 → 다섯 출처 분할 평균을 유지한다. 기존에 제외한 CNN 한 개도 그대로 제외한다. 학습, 양자화, 계수 재적합, 입력 구간 변경, 점수 자르기는 하지 않는다.

현재 계산은 ONNX Runtime Web 1.31.1의 WebAssembly CPU 1스레드다. GPU·NPU 가속을 사용하지 않는다. 한 번에 한 모델을 준비·계산·해제해, 54개 실행 모델을 메모리에 모두 유지하는 부담을 피한다. 따라서 모델 준비 비용이 매 실행에 포함된다. 속도는 이 구현의 값이며 기기에서 얻을 수 있는 최고 속도를 뜻하지 않는다.

표본에 실제 GDI 정답은 없다. 점수의 의학적 정확도, 정상·비정상 분류 성능, 다른 대상자에 대한 성능은 이 실험에서 판단하지 않는다. PC와 같은 계산을 수행하는지와 기기 실행 시간을 확인한다.

## 접속이 안 될 때

- PC 실행 창이 열려 있는지 확인한다. 화면을 여는 주소는 `file://`가 아니라 실행 창의 `http://...` 주소다.
- 학교·공용 Wi-Fi는 기기끼리의 접속을 막을 수 있다. 이 경우 노트20의 모바일 핫스팟에 PC를 연결한 뒤 PC 실험 창을 다시 실행해 새 QR을 사용한다.
- Windows가 Node.js의 네트워크 접근 허용을 물으면 사용자가 실험에 사용하는 신뢰할 수 있는 네트워크인지 확인한 뒤 직접 선택한다. 이 준비 작업은 방화벽 설정을 자동 변경하지 않는다.
- 「자료 지문 불일치」나 「PC와 점수 차이 기준 초과」가 나오면 정상 실행으로 간주하지 않는다. 화면 문구와 저장 기록을 확인한다.

## 파일과 재현

작은 코드·검산 기록은 이 C 폴더에 있다. 모델·실행 파일·표본과 변환 도구는 `D:/gait-research-data/D_P/note20-score-20261102`에 둔다. D 폴더를 유지해야 시작할 수 있다. 기존 연구 모델·최종 평가 파일과 다른 앱 작업본은 수정하지 않는다.

- `build_models.py`: 기존 54개 체크포인트를 ONNX로 변환하고 같은 표본의 기존 예측과 비교한다.
- `web/score.mjs`: 브라우저와 PC 검산이 함께 사용하는 실제 계산 경로다. 모델별 출력을 구간 평균한 뒤 고정 보정·결합식을 적용한다.
- `web/worker.mjs`: 계산을 별도 실행 영역에서 수행해 진행 화면이 멈추지 않도록 한다.
- `server.mjs`: 이번 실험의 파일만 읽어서 제공한다. 파일 업로드·점수 계산·결과 수집 기능은 없다. 준비 뒤의 실행 기록은 사용자가 저장하기 전까지 브라우저 안에만 있다.
- `export-verification.json`: 기존 PyTorch 예측과 ONNX CPU 예측의 비교다.
- `wasm-verification.json`: PC의 브라우저용 WASM 엔진과 같은 JavaScript 계산 코드로 표본 두 개를 재현한 결과다.
- `server-verification.json`: 화면·모델·실행 파일 제공과 지정하지 않은 요청의 차단 검사다.

재검산: `node verify_wasm.mjs`, `node verify_server.mjs`. 모델을 다시 변환할 때만 기존 연구용 Python과 `build_models.py`가 필요하다. 휴대폰 실험을 시작할 때 Python이나 재학습은 필요 없다.

기술 근거: [ONNX Runtime Web 공식 안내](https://onnxruntime.ai/docs/get-started/with-javascript/web.html). 기존 모델 구조·입력·보정식은 `../20261102-final223-frozen/models.json`과 `../20261101-self-video-gdi/predict.py`를 따른다.
