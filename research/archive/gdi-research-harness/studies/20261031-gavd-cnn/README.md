# GAVD 정상·이상 보행의 고정 다구간 CNN 실제 비교

2026-10-31 · 정상 후보 품질 검토, BODY25 추출, 기존 CNN 추론과 결과 검산 완료

후속으로 요청한 모델·촬영 조건·관절 오류의 분리 결과는 [원인 진단 기록](cause/README.md)에 있다. 개발 자료의 높은 GDI 과소예측과 같은 영상의 관절 재추출에 따른 점수 불안정성을 함께 확인했다. 아래는 최초 고정 비교 결과를 그대로 보존한 것이다.

**정상 영상도 약 71~76점으로 나오는 현상을 재현했다. 촬영 조건을 맞춘 두 쌍에서는 정상 점수가 각각 2.16점·1.95점 높았지만, 표본이 적고 모델별 방향도 일치하지 않아 안정적인 정상·비정상 구분을 확인했다고 말할 수 없다.**

모델이 답하는 질문은 입력된 2D 보행 좌표에 기존 학습 척도로 몇 점을 주는가다. GAVD에는 실제 GDI 정답이 없으므로, 이번에는 정상·비정상 라벨에 따라 점수 차이가 나는지만 살폈다. 정상 라벨에 임의로 100점을 붙이거나 오차를 계산하지 않았다.

## 실제 결과

다음 전체 평균은 촬영 조건이 섞인 **구간 단위 기술통계**다. 같은 사람의 반복 영상일 수 있어 참가자 수나 구분 성능으로 해석하지 않는다.

| 구분 | 구간 / 원영상 / 의존 묶음 | 평균 | 중앙값 | 범위 |
|---|---:|---:|---:|---:|
| 정상 | 7 / 6 / 5 | 73.13 | 72.35 | 70.99~75.81 |
| 비정상 | 18 / 18 / 16 | 70.40 | 71.01 | 59.50~78.02 |

의존 묶음은 원영상 ID를 기본으로 하되, 서로 다른 영상에 같은 배우로 보이는 대상이 나온 경우 보수적으로 합친 것이다. 확인된 사람 ID가 아니다. 전체 구간 평균 차이 2.74점에는 방향·촬영 환경 차이가 섞여 있다.

**점수를 보기 전에 정한 촬영 조건을 모두 만족한 비교는 2쌍이다.** 방향·실제 FPS·실내외·카메라 범주가 같고, 영상 높이와 대상자 bbox 높이 비율이 각각 0.5~2인 후보에서 크기가 가까운 순으로 선택했다. 나이·성별·속도·실제 진단은 맞추지 못했다.

| 비교 조건 | 정상 영상 → 점수 | 비정상 영상 → 점수 | 정상−비정상 |
|---|---|---|---:|
| 후면, 25 FPS, 실내·대체로 고정 카메라 | EHx08gSNfxQ → 72.35 | kA40kglSmYw → 70.19 | +2.16 |
| 정면, 29.97003 FPS, 실내·대체로 고정 카메라 | WpARylM4UYU → 70.99 | 05oyBOE_0UE → 69.04 | +1.95 |

두 쌍의 평균 차이는 **+2.06점**이다. 저장된 5개 CNN별 평균 차이는 각각 **+4.32, +2.58, +6.94, +0.21, −3.76점**으로, 한 모델에서는 비정상이 더 높았다. 두 쌍만 재추출한 탐색적 95% 구간은 1.95~2.16이지만, 관측한 두 차이가 비슷해서 좁게 나온 수치다. 이를 일반 모집단의 유의한 차이나 임상 구분 근거로 사용하지 않는다.

촬영 방향·FPS만 맞춰 더 넓게 비교한 결과도 일관되지 않았다. 아래 수는 같은 라벨·방향·FPS의 의존 묶음별 평균에 같은 가중치를 준 값이다. AUROC는 임의의 정상 점수가 비정상보다 높은 비율이며, 0.5는 순위 구분이 없는 수준이다.

| 방향·FPS | 정상 / 비정상 묶음 | 정상−비정상 | AUROC |
|---|---:|---:|---:|
| 후면·25 | 1 / 2 | +0.96 | 0.50 |
| 후면·30 | 1 / 5 | +3.76 | 0.80 |
| 정면·23.976 | 1 / 1 | −1.03 | 0.00 |
| 정면·29.97 | 1 / 3 | +4.20 | 0.67 |
| 정면·30 | 2 / 3 | +3.05 | 0.67 |

정면·30 FPS의 차이 95% 구간은 **−3.48~+9.21점**, AUROC 구간은 0~1이다(묶음 재추출 5,000회). 다른 행은 한쪽 묶음이 1개라 신뢰구간을 제시하지 않는다. 정상 측면 구간은 품질 검토에서 모두 제외되어 측면 구분을 평가하지 못했다. 29.97 묶음은 디코딩 FPS의 소수 셋째 자리 표시이며 30 FPS와 합치지 않았다.

원자료에서 병적 유형으로 주석된 6종만 남긴 추가 분석도 저장했다. FPS를 합친 탐색 결과의 차이는 후면 +1.44점(95% −0.19~3.64), 정면 +3.97점(−1.60~9.89)으로 모두 0을 포함한다. 이 라벨이 실제 진단을 보증하지는 않는다. 방향·정확한 FPS·유형별 원결과는 [comparison.json](runs/confidence_primary/comparison/comparison.json)에 있다.

## 표본 선정과 처리

`원영상·주석 확인 → BODY25 추출 → bbox 대상자 선택·관절/편집 검토 → 점수 전 목록 고정 → 기존 124프레임 전처리 → 저장된 CNN 5개 → 방향·FPS·촬영 조건별 비교`

- 취득 후보 정상 117구간·20영상에서 3시점 관절 검사를 거쳐 영상·방향당 최초 적격 구간을 골랐다. 연속 추출은 정상 22구간·14영상, 비정상 22구간·22영상이었다. 비정상은 다운로드한 44영상의 촬영 조건·라벨·보행 장면을 검토하고, 26영상 파일럿에서 같은 관절 기준을 적용했다.
- 정상 3,581프레임·비정상 5,814프레임을 추출했다. 이 수에는 1프레임 이동 확인용 여유 프레임이 포함된다. 점수 전 영상 8시점·관절 겹침 그림, 전 프레임 bbox 선택/결측 검사, 큰 관절 점프의 인접 3프레임 확대 검토를 수행했다.
- 정상은 편집·방향/촬영 조건 문제와 좌우 다리 교환·발목 오검출로 15구간, 비정상은 편집 2·다리 교환 2구간을 제외했다. 최종 7·18구간은 **이번에 처음 선정한 후보의 결과**이며, GAVD 전체에서 쓸 수 있는 수의 상한이 아니다. 작은 관절 점프나 검토한 시점 사이의 모든 해부학적 오류가 없다는 보증도 아니다.
- `primary_prescore_freeze.json`과 `shift1_prescore_freeze.json`에 표본·매칭 목록 지문을 저장했다. 점수에 따른 표본 교체·재학습·보정 변경·점수 자르기·시간 재표본화·자동 좌우 반전은 하지 않았다.
- 모델 입력은 좌우 각각 124프레임×12특징이다. 발목·무릎·엉덩이·엄지발가락 좌표와 기존 각도·거리 특징을 사용한다. 원래의 결측 25% 제한, 이동창, 학습된 보정식을 유지했다. 최종 주분석은 25기록·95창, 인접 1프레임 이동 분석은 23기록·90창이며 모두 5모델을 사용했다. 창과 모델을 독립 참가자로 세지 않았다.

## 확인한 오류와 처리 범위

기존 입력 검사에서 신뢰도 1 초과 때문에 정상 `WpARylM4UYU`, 비정상 `kA40kglSmYw`가 거부됐다. 각각 실제 프레임을 공식 OpenPose CPU로 다시 처리해 **1.002261·1.022008**이 나오는 것을 확인했다. 원래 신뢰도 상한과 공식 출력이 충돌한 사례다. 기존 실행은 정상 6·비정상 17구간 결과로 보존했다.

사용자가 **「별도 어댑터로 2쌍 비교 진행」**을 승인한 뒤, [prepare_official_confidence.py](prepare_official_confidence.py)에서 해당 두 구간의 상한 검사만 예외 처리했다. 원본 신뢰도 값도 잘라내지 않고 유지했다. 다른 구간의 입력 검사, 좌표·모델·보정·결측 기준은 그대로다. 기존 bundle 파일을 수정하지 않았다. 이 문서의 최종 수치는 승인된 예외 실행이며, 이전 실행과 혼동하지 않는다.

검산 결과는 다음과 같다.

- 전체 연속 추출 JSON **9,395개**의 저장 SHA256 일치. 원격 열지도 청크도 회수 시 SHA256을 대조했다.
- 공식 CPU/GPU 입력 blob 3종 크기에서 동일, 열지도 최대 차이 약 1.61×10⁻⁶로 기존 10⁻⁴ 기준 통과.
- **별도 엄격 좌표 동일성 검사는 실패 상태를 보존했다.** 최초 3이미지에서 좌표 최대 차이 0.0001221픽셀, 4-ULP 기준 2/3 실패다. 후속 신뢰도 오류 재현 프레임에서도 좌표 차이 최대 0.0001526픽셀이 있었다. 공식 후처리를 사용했지만 출력이 비트 단위로 같다고 주장하지 않는다.
- 기존 bundle **684파일 지문 불변**, 예외 전 통과했던 모든 기록의 CNN 입력 특징은 비트 단위 동일. 재추론 점수 차이는 주분석 최대 2.20×10⁻⁶점, 이동 분석 최대 3.82×10⁻⁶점으로 기존 재현 검사 허용오차 10⁻⁴점 안이었다.
- 좌우·창·5모델 평균을 원 CSV에서 다시 계산했다. 집계 최대 오차 2.85×10⁻¹⁴점, 저장 보정식 대입 오차 0. AUROC는 별도 Mann–Whitney 순위 계산과 대조했다. 원본 FPS·124프레임 경계·결측 제한과 사전 매칭 조건도 검산했다.
- GAVD 주석의 0/1 프레임 시작 규칙은 확정하지 못했다. 인접 1프레임 이동에서 공통 23기록의 점수 변화는 평균 절댓값 **0.081점**, 최대 **0.264점**이었다. 이는 이번 입력의 작은 이동 민감도이며 원 주석 이력을 확정한 것은 아니다. 뒤 여유 프레임이 없는 2기록은 이동 분석에서만 빠졌다.

따라서 정상의 낮은 점수 현상은 이번 공개 영상에서도 확인되지만, 원인을 모델의 점수 압축·학습 자료와 촬영 조건 차이·남은 관절 오류 중 하나로 확정할 수 없다. 이 결과는 임상 GDI 정확도, 진단 또는 일반인 정상 판정 성능의 검증이 아니다.

## 결과 위치와 재현

- 최종 수치·기록별 점수·2쌍 결과·그림: [results/official_confidence](results/official_confidence/actual_results.json). 검산은 같은 폴더의 `actual_verification.json`, `exception_verification.json`에 있다.
- 원래 검사 기준의 결과: `results/actual_results.json`, `runs/primary/comparison/`. 승인 예외 실행: `runs/confidence_primary/comparison/`.
- 영상·BODY25 JSON·입력/예측 배열·수신 묶음: `D:/gait-research-data/D_P/datasets/GAVD`. 최종 배열은 `runs/confidence_primary`, 이동 분석은 `runs/confidence_shift1` 아래에 있다.
- 실행은 `run_reviewed.ps1`로 원래 결과를 만든 뒤, 승인한 `run_confidence_exception.ps1 -BaseRun primary` 및 `-BaseRun shift1`을 수행했다. 원 bundle의 `prepare.py`/`infer.py`를 사용하며, 승인 예외 어댑터가 지정한 검사 한 곳만 분리한다.
- 통계·검산 명령은 `analyze_actual.py`, `verify_actual.py`에 `--primary-run confidence_primary --sensitivity-run confidence_shift1 --out results/official_confidence`를 주고, 이어 `verify_confidence_exception.py`를 실행한다. 코드 환경은 기존 Python 3.12/CNN 의존성, 공식 OpenPose 후처리는 기존 Python 3.7 환경이다. 새 모델 학습은 없었다.

전체 주석은 458,116행·1,874구간이며 원영상 ID는 348개다. 구간 내 프레임 번호의 누락·중복은 없었다. 11구간은 촬영 방향 주석이 구간 안에서 바뀌므로 이번 보수적 후보 목록에서 보류했다. 긴 연속 부분만 골라 재포함하지 않았다.

**라벨 불일치:** `gait_pat=normal`은 291구간이지만 그중 37구간·5영상은 `dataset=Abnormal Gait`다. 논문의 정상 291구간과 CSV의 이진 라벨 정상 254구간이 달라지는 이유다. 어느 열이 정답인지 임의로 결정하지 않고 `annotation_review.csv`에 보류했다. 이 파일에는 방향이 바뀌는 구간도 포함한다. 원자료는 수정하지 않았다.

길이 후보에 해당하는 317영상 모두 oEmbed를 조회했다. 302개 성공, 15개 HTTP 오류(401: 7, 404: 5, 403: 3)였다. 성공한 302개에서 추가로 스트림 정보를 조회해 289개에서 형식 목록을 받았고 13개는 실패했다. 이것은 당시 이 환경의 접근 결과이며, HTTP 오류만으로 영구 삭제를 단정하지 않는다. 이 중 라벨·촬영 방향 조건까지 통과한 영상이 위 표의 286개다. 로그인·쿠키·접근 제한 우회는 사용하지 않았다.

| 촬영 방향 | 정상: 구간 / 원영상 | 이상: 구간 / 원영상 |
|---|---:|---:|
| 왼쪽 측면 | 28 / 7 | 237 / 115 |
| 오른쪽 측면 | 29 / 7 | 268 / 130 |
| 정면 | 35 / 12 | 286 / 135 |
| 후면 | 25 / 8 | 173 / 86 |

같은 원영상이 여러 방향에 있으므로 영상 수를 행끼리 더하면 안 된다. 측면 합계의 중복 제거 원영상은 **정상 9개·이상 161개**다. 구간은 각각 57개·505개다. 특히 정상 원영상이 적다. 영상 ID는 사람 ID가 아니며, 한 영상의 여러 사람이나 서로 다른 영상에 나온 동일인은 아직 확인하지 않았다.

병적 보행으로 주석된 6유형(`parkinsons`, `cerebral palsy`, `myopathic`, `antalgic`, `stroke`, `prosthetic`)만 보면 이상 후보는 316구간·79영상이다. 이는 확정 진단이 아니라 원자료의 관찰 라벨이다. 전체 이상에는 운동·과장된 걸음·원인 미상 등이 섞여 있으므로 두 비교를 분리하도록 준비했다.

## 실제 영상 접근 확인

점수를 보지 않고 후보 목록에서 각 라벨의 첫 구간에 해당하는 영상을 골랐다. 두 영상만 다운로드했으며 전체 영상 다운로드를 완료한 것은 아니다.

| 구분 | 영상 ID | 실제 디코딩 정보 | 확인 범위 |
|---|---|---|---|
| 정상 | `diCVwltkV5M` | 320×240, 15 FPS, 전체 2,293프레임 | 주석 시작 번호를 임시 읽기 위치로 사용해 124프레임 읽힘 |
| 이상 | `B5hrxKe2nP8` | 1280×720, 30 FPS, 전체 6,176프레임 | 같은 방식으로 124프레임 읽힘 |

두 파일은 약 11.1MB다. **디코딩 성공은 주석과 프레임의 정확한 대응·정상/이상 라벨·대상자·발끝 검출을 확인했다는 뜻이 아니다.** 정상 샘플은 15 FPS라 124프레임의 실제 시간이 30 FPS 자료의 두 배다. 해상도도 다르다. 이 두 샘플을 그대로 넣어 차이를 보행 효과라고 해석하지 않는다. `media_sample_checks.json`에 실제 파일 정보와 지문을 남겼다.

## 준비한 실험 흐름

`원영상·주석 대응 확인 → BODY25 좌표 추출·대상자 선택 → 기존 124프레임 전처리 → 고정된 CNN 5개 → 촬영 방향·FPS별 점수 비교`

- 기존 `outputs/team-share-gdi-normal-cnn-20261031-v2/bundle`을 그대로 호출한다. 학습·보정 재학습·점수 자르기·FPS 재표본화·자동 좌우 반전은 하지 않는다. 모델 명세 지문은 `experiment_config.json`에 있다.
- 정상·이상 라벨은 CNN 입력과 분리한다. 정상이라는 이유로 GDI 100점을 정답으로 붙이지 않는다.
- 기록별 구간 평균·기존 보정 결과에서 좌우와 5모델을 평균한 참고 점수를 비교한다. 모델별 결과도 따로 계산한다. 5모델 평균은 기존 교차검증 성능의 추정량과 같지 않다.
- 같은 촬영 방향 안에서 비교하며 실제 디코딩 FPS가 같은 자료의 결과를 별도로 낸다. FPS를 모두 합친 결과는 탐색용으로 표시한다. 30 FPS와 29.97 FPS도 자동으로 하나로 합치지 않는다.
- 확인된 동일인이 있으면 같은 사람 묶음으로, 없으면 원영상 묶음으로 집계한다. 구간·좌우·모델 5개를 독립된 사람처럼 세지 않는다. 입력 계약의 `person_id`에 `video:ID`가 들어가는 경우는 기술상 묶음 ID이며 참가자 수가 아니다.
- 정상−이상 평균 차이, 중앙값, 정상에 더 높은 점수를 주는 방향의 AUROC를 계산한다. AUROC 0.5는 순위 구분이 없는 수준, 1은 모든 정상 점수가 이상보다 높은 경우다. 방향을 결과에 맞춰 뒤집지 않는다.
- 2,000회 묶음 단위 재추출로 탐색적 95% 구간을 구한다. 같은 묶음이 양쪽 라벨에 있으면 함께 재추출한다. 작은 정상 표본, 영상 간 동일인 미확인, 여러 방향·유형 비교의 영향이 남는다. 임상 성공 기준이나 정상 판정 점수 문턱을 새로 정하지 않았다.

## 실행 준비물과 남은 작업

`review_template.csv`에는 후보 1,081구간의 출처·라벨·촬영 방향·원본 프레임 범위·예정 BODY25 경로가 있다. 실제 확인값은 이 파일을 별도 `reviewed.csv`로 복사해 기록한다. `inventory` 명령은 템플릿을 다시 만들지만 별도 검토 파일은 덮어쓰지 않는다.

남은 작업은 후보 원영상 확보, 원영상 프레임과 주석의 대응 및 해상도 변환 확인, BODY25 추출, 사람 선택, 해부학적 좌우·직선 보행·시야 확인이다. 현재 이 단계를 자동으로 완료하는 새 영상→BODY25 프로그램을 만들거나 전체 좌표 추출을 실행한 것은 아니다. 기존 로컬 OpenPose CPU 실행본과 별도 연구의 GPU 추출 구현은 존재하지만 이번 준비에서 GPU 제출·예약·기존 작업 변경은 하지 않았다.

BODY25 파일은 `D:/gait-research-data/D_P/datasets/GAVD/body25/<seq>/`에 둔다. JSON 파일명 `..._<주석 프레임 번호>_keypoints.json`은 원 주석 번호를 유지한다. 검출이 없는 프레임도 `people: []`로 남기며 앞 최대 1,499프레임을 쓴다. 모든 파일의 대상자 선택을 `selection.csv`의 `filename,person_index`로 명시한다. `-1`은 대상자 없음이며, 사람 배열의 첫 항목을 무조건 대상자로 쓰지 않는다. 프레임 시작이 0인지 1인지, 영상이 편집됐는지, 주석 bbox를 현재 영상 크기로 어떻게 대응시켰는지를 먼저 확인해야 한다.

## 확인한 검증

- 실제 CSV 458,116행을 SQLite로 독립 재집계했다. 1,874구간·348영상·라벨 불일치 37구간, 프레임 경계·누락·중복·방향 변동을 대조했다.
- 가상 입력으로 AUROC 방향과 동점, 끊긴 프레임을 이어 붙이지 않는 처리, 같은 묶음의 두 라벨 재추출, 반복 구간 수에 따른 가짜 표본 증가 방지, 5모델 예측 누락·중복·NaN 거부, 미검토 자료의 실행 차단을 검사했다. 이는 GAVD 정확도 시험이 아니다.
- 기존 공개 개발 샘플 JSON 650개→12구간을 재처리했다. 특징 최대 차이 0.0, 5모델 예측 최대 차이 0.0으로 기존 허용치(각각 1e-6, 1e-4) 안이었다. 이 샘플은 정상인 검증 자료가 아니다.
- 확인되지 않은 실제 GAVD BODY25 입력으로 전체 실행이 성공한다고 주장하지 않는다. 준비 코드 검사와 실제 영상·임상 검증을 구분한다.

재집계는 `audit_gavd.py audit`, 접근 확인은 `audit_gavd.py probe`와 `probe_streams.py`, 후보 갱신은 `prepare_comparison.py inventory`, 검산은 `verify_preparation.py`를 사용한다. 모두 이 폴더의 파일이다. Python 표준 라이브러리로 주석을 처리하고 NumPy로 점수를 비교한다. 스트림 조회용 `yt-dlp 2026.10.26`만 `D_P/tmp/gavd-python-deps`에 추가했다. 실제 영상 디코딩은 기존 `tmp/pose-python37`의 OpenCV, CNN은 기존 CPU PyTorch·NumPy·SciPy 환경을 재사용했다.

검사 중 샌드박스 임시 폴더 정리 권한 오류가 있어, 미검토 명세 거부 검사는 실제 임시 폴더를 만들지 않는 방식으로 수정했다. 판정 기준을 완화하지 않았다. 검증 결과는 `verification.json`, 기존 CNN 재현은 `frozen_sample_verification.json`에 있다.
