# CNN·STT 입력별 결합 비교와 Mamba 사용 가능성 확인

작성일: 2026-11-01. 기존 개발 자료 692명·1,061기록을 사용한 탐색 실험이다. 독립된 새 자료의 성능이나 임상 성능을 확인한 결과는 아니다.

**결론.** 이번의 작은 입력별 게이트를 새 기본 방법으로 채택할 근거는 부족하다. 같은 예측·사람 분할에서 고정 결합보다 전체 오차가 0.007점 줄었지만, 고득점의 과소예측은 줄지 않았다. Mamba는 실제 입력 형태의 CPU 연산 확인을 통과했다. 공식 패키지 설치와 GPU 가속 경로, GDI 예측 성능은 아직 확인하지 않았다.

**무엇을 확인했는가.** 게이트는 ‘이 기록에서는 CNN과 STT 중 누구의 예측을 더 믿을 것인가’를 정하는 작은 계산식이다. 기존 두 모델을 다시 학습하지 않고, 저장된 예측만 사용했다. 두 모델의 예측 수준·서로 다른 정도·좌우 차이·짧은 구간 사이의 예측 흔들림·구간 수 등 12개 값을 입력했다. 좌표의 추적 품질을 직접 넣은 실험은 아니다. 예측 흔들림을 실제 측정 불확실성으로 검증한 것도 아니다.

먼저 정답을 안다고 가정하고 기록마다 최선의 결합 비율을 고르는 진단을 했다. 같은 내부 자료의 고정 결합보다 평균 1.103점 줄일 여지가 있었다. 이는 정답을 몰라도 고르는 법을 배울 수 있다는 증거가 아니라, 두 예측을 섞는 범위 안에 개선 여지가 있는지를 보는 참고 상한이다. 미리 정한 0.1점 기준을 넘어 실제 학습 비교를 진행했다.

**비교가 공정하도록 한 선택.** 기존의 사람별 5분할을 유지했다. 각 평가 묶음마다, CNN·STT 학습에서 빠져 있던 사람들로만 게이트를 학습했다. 이 사람들을 다시 60% 학습·20% 방법 선택·20% 내부 점검으로 나눴다. 같은 모델이 이미 학습한 사람의 예측을 게이트 학습에 섞지 않기 위해, 내부 모델별로 별도 게이트를 만들었다. 총 20개 CNN·STT 쌍을 사용했다.

한 개 비율을 양쪽 다리에 함께 쓰는 방법과, 양쪽 평균용 비율·좌우 차이용 비율을 따로 정하는 방법을 비교했다. 지나치게 복잡하게 맞추지 않도록 계산식의 계수 크기를 제한했고, 그 제한 정도는 내부 선택 자료에서만 골랐다. 고정 결합이 더 좋으면 고정 결합을 선택할 수 있게 했다. 20개 경로에서 공통 비율 8개, 평균·차이 분리 7개, 고정 결합 5개가 선택됐다.

선택을 고정한 뒤 내부 자료 전체로 다시 학습하고, 전혀 다른 평가 사람에게 적용했다. 각 평가 묶음에서 4개 경로를 평균했다. 고정 결합도 **동일한 원래 모델·보정·평균 경로**를 사용했다. 이전에 보고한 고정 결합 6.687점과 새 게이트를 바로 비교하면, 경로 평균의 효과까지 게이트 효과로 오해할 수 있다.

**결과.** 모든 오차는 작을수록 좋다. 기록이 많은 사람의 영향이 커지지 않도록 먼저 사람별로 평균한 뒤 전체를 평균했다. 고득점은 실제 좌우·기록 평균 GDI가 90 이상인 68명으로, 평가할 때만 구분했다.

| 방법 | 전체 절대오차 | 고득점 절대오차 | 고득점 과소예측량 | 좌우 차이 오차 |
|---|---:|---:|---:|---:|
| 같은 경로의 고정 결합 | 6.5496 | 8.7451 | 8.2953 | 6.4839 |
| 공통 비율 게이트 | 6.5489 | 8.7762 | 8.3200 | 6.4679 |
| 평균·차이 분리 게이트 | 6.5458 | 8.7933 | 8.3372 | 6.4646 |
| 내부 자료에서 선택한 방법 | 6.5423 | 8.7875 | 8.3312 | 6.4647 |
| 이전 최고 방법: 참고 비교 | 6.5158 | 8.7825 | 8.3488 | 6.3057 |

절대오차는 예측과 실제 점수가 벌어진 거리다. 과소예측량은 실제보다 낮게 예측한 부분만 세고, 높게 예측한 경우는 0으로 세므로 서로 상쇄되지 않는다. 좌우 차이 오차는 ‘예측한 왼쪽−오른쪽’과 ‘실제 왼쪽−오른쪽’이 벌어진 거리다. 이는 차이의 크기뿐 아니라 방향까지 평가한다. 고득점의 단순 편향, 즉 예측−실제의 평균도 고정 결합 −7.8455점에서 선택 방법 −7.8750점으로 낮아졌다.

선택 방법의 전체 오차 차이는 −0.0074점이다. 사람을 다시 뽑아 5,000번 비교했을 때 차이의 95% 참고 범위는 −0.0225~+0.0077점으로, 개선과 악화 양쪽을 포함했다. 5개 평가 묶음 중 3개에서 줄고 2개에서 늘었다. 좌우 차이 오차는 0.0191점 줄었고 그 참고 범위는 −0.0357~−0.0022점이었다. 다만 여러 항목을 함께 본 개발 자료의 탐색 결과이며, 차이 자체도 작다. 고득점 절대오차는 0.0424점, 과소예측량은 0.0359점 늘었다. 이전 최고 방법의 전체 오차와 좌우 차이 오차도 넘지 못했다.

방법 선택에 사용하지 않은 내부 점검에서도 고정 결합 약 6.87점에 비해 선택 방법 약 6.90점으로 개선되지 않았다. 이는 20개 경로의 점검 결과를 모은 요약이며, 같은 사람이 여러 경로에 반복될 수 있으므로 580명의 독립 평가로 해석하면 안 된다.

**이 결과로 무엇을 결정할 수 있는가.** 저장된 예측 요약만으로 비중을 바꾸는 이번 방법은 우선순위가 낮다. 더 복잡한 모든 게이트의 가능성이 없다고 결론 낼 수는 없다. 특히 두 모델이 모두 낮게 예측한 사례에서는, 두 예측 사이를 섞는 방식만으로 그 범위를 넘어 정답까지 올릴 수 없다는 구조적 제약이 있다. 다음 비교를 한다면 실제 좌표 품질 정보가 추가될 때 도움이 되는지, 또는 고득점에서 두 모델이 함께 틀리는 원인을 먼저 분해하는 편이 타당하다. 이 후속 비교는 이번에 실행하지 않았다.

**Mamba는 어디까지 가능한가.** Mamba는 시간 순서대로 들어오는 정보를 작은 내부 상태에 이어 담으며 처리하는 모델이다. 공식 v2.2.4의 Mamba-1 클래스와 공식 기본 연산 함수(selective_scan_ref)를 사용했다. GPU 전용 패키지 불러오기를 우회하고 기본 연산을 연결했으므로, 정식 설치 성공과 구분해야 한다.

실제 학습 쪽 사람의 데이터에서 좌우 2개×124프레임×8개 좌표 값을 사용했고, 시간 순서의 짧은 구간 묶음 10~12개도 입력했다. 후자는 현재 구간별 단순 요약값으로 형태를 확인한 것이며, CNN·STT가 뽑은 중간 특징을 학습한 결과가 아니다. 예측 방향 계산·학습을 위한 변화량 계산·3회 수치 갱신·한 시점씩 처리한 결과와 전체 처리 결과의 일치·저장 후 재실행을 확인했다. 기본 연산을 별도로 구현한 계산과 비교했을 때 출력 최대 차이는 9.54×10⁻⁷, 학습 변화량 최대 차이는 4.77×10⁻⁷이었다. 저장 후 출력 차이는 0이었다. 이 갱신에는 GDI 정답을 쓰지 않았으므로 GDI 학습이나 성능 개선을 주장할 수 없다.

시험한 블록은 조정 가능한 숫자 2,592개인 작은 구조다. 기존 CNN·STT 뒤에 시간 순서 처리기를 붙이는 구현은 가능하다고 판단한다. 다만 기존 입력은 124프레임이고 기록당 구간 수도 약 10개인 사례를 확인했으므로, 긴 시퀀스에서의 장점이 이 연구에서도 크게 나타난다고 단정할 수 없다. 원래 구간별 CNN·STT 특징을 보존해 평균 결합과 비교하는 별도 학습이 있어야 유용성을 판단할 수 있다.

시험한 v2.2.4의 공식 안내는 Linux·NVIDIA GPU·PyTorch 1.12 이상·CUDA 11.6 이상이며, 설치 코드의 Python 조건은 3.9 이상이다. 현재 확인한 로컬 환경은 Windows·Python 3.12·CPU용 PyTorch 2.14.1이며 GPU 가속 사용 불가다. 서버의 현재 Python·PyTorch·CUDA 조합, 공식 패키지 설치와 GPU에서의 학습 한 회 속도는 확인하지 않았다. 패키지를 새로 설치하거나 GPU 작업을 제출하지 않았다. 출처: [공식 v2.2.4 안내](https://github.com/state-spaces/mamba/tree/v2.2.4), [해당 버전 설치 코드](https://github.com/state-spaces/mamba/blob/v2.2.4/setup.py).

**GPU와 소요 시간.** 게이트 학습은 CPU 실측 약 3.25초, 결과 비교·사람 재추출 계산은 약 2.61초였다. 별도 검산은 실행에 따라 약 3~6초였다. 이 수치는 Python 시작 시간·자료 조사·실험 코드 작성 시간을 제외한 내부 측정이다. 이 정도 작은 계산은 GPU 준비·자료 이동이 더 큰 비중을 차지할 수 있으므로 GPU 전환의 실익이 작다. 파일 출처 확인과 사람 분할 검산도 주로 CPU·파일 읽기 작업이다. 처음 제시한 수십 분은 이러한 준비와 확인을 포함한 예상이지 순수 학습 시간은 아니었다.

Mamba CPU 기본 연산의 계산 확인은 약 12.85초였다. 작은 블록, 한 묶음 8개 입력의 출력·학습 변화량 계산은 길이 12에서 약 0.013초, 124에서 0.150초, 500에서 0.933초였다. 이는 GPU 속도나 전체 학습 시간의 추정치가 아니다. Mamba 본학습은 GPU 가속으로 단축할 여지가 있지만, 준비된 실제 GPU 환경에서 속도를 재기 전에는 몇 배 빨라지는지나 전체 완료 시간을 확정할 수 없다.

**재현과 검산.** `study.py train` → `study.py evaluate` → `verify.py` 순서로 실행한다. 현재 기본 Python에 과학 계산 패키지를 새로 설치하지 않고, 기존 연구 폴더의 SciPy를 사용한다. `mamba_check.py acquire`는 출처를 고정한 공식 공개 파일만 별도 폴더에 받으며, `mamba_check.py check`가 CPU 계산을 확인한다. 실행에는 기존 연구 데이터와 환경 경로가 필요하다.

검산에서는 20개 경로의 학습·선택·평가 사람 분리, 원자료·모델·예측 파일 해시, 160회 선택·최종 재학습과 40회 내부 점검 재학습, 독립 계산으로 예측·평가지표 재현을 확인했다. 평가 정답을 바꿔 넣어도 예측이 바뀌지 않는지, 좌우를 바꾸면 출력도 같은 방식으로 바뀌는지, 사람별 가중치가 유지되는지도 확인했다. 모든 검산이 통과했다. 이전에 여러 실험을 한 개발 자료를 재사용했으므로, 이번 수치만으로 새 사람 집단에서의 개선을 확정할 수 없다. 별도 최종 평가 자료는 열지 않았다.

구현 중 기존 CNN 체크포인트와 신원 기록 파일이 같은 폴더에 있다고 가정한 경로 오류가 있어, 기존 출처 증명에 기록된 파일 경로를 사용하도록 고쳤다. 공식 코드 다운로드는 제한된 네트워크에서 DNS 조회에 실패한 뒤 허용된 외부 접속으로 완료했다. 이들은 실행 준비 중의 문제이며 학습 결과를 선택하거나 제외한 이유가 아니다.

작은 코드·요약·검산·예측 산출물은 이 폴더에 저장했다. 기존 대량 예측·모델·데이터는 원래 저장 위치에서 읽었으며 바꾸지 않았다. 상세 수치는 `analysis/comparison.json`, 게이트 검산은 `analysis/verification.json`, Mamba 확인은 `analysis/mamba-feasibility.json`에 있다.
