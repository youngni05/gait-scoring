# 원 공개 CNN 입력·처리에 가까운 한 구간 비교

기존 CNN8.683점과 원 논문의6.5점 사이에 있는 입력·전처리·좌우 처리 차이를 확인하려 한다. 먼저 **원 연구의12개 특징을 기존과 같은124프레임에서 추출하고, 좌우를 같은 CNN으로 따로 예측한 뒤 학습자료에서 구한 선형 보정식을 적용**하는 실행 묶음을 준비했다.

현재는 원자료 준비·코드·로컬 검사 완료 상태다. 실제 GDI 자료로 새 CNN을 학습하거나 GPU에서 실행하지 않았다. 여러 구간 학습은 다음 단계이며 이번 묶음에는 없다.

## 확인한 원 구현과 선택한 처리

원 코드 commit은 `4167ee6213ac81fb9168f4e20c6538d42a41a5a6`이다. [공개 training 코드](https://github.com/stanfordnmbl/mobile-gaitlab/tree/4167ee6213ac81fb9168f4e20c6538d42a41a5a6/training), [원 논문 Methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC7426855/)를 대조했다. 실제 파일11개·URL·지문·Apache2.0 라이선스는 `sources/`에 보관했다. 처리된 좌표는 제공자의 CC BY-NC2.0 조건과 구분한다.

| 과정 | 원 공개 코드에서 확인한 처리 | 이번 구현 |
|---|---|---|
| GDI 연결 | 환자·검사·좌우로 GDI 연결 | 기존 검산된 좌우GDI를 그대로 사용. 다른 목표값을 학습하지 않음 |
| 사람 선택 | 화면 왼쪽 절반의 사람, x최댓값<320 | 기존 연구와 같이 유일한 사람만 사용. 여러 명이면 결측으로 유지 |
| 원 프레임 변환 | frame1~1499, 첫 JSON 누락에서 중단 | 동일한 범위를 적용하고 선택124프레임이 포함되는지 확인 |
| 결측·평활화 | x/y의0·NaN을 결측으로 보고 선형 보간, 끝부분 평균 채움, Gaussian sigma1 | 원 함수 본문을 사용. NumPy2에서 없어진 `np.NaN` 표기만 `np.nan`으로 변경 |
| 정규화 | 골반 중심, 양쪽 허벅지 길이 평균으로 나눔 | 동일하게 계산. 기존 MotionBERT의 경계 상자 정규화와 다름 |
| 방향 | 공개 doublesided 경로는 `swap_orientation=False` | 그 경로를 따름. 논문 설명의 방향 정렬을 별도로 추정해 추가하지 않음 |
| 특징 | 발목·무릎·엉덩이·엄지발끝 x/y8개 + 각도2개 + 거리2개 | 좌우 각각12개, 순서 동일 |
| 구간 결측 검사 | 필수8관절 x/y 각 채널 중 최대 결측률≤25% | 선택된 같은124프레임에 적용 |
| 좌우 학습 | 좌우를 별도 예제로 쌓아 같은 네트워크에 입력 | 좌우 예제를 함께 섞어 배치32로 학습. 같은 사람의 좌우는 분할을 넘지 않음 |
| 출력·손실 | 출력2칸 중 첫 칸만 GDI 손실에 반영 | 구조 유지, 두 번째 칸 손실가중치0. 좌우GDI 동시 출력 모델과 구분 |
| 예측 보정 | 학습 예측→실제값 OLS, 좌우를 합친 기울기·절편 | 매epoch 해당 학습 사람만으로 구하고 내부 검증에 적용. 보정 전후 모두 저장 |
| epoch 선택 | 공개 보정 노트북은 검증RMSE | 현재 비교 규칙인 사람MAE로 선택. 원 논문과의 차이로 명시 |

12개 특징 순서는 발목x/y, 무릎x/y, 엉덩이x/y, 엄지발끝x/y, 발목–무릎–엉덩이 각도, 발끝–발목–무릎 각도, 발끝–발목 거리, 반대쪽 발목x−해당 발목x다. 각도는라디안, 좌표·거리는 허벅지 길이로 정규화된 값이다. 신뢰도는 CNN 특징으로 넣지 않는다.

공개 노트북은 기본목표가 무릎각도이고, GDI의 파일명·좌우 열 연결이 완결된 일괄 실행본은 아니다. 또한 원 프레임 변환기의 중복 사람 카운터 위치 때문에 여러 후보가 있으면 마지막 사람 값으로 덮어쓸 수 있다. 이번 구현은 기존 프로젝트의 유일한 사람 조건을 유지해 해당 프레임을 결측으로 둔다. 영상 전체에서 그런 프레임26,994개가 있었지만, 유지된 선택124프레임 구간 안에서는0개였다.

여러 구간에 가중치를 주는 공개 손실 코드에는 배열 차원에 따른 broadcasting을 따로 검토할 부분이 있다. 이번에는 기록당 한 구간이므로 구간 가중치가 모두1이며, 첫 출력의 표준 평균제곱오차와 동등한 계산을 사용한다. 여러 구간 실험을 시작하기 전에 그 가중치 계산을 별도로 검증한다.

## 준비된 사람과 비교 범위

원래695명·1,064기록을 검사해 **692명·1,061기록**을 준비했다.

- 기존175명 중174명·202기록, 추가520명 중518명·859기록이다.
- 1기록은 공개 변환기가 시작하는frame1이 없어 처리 길이가0이 되었고, 기존 선택 구간을 포함할 수 없었다.
- 2기록은 발끝을 포함한 필수 좌표의 최대 결측률이30.65%,31.45%로25% 기준을 넘었다.
- 기존 fold 번호를 그대로 유지했다. 평가 사람은fold별138·138·138·139·139명이다. 새로 분할하지 않았다.
- `data.npz`는 `[1061기록,2좌우,124시간,12특징]`, 정답은 `[1061,2]`다. `original_row_index`로 기존1,064기록과 연결한다.
- 각 기록의124프레임 ID는 이전 입력과 동일하다. 보간·평활화는 **원 변환 범위의 전체 영상에서 먼저 계산**하므로, 선택 구간 바깥 프레임도 전처리에 영향을 줄 수 있다. 정보 사용량이 완전히 동일한 ‘특징만 변경’ 실험은 아니다.
- 기존37/38명·최종예약223명의 숫자 정답은 읽거나 묶음에 넣지 않았다.

기존 결과를 같은692명·1,061기록만 뽑아 다시 집계했다.

| 비교 방법 | 공통 평가자료 MAE |
|---|---:|
| MotionBERT+PLS | 7.986987 |
| MotionBERT 마지막 단계 부분학습 | 8.369198 |
| MotionBERT+Ridge | 8.541777 |
| 이전51채널 CNN | 8.694405 |

이 값들은 **기존 예측의 재집계**이며 기존 모델을692명 조건으로 다시 학습한 값은 아니다. 기존 모델의 학습자료에는 이번에 제외된 사람이 일부 들어 있었을 수 있다. 같은 평가대상 비교는 가능하지만 학습집단까지 완전히 일치한 비교나 입력 변경만의 인과 효과로 표현하지 않는다.

원 연구식 여러 구간 후보는 유지된 기록에서11,257개를 찾았다. 이 중4기록은 처음500프레임 안에 유효한 슬라이딩 구간이 없지만 기존 선택124프레임은 유효했다. 이번 묶음에는 여러 구간 학습을 넣지 않았고, 다음 단계에서 구간 수 가중치·공통집단을 별도로 맞춘다.

## 학습과 평가

모델은 공개6개 Conv1D 구조와 출력2칸을 유지한47,840파라미터 모델이다. RMSprop0.001,10epoch마다학습률×0.8,Dropout0.5,마지막4개Conv kernel L2=10^-3.5,최대100epoch다. 배치32는 좌우를 분리한 예제32개이며 이전 CNN의 기록32개와 다르다. 좌우를 합친 **현재 학습 집단의** GDI 최솟값·범위로 정답을 변환한다.

각 바깥 평가 fold를 남기고 나머지4개를 내부 검증에 사용한다. 내부 검증 사람이 조금씩 다르므로 사람 수로 가중한 평균MAE로epoch를 선택한다. 선택 후 바깥 학습 사람 전체로 새로 학습한다. 내부20개+바깥 재학습5개, 총25개 모델이다.

주 결과는 **학습자료로 맞춘 선형 보정 후 예측**으로 미리 정했다. 보정 전 결과도 진단용으로 저장하지만, 바깥 평가 오차를 보고 둘 중 좋은 쪽을 골라 주 결과로 삼지 않는다. 보정은 정확도를 보장하지 않는다. 새로운 데이터에 적용할 때도 학습에서 저장한 기울기·절편만 사용한다.

원 논문 사람 분할·자료 전체·여러 구간·RMSE선택·Keras 실행환경까지 맞춘 것은 아니다. 이번 실험명은 ‘원 공개 입력·처리를 적용한 같은124프레임 CNN 비교’로 유지한다. 원 논문의6.5점을 재현했다고 주장할 수 있는 실험은 아직 아니다.

## 로컬 검증

실제 입력은 원자료 CRC·원 입력 지문·동일 124프레임·각도/거리의 독립 기하 계산·결측 기준·사람 분할을 검사했다. 가상 좌표·가상 GDI로 25개 학습 흐름, 학습자료만 사용하는 보정, epoch 선택의 사람 수 가중, 저장·재개와 보정 전후 재추론을 검사했다. 검증 정답을 9999로 바꾸어도 학습 가중치·보정 계수는 변하지 않는지 확인했다. Python 3.8 문법·ZIP 내용 검사는 별도이며 서버 PyTorch 2.4와 CUDA는 파일럿에서 확인한다.

원자료 준비에는 로컬 SciPy를 사용했고 서버 학습은 기존 NumPy·PyTorch만 필요하다. TensorFlow나 새 패키지의 서버 설치는 포함하지 않는다.
