## 맞춘 조건과 유지한 차이

692명·1,061기록·11,261구간의 좌표, 구간 시작 위치, 구간과 기록의 대응, 사람 ID, 영상 ID, 정답, 바깥 분할을 CNN과 대조한다. CNN 구간의 앞8개 좌표를 같은 순서로 가져와 `[구간, 좌우, 124프레임, 4관절, xy]`로 바꾼다. 각도·거리4개 특징은 STT에 넣지 않는다. CNN에서 유효한 앞부분 구간을 얻지 못해 기존 단일 구간을 사용한4기록도 그대로 유지한다. 원 연구 전체 자료·분할을 복원한 실험은 아니다.

구간별 오차는 학습 기록의 구간 수 역수로 가중한다. 기록 안에서 각 구간의 비중을 같게 하고, 많은 구간을 가진 기록이 학습 손실을 과도하게 차지하지 않도록 하는 CNN의 구현을 사용한다. 예측은 구간별 좌우 점수를 기록 안에서 평균한 뒤 현재 학습 기록만으로 계산한 하나의 기울기·절편으로 보정한다. 이 보정 후 결과가 사전 지정 주결과이며 원시 결과도 저장한다.

내부 학습20개와 바깥 재학습5개를 진행한다. 내부 검증의 사람별 MAE를 검증 사람 수로 가중 평균해 종료epoch를 고른다. 정답 min/max·보정계수는 학습자료에서만 구하고, 바깥 평가자료를 선택에 사용하지 않는다. 보호된 최종 평가자료도 추가하지 않는다. 매epoch의 원시 예측 배열·보정계수·원시/보정 MAE·학습률을 저장한다.

STT 공식 모델27,022개 파라미터, Adam·배치128·최대200epoch·학습률0.0003·최소0.00008·40epoch cosine restart는 이전 STT와 같다. CNN의 RMSprop·배치32·최대100epoch와 다르므로 계산량까지 맞춘 비교는 아니다. 파일럿 가중치부터 본 학습을 재개하지 않는다.

## 실행과 GPU 확보

GPU1개·CPU4개·RAM12GB씩 두 작업을 사용한다. 각 GPU의 배치 메모리는 이전 단일 STT 파일럿처럼 수백MiB 수준으로 예상하지만 실제 여러 구간 파일럿에서 다시 측정한다. 총 구간 수는 단일 대비 약10.6배이며 수시간이 걸릴 수 있다. 실제 예상 소요는 파일럿 시간으로 계산한다.

`primary`는 파일럿을 실행하고 검산 승인 파일을 기다린다. 입력·가상 재개·검증자료 분리·25개 가상 학습·실제3epoch 파일럿·저장 모델 재추론이 통과한 후에만 본 학습을 허용한다. 승인 파일은 묶음·파일럿 요약·체크포인트 지문을 포함한다. 최대45분 안에 승인되지 않으면 작업을 종료한다. `secondary`도 같은 승인을 확인해야 시작한다.

본 학습은 primary에 바깥분할0·1·2, secondary에3·4를 배정한다. 학습 출력은 분할마다 달라 겹치지 않는다. 각 분할은 별도 난수 초기값과 자기 학습자료를 사용하므로 두 GPU의 학습 결과를 서로 전달하지 않는다. 마지막 작업이 잠금을 얻어5개 분할을 검산·통합하며, 이전 작업의 모델이나 평가예측을 입력으로 쓰지 않는다.

각 작업의 상한은24시간이다. 사용자 요청으로 **primary만 학습 종료 후에도 배정 시작부터 총24시간 동안 배치를 유지**한다. 정상 만료 직전5초에 반환한다. secondary는 담당 학습·필요한 통합이 끝나면 반환한다. 유지 중에는 새 학습이나 가짜 GPU 계산을 실행하지 않으며 다음 승인된 실험에서 기존 할당을 사용할 수 있다. 학습 완료와 GPU 유지 상태를 `control/worker-primary.json`에 구분한다. 학습 실패 시에도 파일럿 승인 후 primary 할당은 유지하고 오류코드를 남긴다. 파일럿·검증 실패는 즉시 종료한다.

제출 전에는 사용 가능한 GPU가3개 이상인지, 각 작업이 배정된 뒤에는1개 이상 남았는지 확인한다. 다른 사용자의 이후 배정이나 관리자 조치·노드 장애까지 막는 예약은 아니다. 서버 설정상 p02 최대7일이며 별도의 유휴 점유 운영 지침은 현재 확인되지 않았다.

```bash
cd /abr/RESEARCH_USER/gdi-stt692-multiwindow-20261031
mkdir -p logs control
/usr/bin/python3.8 -B capacity.py --min-free 3
sbatch --nodelist=DIS01 --job-name=gdi-stt-multi-a submit.slurm primary
# 파일럿 검산 후 control/approve-main.json 작성. 이후 여유 확인 후 두 번째 제출.
/usr/bin/python3.8 -B capacity.py --min-free 2
sbatch --nodelist=DIS02 --job-name=gdi-stt-multi-b submit.slurm secondary
```

유지 중인 GPU를 조기 반환하려면 해당 작업ID로 `control/release-작업ID` 빈 파일을 만든다. 이 신호는 학습을 중단하지 않고 학습 종료 후 대기만 끝낸다. 학습까지 즉시 중단하려는 경우에는 해당 작업 하나에 `scancel 작업ID`를 사용한다.

유지 상태에서만 다음처럼 기존 할당 내부에 승인된 작업을 실행할 수 있다. 새 GPU를 신청하는 명령이 아니다. 실제 작업ID로 바꾸고 먼저 `control/worker-primary.json`의 상태와 `squeue`를 확인한다.

```bash
srun --jobid=작업ID --overlap --ntasks=1 --cpus-per-task=4 --gres=gpu:1 --pty bash
```

기존 할당의 종료시각은 다음 작업에도 적용되며 새24시간으로 갱신되지 않는다. 할당 내 재사용은 [Slurm srun 문서](https://slurm.schedmd.com/srun.html)를 참고한 절차이며 실제 재사용 검증 여부는 STATUS에 별도로 기록한다.
