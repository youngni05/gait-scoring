# STT 본 학습 실행 기록

같은 사람 분할과 평가 방식으로 STT를 학습해 기존 CNN과 비교한다. 기존 파일럿과 여러 구간 CNN은 보존하고, 이 폴더와 서버 `gdi-stt692-full-20261031`에서만 새 실험을 진행한다. 최신 작업 ID와 진행 상태는 상위 `STATUS.md`에 기록한다.

입력은 기존 692명·1,061기록의 단일 124프레임이다. 양쪽 다리 각각 발목·무릎·엉덩이·엄지발끝 xy 좌표로 GDI를 예측한다. CNN의 좌표 8개를 사용하며 추가 각도·거리 특징 4개는 넣지 않는다. 공식 STT 모델 파일은 그대로 사용하고 27,022개 파라미터를 처음부터 학습한다. 파일럿의 가중치를 이어받지 않는다.

## 학습과 평가

1. 기존 사람 단위 5분할 중 하나를 바깥 평가로 남긴다.
2. 나머지 네 분할을 번갈아 내부 검증으로 사용해 각각 최대 200epoch를 학습한다. STT 공식 설정의 최대 epoch를 사용하며 CNN의 100epoch와 다르다.
3. 같은 epoch의 내부 검증 MAE를 검증 사람 수로 가중 평균한다. 보정 후 MAE가 가장 낮은 시점 중 가장 이른 epoch를 고른다.
4. 바깥 평가를 제외한 사람 모두로 새 모델을 처음부터 선택된 epoch까지 학습한다. 이후 바깥 평가를 한 번 예측한다.
5. 바깥 분할을 바꿔 총 25개 학습을 실행한다. 최종 지표는 사람마다 같은 비중으로 계산한다.

학습 사람만으로 GDI min/max와 출력 보정의 기울기·절편을 계산한다. 보정은 `원시 예측 × 기울기 + 절편`이다. 기울기가 음수여도 임의로 자르거나 바꾸지 않고 기록한다. 바깥 평가 예측은 epoch 선택에 사용하지 않는다. 보호된 최종 평가 사람은 추가하지 않는다.

Adam lr0.0003, 최소 lr0.00008, cosine warm restart40, 배치128, dropout0, 기존 시드 규칙을 유지한다. 보정 산술은 float64로 명시해 NumPy 버전별 스칼라 형 변환 차이를 줄인다. 학습의 float32 연산은 유지한다.

## 기록과 재개

- `runs/main/fold*/inner*/curve.json`, `refit/curve.json`: epoch별 학습·내부 검증의 원시/보정 MAE, 기울기·절편, 손실, 학습률, 시간.
- 각 학습 폴더의 `raw_predictions/epochXXXX.npz`: 학습/내부 검증의 실제 원시 예측 배열. 행 순서는 고정된 `data.npz`의 해당 분할 순서다. refit의 검증 배열은 비어 있다.
- `identity.json`, `latest.pt`: 데이터·실행 식별 정보와 모델/optimizer/scheduler/난수 상태. 같은 폴더로 재개하면 완료 epoch를 반복 최적화하지 않는다. 원시 배열을 먼저 저장한 뒤 체크포인트를 저장한다.
- `selection.json`: 내부 검증 곡선과 선택된 epoch. `predictions.npz`: 해당 바깥 분할의 원시·보정 예측과 정답.
- 완료 후 `oof_predictions.npz`, `predictions.csv`, `summary.json`, `diagnostic_curves.csv`, `runs/main-review.tar.gz`를 생성한다. 요약 전에 모든 epoch의 저장 원시 예측에서 보정과 지표를 다시 계산하고 해시를 검사한다.

본 학습은 GPU1개·CPU4개·RAM12GB·최대2시간을 요청한다. 파일럿에서 최대 PyTorch 할당은188MiB였다. 예상 소요40~90분은 단일 구간 파일럿을 근거로 한 대략치이며 저장·요약 시간에 따라 달라진다. 시작 전에 GPU 여유2개 이상, 할당 뒤1개 이상을 검사한다. 공유 자원의 이후 변동을 예약하거나 보장하지 않는다.

CPU에서 실제 입력과 분할 검사, 가상 학습의 저장·재개·검증 분리, 가상 25개 학습 전체 흐름을 검증한다. 서버에서도 같은 검사를 통과한 뒤 본 학습한다. 테스트용 가상 자료와 실제 GDI 최적화 횟수는 구분한다. 전체 데이터에 대한 새 CPU 학습은 하지 않는다.

```bash
cd /abr/RESEARCH_USER/gdi-stt692-full-20261031
mkdir -p logs
/usr/bin/python3.8 -B capacity.py --min-free 2
sbatch --nodelist=DIS03 submit.slurm
```

기존 같은 실험이 실행 중인지 먼저 확인한다. 재개도 같은 명령과 같은 출력 폴더를 쓰며, 동시 중복 제출하지 않는다. Slurm 종료 시 마지막으로 저장된 epoch부터 다시 실행할 수 있다.
