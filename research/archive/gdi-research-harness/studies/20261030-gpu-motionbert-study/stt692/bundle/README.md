# STT 단일 구간 GPU 파일럿

현재 CNN·MotionBERT 보정이 같은 사람들에게 비슷한 오차를 보이는지 분석하고, 관절 관계를 직접 학습하는 STT를 같은 조건에서 비교할 준비를 했다. 이 묶음은 **입력 검사 → 가상 자료 검사 → 실제 자료 3epoch GPU 파일럿**까지만 실행한다. 본 학습과 최종 성능 비교는 포함하지 않는다.

## 무엇을 입력하고 학습하는가

- 기존 단일 CNN과 동일한 692명·1,061기록·124프레임·좌우 GDI·사람별 5분할이다. 보호한 최종 평가자료는 추가하지 않았다.
- 기존 CNN 특징 12개 중 앞 8개 좌표를 그대로 재배열한다. `[기록,좌우,124시간,4관절,xy]`이며 관절 순서는 **발목·무릎·엉덩이·엄지발끝**이다. 각도·거리의 추가 4개 특징과 OpenPose 신뢰도는 STT 입력에 넣지 않는다.
- 골반 중심·허벅지 길이 정규화, 영상 전체의 기존 보간·평활화, 원 구간의 프레임 ID를 유지한다. 새 방향 반전이나 영상 선택은 없다. 새로운 RGB 영상이나 MotionBERT 특징을 사용하지 않는다.
- 한 기록의 좌우를 별도 예제로 만들어 같은 STT가 각각 GDI 하나를 예측한다. 좌우/같은 사람의 다른 기록은 학습·평가 분할을 넘지 않는다.
- 파일럿은 바깥 fold0을 남기고, 나머지 중 fold1을 내부 검증으로 쓴다. 학습 416명·검증 138명이며 바깥 138명은 학습·보정·검증 예측에 쓰지 않는다. 이 파일럿 수치는 최종 평가 성능이 아니다.

## 공식 코드와 적용한 차이

공식 저장소: https://github.com/vinuni-vishc/transformer-gait-analysis

확인 commit: `549d58bc32449b24a0eae0c37ca573f9aa58a1dd`. 원 파일·해시는 `sources/`, `sources.json`에 보존했다. `model/`의 공식 모델 파일 4개는 바꾸지 않았다. einops 0.8.1을 `vendor/`에 포함하므로 서버의 전역 패키지를 바꿀 필요가 없다. PyTorch와 NumPy는 서버 기존 설치를 사용한다.

구조는 4관절×2좌표 → 관절 attention → 시간 attention → 학습 가능한 시간 가중 평균 → GDI 출력이다. 임베딩 12, attention head 2, 각 공간/시간 블록 1개이며 파라미터는 **27,022개**다. 가중치는 처음부터 학습한다. 공식 사전학습 체크포인트를 불러오지 않는다.

| 항목 | 공식 코드/논문 | 이번 파일럿 |
| --- | --- | --- |
| 입력 | 124프레임 다중 구간, 한쪽 4관절 xy | 같은 124프레임 한 구간; CNN 첫 8개 좌표와 배열 전체 일치 |
| 사람 분할 | 제공된 train/validation/test, 논문 8:1:1 | 기존 5분할 유지, outer0/inner1만 파일럿 |
| 최적화 | Adam, GDI lr0.0003, 최소0.00008, cosine warm restart40 | 동일한 optimizer·학습률·scheduler, 파일럿3epoch |
| 배치 | 128, 공개 반복문은 고정 순서 | 좌우 예제128, seed로 epoch마다 순서 섞기 |
| 정답 변환 | 학습 정답 min/max | 현재 학습 사람만의 좌우 min/max |
| 손실 | 구간 가중 MSE 함수 | 한 구간이므로 1차원 예측·정답의 표준 MSE |
| 예측 보정 | 학습 예측으로 공통 기울기·절편 | 동일하게 학습 사람만으로 계산; 보정 전후 모두 저장 |
| 종료/평가 | 보정 후 validation RMSE 선택 코드 | 파일럿은 고정3epoch; 본 학습은 미구현. 이후 기존 내부 사람 가중 MAE 비교 원칙 유지 예정 |

공식 코드에서 확인한 주의점은 다음과 같다. 논문 결과 자체가 틀렸다고 판정한 것은 아니다.

1. `transformer_model.py`는 매 배치의 오차 `[B]`에 전체 학습 구간 가중치 `[N,1]`를 전달한다. 이는 `[N,B]`로 확장되며 각 예제에 맞는 가중치를 적용하지 않는다. 실제 함수로 가상 예제를 계산해 2.5가 나오는 반면 올바른 대응 가중 평균은 3.25임을 확인했다. 이번 한 구간 입력은 동일 가중치의 MSE로 명시하고 차원 검사를 둔다.
2. `test.py`의 마지막 `best_epoch_preds`는 선택한 `best_epoch` 대신 앞 반복문의 `epoch`를 사용한다. 이번 실행부는 공식 `test.py`를 실행하지 않는다. 파일럿은 마지막 3epoch 모델의 내부 검증 예측만 저장한다.
3. 제공된 원자료 split과 전체 자료를 그대로 읽는 공식 `GaitDataset` 대신 우리의 해시가 고정된 NPZ와 사람 분리 검사를 사용한다. 모델 파일만 재사용한다.

이 차이들 때문에 이번 실험은 **공식 STT 구조를 우리 단일 구간·분할에 적용한 비교 준비**다. 원 논문의 MAE6.3137 재현 실험이라고 부르지 않는다.

## 검증과 파일럿 실행

로컬에서 실제 자료의 입력·20개 내부 분할·실제 입력 순방향 추론을 검사한다. 가상 자료로만 가중치 갱신, 정확한 모델/optimizer/scheduler 재개, 검증 입력·정답 변경 시 학습 가중치·정답 변환·보정계수 불변, 사람 중복·다른 체크포인트 거부, 저장 모델 재추론을 검사한다. 실제 GDI 정답의 로컬 최적화는 하지 않는다.

GPU는 A6000 **1개**, CPU4개·RAM12GB·최대30분을 요청하도록 작성했다. GPU 시간·메모리는 아직 측정하지 않았으며 파일럿이 실측값을 저장한다. 용량 계획값과 실측을 혼동하지 않는다. `/usr/bin/python3.8`을 명시해 DIS03 기본 Anaconda와의 충돌을 피한다.

서버에 ZIP을 전송·해제한 뒤 실행할 명령이다. **이번 준비 작업에서 전송·제출하지 않았다.**

```bash
cd /abr/RESEARCH_USER
/usr/bin/python3.8 -B -m zipfile -e gdi-stt692-pilot.zip .
cd gdi-stt692-pilot-20261031
mkdir -p logs
/usr/bin/python3.8 -B capacity.py --min-free 2
# 위 검사가 성공했고 기존 작업·예약을 확인한 뒤 한 번만 제출한다.
sbatch --nodelist=DIS03 submit.slurm
```

DIS03 사용 가능 여부는 제출 직전에 확인한다. `capacity.py`는 배정 금지/고장 노드를 제외한 잔여 GPU 수 검사이며 예약·CPU·메모리까지 보장하는 스케줄러가 아니다. 배정 후에도 잔여 GPU가1개 이상인지 재검사하고 부족하면 학습을 시작하지 않는다. 다른 사용자의 이후 배정까지 막거나 예비 GPU를 점유하지 않는다.

결과는 `runs/pilot/pilot_summary.json`, 내부 검증 예측은 `validation_predictions.npz`, 모델은 `fit/latest.pt`, 로그는 `logs/pilot-작업번호.log`다. 출력에 `STT_PILOT_FINISHED`가 있어야 한다. 실패 시 로그를 확인하며 기존 여러 구간 CNN은 건드리지 않는다. 파일럿 재개는 같은 묶음·같은 출력 경로만 허용하며 모델과 optimizer·scheduler를 함께 복원한다.

한 단계라도 실패하면 배치 스크립트가 다음 단계로 넘어가지 않는다. 본 학습 자동 실행은 없다.
