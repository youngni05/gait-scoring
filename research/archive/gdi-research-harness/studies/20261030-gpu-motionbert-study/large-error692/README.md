# 큰 오차의 입력·구간 추적

2026-10-31. 완료된 기록 배치 CNN 대조군 `window_control`에서 오차가 가장 큰 5개 기록을 CPU로 추적했다. 아직 진행 중인 `record_mean`의 결과가 아니다. **최대 오류는 12개 구간 중 3개 예측의 폭주가 평균과 보정에서 커진 경우였다. 다른 4개는 구간 전반에서 높게 예측하는 유형이었다.**

## 무엇을 확인했나

좌우 중 큰 절대오차를 기준으로 상위 5개 기록을 정했다. 원본 OpenPose JSON → 보간·평활화·허벅지 길이 정규화 → 124프레임 구간 → 모델 예측 → 구간 평균 → 학습자료 보정 순서로 추적했다. 같은 입력을 과거 여러 구간 CNN에 넣어 차이도 확인했다.

원본 ZIP은 기존 D 자료를 읽었다. 선택한 5개 기록의 JSON 내용 지문이 기존 준비 기록과 일치하고, 원래 전처리로 다시 만든 모든 구간이 저장 입력과 정확히 같았다. CPU float64로 두 모델씩 총 10개 사례 예측을 재현했다. 저장 결과와 최대 차이는 **0.000008006점**, 기존 허용차이 0.0001점 이내다. 파일 손상이나 집계 오류로 이번 큰 오차를 설명할 근거는 없었다.

## 55.60점이 159.01점이 된 경로

왼쪽 정답 55.6015점의 기록에는 12개 구간이 있었다. 세 구간의 원시 예측이 특히 컸다. 프레임 번호는 0부터 세며 구간은 서로 겹친다.

| 시작 프레임 | 새 대조군 원시 예측 | 기존 CNN 원시 예측 | 필수 좌표 최대 결측률 |
|---|---:|---:|---:|
| 217 | 182.03 | 51.65 | 20.16% |
| 248 | 326.83 | 50.08 | 22.58% |
| 279 | 457.38 | 51.47 | 22.58% |

나머지 9개 구간은 약 65~73점이다. 12개를 평균하면 **131.90점**, 보정식 `1.439892×원시 예측−30.908522`를 적용하면 **159.01점**이다. 보정이 추가로 약 27.11점을 올렸지만, 최초 폭주는 보정 전에 이미 발생했다.

같은 원본·전처리·구간을 사용한 기존 CNN은 최종 **57.72점**, 기존 CNN·STT 결합은 **57.86점**이다. 따라서 이 159점 오류를 현재 가장 좋은 예측 결합의 오류로 혼동하면 안 된다. 이번 평균·차이 분리 결합도 이 사례는 57.89점이다.

문제 구간은 결측률 25% 이하라는 기존 통과 조건을 만족했다. 그러나 신뢰도 0.2 미만 또는 미관측인 필수 관절의 비율은 약 26~29%였다. 기존 입력에서는 신뢰도 채널이 제거되며 이 비율은 필터 기준이 아니라 이번 진단 통계다. 정규화된 골반 x좌표는 해당 바깥 분할의 학습 입력 중앙 99% 범위를 벗어난 값이 약 41.4%였다. 이는 전체 학습 범위 밖이라는 뜻은 아니다. 관찰 구간의 허벅지 기준 길이는 32.06~78.37픽셀이어서 분모가 0에 가까워진 폭주로 볼 근거도 없었다.

모델 내부 출력을 추적하면 마지막 BatchNorm 층에서 문제 세 구간의 왼쪽 최대 절댓값은 새 대조군 약 11.5~11.9, 기존 CNN 약 3.3~3.7이었다. 두 모델 모두 일부 채널의 저장 분산이 매우 작아, 그 사실 하나만으로 BatchNorm을 원인으로 확정할 수는 없다. **특정 입력 구간에 대한 학습된 모델의 반응 차이**는 확인했으며 배치 구성·학습 경로·정규화 중 무엇의 효과인지는 별도 대조 실험이 필요하다.

## 나머지 큰 오차는 같은 유형인가

각 기록에서 오차가 더 큰 쪽을 표시했다. 입력을 수정하거나 기록을 제외하지 않았다.

| 사례 | 정답 | 새 대조군 | 기존 CNN | 기존 CNN·STT 결합 | 평균·차이 분리 결합 |
|---|---:|---:|---:|---:|---:|
| 1, 왼쪽 | 55.60 | 159.01 | 57.72 | 57.86 | 57.89 |
| 2, 오른쪽 | 39.12 | 71.69 | 66.83 | 65.66 | 65.91 |
| 3, 오른쪽 | 48.82 | 80.94 | 74.76 | 76.01 | 76.78 |
| 4, 오른쪽 | 59.89 | 88.47 | 86.51 | 75.59 | 74.85 |
| 5, 왼쪽 | 60.72 | 86.57 | 84.12 | 84.45 | 85.26 |

사례 2~5의 대조군 원시 구간 예측 범위는 각각 67.38~73.48, 73.86~81.20, 79.55~84.23, 77.00~85.52점이다. 일부 구간만 튄 것이 아니어서 중앙값이나 극단값 억제만으로 정답까지 내려갈 이유가 없다. 학습된 평균 쏠림, 입력이 표현하지 못하는 동작, 영상과 GDI 정답의 대응 등을 더 확인해야 하는 사례다. 이번 분석으로 원인을 하나로 확정하지 않는다.

대조군의 기존 CNN 대비 전체 MAE 증가는 0.384128점이다. 사례 1 사람의 모든 기록이 그 차이에 기여한 몫은 약 0.082783점이다. 즉 가장 눈에 띄는 폭주 하나가 전체 차이를 모두 설명하지 않는다. 사례 제외 후의 성능으로 보고한 값은 아니다.

## 다음 비교에 활용할 근거와 한계

관찰된 근거는 ‘소수 구간의 폭주’와 ‘구간 전체의 지속적인 편향’을 나눠 다뤄야 한다는 점이다. 구간을 합칠 때 극단값의 영향을 줄이는 후보와, 기록 배치 변경에 따른 모델 반응을 점검하는 후보를 따로 비교할 필요가 있어 보인다. 이는 후속 후보이며 이번에는 학습·보정식·구간 선택 기준을 변경하지 않았다.

오차를 본 뒤 고른 5개 사례의 진단이므로 전체 자료의 결측률 기준을 새로 정하는 근거로 바로 쓰지 않는다. 영상이나 3D 기준 동작을 대조하지 않았으므로 실제 보행 이상과 자세 추출 오류를 확정적으로 구분할 수 없다. 입력 범위 비교는 해당 바깥 **학습 구간만** 사용했지만, 겹친 구간별 기술통계이며 사람 동일 비중의 성능 지표가 아니다. 보호된 최종 평가자료·LJMU는 열지 않았다.

`analyze.py`가 원본 좌표와 저장 모델을 읽어 구간별 흐름을 복원한다. `inspect_activations.py`는 가중치를 바꾸지 않고 모델 내부 값만 기록한다. `summarize_verify.py`는 원본 지문·사례 선택·평균·보정식·CSV를 별도로 검사한다. [검산](analysis/verification.json) · [5사례 요약](analysis/case_summary.csv) · [모든 구간](analysis/windows.csv) · [입력 진단](analysis/diagnostics.json).

작은 코드·보고서·검산 결과는 C의 이 폴더에 저장했다. 원본 자료와 모델은 기존 경로에 보존했고 새 대용량 다운로드는 없다.
