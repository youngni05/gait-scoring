## 이 실험으로 답할 질문

**강도 1 RankSim의 작은 이득은 학습의 우연이 바뀌어도 남는가? 기존 모델과 새 모델을 평균하면 실제로 더 잘 맞는가?**

강도 0.1·0.3 추가 앙상블은 전체 MAE6.553794·6.523413점이었다. 내부에서 강도와 비중을 함께 고른 결과도6.509324점으로 기존 강도1 앙상블6.476735점을 넘지 못했다. 더 약한 강도를 추가 탐색할 근거는 부족하다. 기존 강도1 앙상블 자체도 원래 최선6.515817점 대비 차이의95%범위에0을 포함한다. 이를 확실한 개선으로 승격하지 않고 초기값과 모델 평균 효과를 대조한다.

입력은 같은692명·1,061기록·11,261개 측면 OpenPose 구간(한쪽124프레임×12특징), 정답은 실제 좌우GDI다. **바꾸는 것은 난수 시작값(seed20261028→20261102) 하나다.** 초기 가중치뿐 아니라 dropout·학습 표본의 순서도 이 seed에 따라 달라진다. 같은 새 seed 안의 일반 MSE와 RankSim1은 초기 가중치·사람별 추출횟수·추출 순서를 맞춘다. 기존 자료·사람5분할·모델·손실 강도1·정규화·보정·최대100epoch는 유지한다.

새 학습은50개, 바깥 예측은10개다. 기존50개 학습은 SHA와 코드·입력 조건을 대조해 재사용한다. seed 사이 평균은1:1로 고정한다. 기존 최선에 추가하는 비중만0~1의0.05간격에서 **바깥 평가 사람을 제외한 내부 검증**으로 정한다. 바깥 성능을 보고 seed·손실·조합을 다시 고르지 않는다. 같은(f,j) 내부 모델은 f와j 사람을 모두 학습에서 제외한다.

각 seed/손실의 epoch는 나머지4분할의 사람 수를 반영한 내부MAE로 고른다. 내부 선택에서 쓰는 단일 모델과 바깥의 기존 최선 모델 평균, 내부100epoch와 바깥 refit 선택epoch의 차이는 계속 기록한다. 실제 정답이 고득점인지 알아야만 작동하는 분기는 만들지 않는다.

## 검증과 판단

계획 CPU 사전검사 → 실행 코드의 전체 가상검사 → GPU1개짜리 최대3작업 → 각GPU 검사와 실제 두 조건3epoch 파일럿 → 서버·로컬 재추론과SHA 검산 → 같은 지문 본학습 순서다. CPU 계획 검사는 실제 사람 분리·seed 공식·동일 초기화·동일 표본을 확인하며, 전체 실행 코드나 GPU 파일럿을 대신하지 않는다.

주 비교는 두 seed RankSim 평균을 추가한 앙상블과 기존 한 seed RankSim 추가 앙상블이다. 사람 동일 비중 전체MAE, 사람 평균90/100 이상과 관측값90/100 이상의 인원·MAE·편향, 낮은 점수대 손익·분할별 변화·사람 짝지은10,000회 재표집을 본다. 전체 차이95%상한<0·4/5분할 이상 개선을 요구하고, 고득점MAE와 절대편향도 나빠지지 않을 때만 양쪽 개선으로 분류한다. MSE 평균도 같은 만큼 좋아지면 RankSim 고유 효과로 설명하지 않는다.

예상 총GPU20~40시간·병렬 경과10~18시간·메모리1GiB 미만이다. 이전 파일럿26.23초/epoch·182.2MiB에 근거한 추정이며 대기·입출력·로컬 승인·요약은 제외한다. 실제 새 파일럿으로 남은 작업 시간이24시간 할당 안에 들어오는지 확인한다. 안 맞으면 대기·보고하며 epoch 수를 몰래 줄이지 않는다. 다른 채팅 작업과 기존 확보·release파일은 변경하지 않는다.

최종 자료는 D에 회수해 압축과 개별SHA를 대조하고50학습·모든epoch·10최종CPU64재추론을 검산한다. 점수 허용오차0.0001과 원래 계수1e-10 검사는 유지하고, 엄격 계수 실패와 별도 출력 검산은 구분해 남긴다. 코드·계획·작은 검산은 C에 둔다.

## 방법의 근거와 한계

[Deep Ensembles 논문](https://papers.nips.cc/paper/7219-simple-and-scalable-predictive-uncertainty-estimation-using-deep-ensembles.pdf)의 독립 초기화·학습 순서와 모델 평균 아이디어만 적용한다. 분산 출력층·NLL·적대적 학습까지 도입하는 실험이 아니며 불확실성 보정을 검증했다고 주장하지 않는다. RankSim은 [공식 논문](https://proceedings.mlr.press/v162/gong22a.html)의 기존 연구용 어댑터·라이선스를 보존한다.

두 seed만으로 초기값 전체의 안정성을 보장할 수 없다. 같은 개발자료를 반복한 연구이며 외부·임상 검증이 아니다. 보호 최종자료나 정답 없는LJMU는 선택에 사용하지 않는다.
