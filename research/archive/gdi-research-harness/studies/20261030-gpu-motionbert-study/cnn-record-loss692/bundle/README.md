# 기록 평균을 학습하는 CNN 비교

같은 영상의 모든 짧은 구간에 GDI 정답을 각각 맞추는 대신, 구간 예측을 평균한 기록 점수가 정답에 맞도록 학습해 보고자 한다. 기존 실행과 결과는 유지하고 별도 묶음에서 비교한다. 이번 요청은 준비와 검증이며 GPU 제출은 하지 않는다.

기존 여러 구간 CNN의 692명·1,061기록·11,261구간, 124프레임·31프레임 간격, 원 연구식 12개 특징과 좌우 별도 처리를 유지한다. data.npz와 model.py를 그대로 복사하고 SHA256을 대조한다. 6개 합성곱 층·47,840개 파라미터, dropout 0.5, RMSprop 0.001, 기존 L2와 학습률 감소, 최대 100epoch, 내부 20회·바깥 재학습 5회도 유지한다.

## 두 조건이 다른 부분

| 조건 | 한 기록의 학습 오차 |
|---|---|
| `window_control` | 각 구간 예측과 정답의 제곱오차를 평균 |
| `record_mean` | 구간 예측을 먼저 평균한 뒤 정답과의 제곱오차 계산 |

두 조건 모두 기록 2개에 포함된 실제 구간과 좌우를 한 배치로 처리한다. 빈 구간을 덧붙이지 않는다. 기록마다 같은 손실 비중이며, 같은 사람의 여러 기록을 합쳐 사람 비중으로 바꾸지는 않는다. 예측과 평가는 기존과 같이 기록 안 구간 평균 → 학습 기록만으로 기울기·절편 보정 → 사람별 동일 비중 MAE 순서다.

기존 CNN은 무작위 구간·다리 32개 배치였다. 새 두 조건은 기록 2개 배치라 BatchNorm이 보는 구성과 epoch당 최적화 횟수가 달라진다. 따라서 기존 MAE 6.866655와의 비교에는 배치 변화도 포함된다. `window_control`과 `record_mean` 사이의 비교가 손실 계산 순서를 분리하는 대조 실험이다. 데이터 확대·새 구조·사람 비중 변경 효과로 해석하지 않는다.

학습 종료 epoch는 각 바깥 평가 사람을 제외한 내부 검증만으로 선택한다. 정답의 범위 변환과 출력 보정도 해당 학습 기록만 사용한다. 보호된 최종 평가자료는 사용하지 않는다. 매 epoch의 학습·내부 검증 원시 예측, 보정계수, 곡선, 저장 모델을 남긴다.

## 실행과 검증

CPU에서는 실제 입력·25개 학습 부분집합을 확인하고 가상 자료로 손실과 미분, 구간 순서, 중단 후 정확 재개, 검증자료 변경 시 학습 불변성, 각 조건의 25개 중첩 학습 및 바깥 자료 변경 불변성을 검사한다. 실제 GDI 학습이나 GPU 성능 확인은 아니다. 최신 통과 여부는 상위 `verification.json`을 확인한다.

GPU 파일럿은 두 조건을 순서대로 3epoch 실행하고, 저장 모델의 GPU·CPU 재추론과 학습자료만의 보정을 검산한다. 허용 차이는 기존과 같은 GDI 0.0001점이다. 실제 시간과 메모리는 이 파일럿에서 측정한다. CNN 구조는 같지만 한 배치의 구간 수가 달라 기존 시간·메모리를 그대로 보장하지 않는다. 최대 2기록×13구간×2다리=52개 예제이며 별도 GPU 1개로 파일럿이 가능하도록 준비한다.

```bash
mkdir -p logs
sbatch --time=01:00:00 submit.slurm pilot
# 파일럿 검산과 본 학습 실행 결정 뒤에만 각 조건을 제출한다.
sbatch submit.slurm train window_control
sbatch submit.slurm train record_mean
```

파일럿은 본 학습으로 자동 진행하지 않는다. 실행은 `runs/pilot/조건`, 본 학습은 `runs/main/조건`에 분리한다. 기존 GPU 할당·학습·감시 등록은 변경하지 않는다.
