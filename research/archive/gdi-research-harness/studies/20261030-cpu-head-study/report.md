# CPU 예측부 실험 — 단일 조건 실행 결과

기준: 2026-10-30 13:25 KST

**고정 MotionBERT 특징에서 선형 출력부만 추가 학습해 보았지만, 현재 조건에서는 기존 Ridge를 교체할 만큼의 점수 정확도 개선은 확인하지 못했다.** 앞 구간 오차는 조금 커졌고 뒤 구간 오차는 아주 조금 줄었다. 같은 영상의 앞뒤 점수 차이는 약 0.038점 작아졌으나, 이 변화만으로 실제 반복 촬영이 더 안정적이라고 볼 수는 없다.

실제 GDI 학습은 **5묶음×200업데이트=1,000업데이트**를 완료했다. GPU 사용과 MotionBERT 본체 로드·재추론은 없다. 조율 채팅에서 준비 결과와 제안 설정을 검토한 뒤 실행을 지시했다. 이를 별도의 새 사용자 발언이나 새 팀 합의로 기록하지 않는다.

## 입력과 비교 방법

개발자료 175명·203기록의 앞/뒤124프레임에서 이미 추출한 512차원 특징을 사용했다. 기존 사람별 5묶음을 유지하고 각 묶음의 학습140명에서 앞 구간만으로 출력부를 갱신했다. 평가35명의 앞·뒤 예측을 저장한 뒤, 사람 안에서 좌우·기록 오차를 먼저 평균하고 사람 간 평균을 계산했다. 모든203기록은 자신이 학습에 포함되지 않은 묶음의 모델로 한 번씩 예측됐다.

기존 train-only 표준화 값과 Ridge 계수를 시작점으로 사용했다. 1,026개 선형 출력 매개변수만 학습했다. 학습 후 모델은 Ridge 해를 다시 계산한 모델이 아니라, Ridge에서 출발한 선형 출력층이다.

고정 조건: 시드20261028, 5fold, 묶음당200업데이트, 배치32, 출력부 학습률1e-4, weight decay0, AdamW, 좌우 기록동일 평균제곱오차, CPU 스레드2, 10업데이트마다 저장. 평가 결과를 보고 설정·시드·반복 수를 다시 고르지 않았다. 미래 GPU용 특징 추출기 학습률은 이번 실행에서 사용하지 않았으며, 확정값으로 보지 않는다.

## 실제로 학습됐는가?

다섯 묶음 모두 출력부 계수가 바뀌었고, 표준화 평균·크기는 그대로였다. 최대 가중치 변화는 묶음에 따라 약0.00077~0.00349다. 다만 전체 학습자료의 기록동일 평균제곱오차는5묶음 중4묶음에서 오히려 조금 커졌고1묶음에서만 작아졌다. 업데이트가 실행됐다는 사실과 더 잘 학습됐다는 판단은 구분한다.

기존 Ridge 초기값, 작은 학습률, 미니배치 갱신을 사용한 이번 한 조건만으로 모든 출력부 추가 학습이 무효라고 결론 내릴 수는 없다. 반대로 작은 앞뒤 차이 감소를 근거로 조건을 계속 탐색해 성공 결과만 고르지도 않는다. 현재 결과는 **GPU에서 특징 추출부까지 조정한 방법과 비교할 출력부 대조군**으로 남길 만하다.

## 검증과 실행 시간

- 원본 입력·기준 계수·기준 예측·준비 코드·초안 설정의SHA-256 지문을 대조했다.
- 5개 저장 체크포인트를 weights_only=True로 읽고, 독립 NumPy 행렬 계산으로 평가 예측을 재생했다. 최대 차이는 약7.11e-14점이다.
- 203기록의 중복·누락 없는 예측, 원본 행 순서와 사람·영상·fold 식별자, 앞뒤·좌우 축을 확인했다.
- 사람별 평균 오차와 앞뒤 차이, 탐색적 재표집 범위를 별도 계산해 집계파일과 대조했다.
- 본체 가중치 없이 표준화 버퍼와 선형 출력부만 저장됐는지 확인했다.

5묶음의 실제 학습·주기 저장·평가 예측 계산 합계는 약0.984초였다. Python 시작과 자료·지문 읽기, 결과 집계는 제외한 시간이다. 실제 학습을 호출한 셸 명령 전체는 약6.45초에 종료됐다. 이는 작은 캐시 특징 기반 선형층의 비용이며 MotionBERT 재추론·GPU학습 시간이나 영상부터의 전체 처리속도가 아니다.

Python3.12.14, PyTorch2.14.1+cpu, NumPy2.3.5를 재사용했다. 처음 준비 과정의 Python3.13 호환 오류와 가상 기술검사 기록은 아래 준비단계 기록에 남겼다.

# CPU 예측부 실험 — 실행 준비와 학습 조건안

기준: 2026-10-30 13:21 KST

현재는 MotionBERT가 만든 특징을 고정하고, 마지막 점수 계산 부분만 추가 학습하는 비교를 먼저 해보려 한다. GPU에서 특징 추출기까지 학습했을 때의 변화가 단순 추가 학습 효과인지 구분할 대조 조건이다.

**기존 예측 재현과 가상 입력 기술검사는 완료했다. 실제 GDI 추가 학습은 0 step이며, 아래 조건은 조율 채팅의 후속 지시를 기다리는 제안이다.**

## 무엇을 입력하고 무엇을 바꾸는가

- 입력: 이미 추출된 512차원 MotionBERT 특징. 개발자료 175명·203기록의 앞/뒤 124프레임 특징만 사용한다.
- 정답: 해당 개발자료의 좌우 GDI 두 값.
- 시작점: 사람별 5묶음 각각의 학습자료로 만든 기존 표준화 값과 Ridge 계수.
- 학습: 앞 구간 특징으로 선형 출력부의 가중치 1,024개와 절편 2개만 갱신한다. MotionBERT 본체는 로드하지 않는다.
- 평가: 학습에서 제외한 사람의 앞·뒤 구간을 예측한다. 기록 오차를 사람 안에서 먼저 평균한 뒤 사람 간 평균을 구한다.

입력과 좌우 출력의 열 순서를 그대로 유지했다. 각 묶음은 학습 140명·평가 35명이며, 같은 사람이 양쪽에 없는지 검사했다. 표준화 값은 각 묶음의 앞 구간 학습 특징만으로 다시 계산해 일치함을 확인했다.

## 실행 시간과 기술검사

Python 3.12.14, PyTorch 2.14.1+cpu, NumPy 2.3.5, CPU 스레드 2개를 사용했다. Python 3.13 첫 실행은 기존 PyTorch가 cp312 바이너리라 DLL 로드에 실패했고, 기존 준비에서 사용한 3.12 런타임으로 맞춘 재검사는 통과했다. 원본 환경이나 패키지는 변경하지 않았다.

가상 32×512 특징과 가상 좌우 점수로 200업데이트·10회마다 저장하는 계산을 세 번 측정했다. 이번 측정은 다음과 같다.

0.142302초, 0.142642초, 0.154649초

중앙값의 5배로 잡은 5묶음 순수 학습·저장 시간 추정은 0.713초다. Python 시작, 소스 지문 확인, 실제 자료 입출력과 보고서 생성은 제외한다. 준비 검사 전체 명령은 약 6.4초에 종료됐지만, 이를 실제 학습의 확정 소요 시간으로 사용하지 않는다. GPU 학습 시간도 추정한 것이 아니다.
