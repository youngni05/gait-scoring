# PCA 압축 크기를 학습 사람 안에서 선택한 Ridge 비교

기준: 2026-10-30 14:39 KST

**PCA로 특징을 압축해도 이번 조건에서는 기존 Ridge보다 평가 오차가 줄지 않았다. 양끝 점수의 편향과 중앙으로 모이는 분포도 거의 그대로였다.**

바깥 평가 사람을 보지 않고 압축 크기를 선택했다. fold별로 64·16·32·32·16개가 선택됐으며, 이 선택 과정을 포함한 평가 앞 MAE는 8.275834→8.276862점, 뒤는 9.033923→9.041093점이었다. 기존 비교 기준을 교체할 근거는 부족하다.

## 1. 무엇을 바꾸었는가

입력은 같은 개발 175명·203기록의 고정 MotionBERT 특징 512개다. 앞 124프레임 특징으로 학습하고, 각 기록의 좌우 GDI를 예측한다. 기존 Ridge(alpha=1)를 기준으로 그 앞에 PCA 압축을 추가했다. alpha와 데이터 구간은 바꾸지 않았다.

```text
고정 특징 512개 → 학습 사람의 평균·크기로 표준화 → 기존 Ridge
고정 특징 512개 → 학습 사람의 평균·크기로 표준화 → PCA → Ridge
```

PCA는 512개 숫자에서 함께 변하는 방향을 묶어 더 적은 숫자로 나타내는 단계다. 새 움직임 정보나 임상 특징을 추가하는 방법은 아니다. 이번에는 whitening 없이 큰 변화 방향을 남겼다.

## 2. 압축 크기를 어떻게 골랐는가

각 바깥 fold의 학습 140명 안에서만 8·16·32·64개를 비교했다.

1. 바깥 평가 35명은 먼저 제외한다.
2. 학습 140명을 사람 기준으로 다시 4묶음으로 나눈다.
3. 안쪽 학습 105명에게서만 표준화·PCA·Ridge를 학습한다.
4. 안쪽 검증 35명을 예측하는 과정을 4번 반복해 140명의 사람별 MAE를 계산한다.
5. 앞 구간 MAE가 가장 작은 크기를 선택한다. 동률은 작은 크기로 정한다.
6. 선택한 크기로 바깥 학습 140명에서 모든 변환과 Ridge를 다시 학습하고, 제외했던 35명의 앞·뒤를 예측한다.

사람을 나누는 순서는 미리 고정한 난수값으로 정했고 점수는 사용하지 않았다. 내부 표준화나 PCA를 학습 140명 전체에서 미리 계산해 두지도 않았다. 바깥 평가 점수나 뒤 구간 결과로 크기를 바꾸지 않았다.

내부 후보 Ridge 80개와 최종 바깥 Ridge 5개를 학습했다. PCA는 안쪽 분할 20개와 바깥 재학습 5개에서 적합했다. GPU·MotionBERT 재학습·재추론과 보호 평가자료는 사용하지 않았다.

| 바깥 fold | 선택한 크기 | 선택에 사용한 내부 앞 MAE | 남긴 특징 변화의 비율 |
|---|---:|---:|---:|
| 0 | 64 | 8.187415 | 99.99999986% |
| 1 | 16 | 8.853211 | 99.99944234% |
| 2 | 32 | 8.588368 | 99.99999676% |
| 3 | 32 | 7.996511 | 99.99999668% |
| 4 | 16 | 8.221935 | 99.99950909% |

내부 16·32·64개 사이의 오차 차이는 매우 작은 경우가 있었다. 이 표를 특정 차원이 보편적으로 최적이라는 뜻으로 보지 않는다. 내부 점수는 크기를 고르는 용도이며 최종 성능은 아래의 바깥 평가값이다.

## 3. 오차와 점수 분포

각 칸은 기존과 같은 사람 가중치로 계산했다. 학습 쪽에서 같은 사람은 4개 모델에 들어가므로 그 사람의 반복 결과를 먼저 평균해, 한 사람이 차지하는 전체 비중을 맞췄다. 700명의 독립 사람으로 세지 않았다.

퍼짐은 사람 안의 기록·좌우 평균값에 대한 가중 표준편차(ddof=0)다. 실제 점수의 퍼짐은 11.094493점이다.

| 대상 | 구간 | 기존 Ridge MAE | PCA + Ridge MAE | 예측 퍼짐: 기존 → PCA |
|---|---|---:|---:|---:|
| 학습 사람 | 앞 | 7.599833 | 7.610040 | 5.864757 → 5.863871 |
| 학습 사람 | 뒤 | 8.775509 | 8.784458 | 5.345517 → 5.341472 |
| 평가 사람 | 앞 | 8.275834 | 8.276862 | 5.864623 → 5.866992 |
| 평가 사람 | 뒤 | 9.033923 | 9.041093 | 5.339151 → 5.335938 |

평가 앞 구간의 정확한 10점 구간 일치율은 38.57%→38.29%, 뒤는 34.38%→34.10%였다. 같은 영상의 앞뒤 예측 차이는 3.960483→3.971786점으로 조금 커졌다.

사람을 짝지어 10,000번 재표집한 탐색적 오차 감소량 범위는 앞 -0.010419~+0.008532점, 뒤 -0.014795~+0.000382점이다. 감소량은 기존 오차−새 오차이며 두 범위 모두 0을 포함한다. 반복 탐색한 개발자료의 범위이고 임상적 판정 기준은 아니다.

## 4. 양끝 점수 편향은 줄었는가

앞 평가 구간이다. 편향은 예측−실제이며 양수는 과대예측, 음수는 과소예측이다.

| 실제 GDI | 고유 사람 | 기존 편향 | PCA 편향 | MAE: 기존 → PCA |
|---|---:|---:|---:|---:|
| [30,40) | 1 | +33.299937 | +33.300789 | 33.299937 → 33.300789 |
| [40,50) | 7 | +20.086944 | +20.084677 | 20.086944 → 20.084677 |
| [50,60) | 43 | +11.316129 | +11.328734 | 11.685352 → 11.697922 |
| [90,100) | 20 | -16.454465 | -16.466750 | 16.454465 → 16.466750 |
| [100,110) | 5 | -22.900186 | -22.902574 | 22.900186 → 22.902574 |

낮은 점수를 높게, 높은 점수를 낮게 예측하는 경향이 거의 남아 있었다. 학습 사람에서도 비슷한 양상이 유지됐다. 최저 구간은 1명, 최고 구간은 5명으로 표본이 적다는 점도 남긴다.

구간은 기존과 같은 [10k,10(k+1))다. 0~100으로 자르거나 자료를 보고 경계를 바꾸지 않았다. 구간에 임상 이름을 붙이지도 않았다.

![학습·평가 사람의 점수대 편향](01_train_held_band_bias.png)

## 5. 특징을 많이 줄였는데 왜 예측은 비슷했는가

선택된 16~64개 성분이 표준화된 특징 변화의 99.999% 이상을 담았다. 현재 자료에서는 512개 숫자가 서로 독립적으로 크게 변하기보다, 소수 방향으로 함께 변하는 양상이 강했다.

이 비율은 **표준화된 MotionBERT 특징의 변화량**이다. GDI 정보나 움직임의 임상적 의미를 99.999% 보존했다는 뜻은 아니다. 큰 변화 방향을 남겼다는 사실만으로 점수 예측력이 높아지는 것은 아니다.

기존 Ridge가 이미 작은 변화 방향의 영향을 줄이고 있어 PCA를 추가해도 예측이 크게 바뀌지 않았을 가능성이 있다. 이번 결과는 이 설명과 맞지만, 그 원인 비율을 별도로 분리한 것은 아니다.

현재 결론은 이 후보 범위·alpha=1·고정 특징에서 압축을 통한 정확도 개선을 확인하지 못했다는 것이다. PCA나 다른 특징 처리 전반이 무효라고 결론 내리지 않는다. MotionBERT 본체의 계산량이 줄어들었다고 주장하지도 않는다.

## 6. GPU 결과와 연결할 때

점수 예측 결과를 비교할 때에는 `oof_predictions.npz`와 `oof.metadata.json`을 기존 평가기에 바로 연결할 수 있다. 예측은 (203,2,2), 순서는 원본 기록 → front/back → left_GDI/right_GDI다. 사람·영상·fold와 원본 지문을 확인했다.

GPU 특징을 받아 PCA를 다시 학습할 때에는 아래 두 조건을 구분해 보려 한다.

1. GPU 특징 512개 전체 + Ridge(alpha=1): 특징 변경 자체의 효과.
2. 같은 GPU 특징 + 내부 선택 PCA + Ridge(alpha=1): 압축을 추가한 효과.

두 조건은 같은 바깥 학습·평가 사람을 사용한다. 각 fold의 동일 체크포인트에서 얻은 학습 사람의 앞 특징과 평가 사람의 앞·뒤 특징이 최소 입력이다. 학습 사람의 뒤까지 진단하려면 그 특징도 추가로 필요하다. [기존 특징 입력 계약](../artifact_contract.md)을 유지한다.

`run.py`의 choose_k는 바깥 학습 행만 인자로 받으며, pca_design·fit_output·predict를 같은 순서로 재사용할 수 있다. 바깥 평가 사람의 특징이나 GDI를 크기 선택에 넣지 않는다. 새 특징의 표준화·PCA는 그 fold의 학습 특징으로 다시 적합한다.

GPU 본체가 바깥 학습 140명의 정답으로 조정됐다면, 내부 검증 사람의 정보가 이미 특징 생성에 사용됐을 수 있다. 이 경우 내부 점수는 완전한 GPU 파이프라인의 독립 성능이 아니다. 바깥 35명 제외는 유지해야 하며, GPU 본체 설정까지 내부 비교하려면 특징 생성 단계도 내부 분할에 맞춰야 한다. 이번 실험은 GDI 정답으로 조정하지 않은 기존 고정 특징에서 PCA 크기를 선택한 결과다.

실제 GPU 특징이나 결과를 이번에 가정해 계산하지 않았다. 자료·생성 조건을 확인한 뒤 별도 실행할 과제다.

## 7. 검증과 산출물

- 내부 20개 분할의 사람·행을 검사했다. 바깥 평가 사람이 내부 표준화·PCA·Ridge에 들어가지 않았다.
- 내부 80개 후보와 바깥 5개 최종 모델을 별도 sklearn StandardScaler→PCA→Ridge 파이프라인으로 재계산했다. 예측 최대 차이는 내부 약 7.11e-13점, 바깥 약 2.84e-13점이다.
- 내부 예측만으로 크기 선택이 재현되는지 확인했다.
- 저장된 변환과 계수를 재생했다. PCA와 Ridge를 합친 선형식으로도 같은 예측인지 확인했다.
- 학습·평가 전체 8행과 점수대별 64행을 별도 가중치 계산으로 검산했다.
- 원본과 이전 1차·정규화·학습/평가 진단 산출물을 보존했다. 그림 3개를 확인했다.
