# 새 자료의 GDI 정답 연결 검사

## 1단계: 입력과 정답을 연결할 수 있는가

- 질문: 이미 용도를 고정한 새 개발 520명·861건에 좌우 GDI가 하나씩 연결되는가? 최종 평가 예약 223명·378건에는 정답 연결에 필요한 행이 존재하는가?
- 이유: 입력이 준비됐다는 사실만으로 점수 오차를 평가할 수는 없다. 검증 37명에서 설정을 더 고르기 전에 새 자료를 실제로 쓸 수 있는지 확인한다.
- 입력: 봉인된 743명 사람 분리·기록 분리, 기존 입력 준비 장부, 기존 250명 제외 명단, 원본 ZIP 안 annotations/gdi.csv. 원본을 수정하거나 전체 압축을 풀지 않는다.
- 고정 조건: seed=20261027의 개발 520명/최종 예약 223명을 바꾸지 않는다. 입력 준비 완료 기록만 사용한다. Patient_ID·examid·side가 정확히 일치하고 좌우 각각 행이 1개여야 한다. 개발 정답은 유한한 실수여야 한다. 중복 평균, 누락 보간, 임의 범위 자르기를 하지 않는다.
- 정답 보호: CSV 전체를 압축 해제해 메모리에서 읽지만, 기존 250명은 GDI 필드 접근 전에 건너뛴다. 새 최종 예약 자료는 키별 행 수와 비어 있지 않은 필드 수만 센다. 최종 GDI 숫자 변환·값 저장·분포·예측·오차 분석은 하지 않는다. 따라서 최종 예약 자료는 이 단계에서 숫자의 유효성까지 확정된 평가 표본으로 부르지 않는다.
- 검사: 원본 ZIP 멤버 이름·크기·CRC, 입력 장부와 봉인된 분리 파일의 SHA-256, 사람 중복 0, 입력 파일 지문, 기록→사람→검사 연결 일치, 양측 유일성·결측·개발 숫자 유한성. 개인 정답은 팀 공유 문서에 포함하지 않는다.
- 결과물: 개발 정답 연결 목록, 최종 예약 자료의 값 없는 연결 상태 목록, 집계와 쉬운 한국어 보고서, 검사 결과. 이 단계는 새 모델의 정확도 실험이 아니라 평가 표본의 사용 가능성을 확인하는 검사다.
- 후속 판단: 정답이 충분히 연결되면 기존 124장 모델의 조건을 유지한 채 개발 자료 특징을 만들고, 최종 평가를 건드리지 않는 개발 내부 비교를 별도 계획에 먼저 적는다. 연결되지 않으면 원인을 기록하며 기준을 완화하지 않는다.

사용자 요청: 팀 미팅용 기존 실험 정리 후 실험을 계속 진행. 자동 배정기의 과거 선택 대기 기록과 별개인 수동 연구 단위이며 감독 프로그램·운영 설정·과거 증거를 바꾸지 않는다.
