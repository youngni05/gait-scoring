## 전체 연구는 무엇을 하려는가

목적은 영상에서 얻은 움직임으로 GDI라는 보행 관련 수치를 추정하고, 기존 방식보다 나은 부분이 있는지 확인하는 것이다. 현재 구현해 비교한 흐름은 **관절 좌표 → 고정 AI가 움직임을 숫자로 요약 → Ridge가 좌우 GDI 예측 → 정답과 오차 비교**다. 영상 업로드·관절 추정부터 앱 결과 표시까지의 전체 제품 검증은 아직 아니다. 1~5점 경계나 낙상·진단 기준도 정하지 않았다.

처음에는 기존 결과가 재현되는지 확인했다. 이후 사람별 기록 수의 영향, 시간·좌우 정보, 무릎 요약을 비교했다. 가장 최근에는 입력을243장에서124장으로 줄였다. 같은 검증 자료에 설정을 계속 맞추기보다 다른 사람을 분리할 준비가 가능한지 확인하는 단계로 넘어왔다. AI 가중치를 다시 배우는 파인튜닝은 하지 않았다.

## 다음에는 무엇을 하며 왜 그 방향인가

입력 검사가 모두 끝났다. 다음 점수 실험 전 새 사람의 GDI 정답 연결·개봉 범위와 독립 평가 대상·동일 입력의 비교 기준을 사용자와 검토한다. 준비된 입력을 자동으로 학습/평가에 배정하거나 기존 평가38명을 재사용하지 않는다.

입력 준비는 정답 연결이나 점수 성능 검증과 다르다. 기존243장이 준비되지 않는 자료에서는 공정한 직접 점수 비교 범위도 검토해야 한다. 실제 독립 평가의 대상·정답 개봉·판정 기준은 자동 실행 전에 사용자 검토 대상으로 남겼다.

사용자가 검토할 두 안은 다음과 같다.

| 선택지 | 목적과 제약 |
|---|---|
| A. 현재124 모델을 고정해 새 사람에서 검증 | 추가 학습 없이 현재 후보의 오차를 확인한다. 결과를 본 사람을 다시 조정에 쓰지 않으며, 기존243장보다 정확하다는 직접 비교가 되지는 않는다. |
| B. 새 사람을 개발용·최종 평가용으로 먼저 분리 | 추가 학습·파인튜닝을 연구할 여지를 남긴다. 정답 개봉 전에 사람 분리와 비교 계획을 정해야 한다. |

빠르게 현재 모델의 성능을 확인하려면 A의 평가 계획을, 추가 학습이 우선이면 B의 분리 계획을 먼저 검토한다. 두 안 모두 제안 단계이며 실행하지 않았다.


목록과 완료 증거의 지문을 확인한 뒤 결과를 누적한다. 기록 수와 새 사람 수,124 입력 준비와 정답 연결, 특징 저장과 점수 평가를 구분한다. 실제 독립 평가의 대상·사람 분리·정답 개봉·최종 판정 기준은 사용자가 검토할 선택으로 남긴다. 같은 검증37명의alpha·구간·관절을 계속 바꾸는 탐색은 진행하지 않는다.

## 기록과 자동 실행을 어떻게 읽는가

이 문서의 첫 부분·최신 입력 표·점수 비교 표·다음 목표만 읽어도 현재 판단을 파악할 수 있다. 각 실행의 계획과 보고에는 질문·선택 이유·실패·실제 검사·한계가 있고 보존본과 수치 파일은 덮어쓰지 않는다. 과거 보고서의 상태는 당시 시점의 기록이다.

자동 실행은1시간 간격으로 확인하고, 한 실행 최대30분 안에서 연결된 작업을 이어간다. 각 단계 사이에 사용량을 확인해 어느 한도든80% 이상이면 중단한다. 컴퓨터와Codex 앱이 켜져 있어야 하며 정확히 매시 시작을 보장하지는 않는다. Pro CLI 차단을 우회하거나 계정을 자동 교대하지 않는다. [운영 안내](AUTOMATION_SETUP.md)에 켜기·끄기 방법이 있다.

이번에는 새 배정 확인 → 미처리 입력·원시 재현 → 기록과 사람 집계 → 다음 단계 검토 항목 정리 → 보고 보존을 이어갔다. 남은 입력1050건의 실제 검사와88묶음 원시 재현을 마쳐 미처리가0건이다. 사용량 최대34%로 여유가 있지만, 새 사람을 검증 전용으로 쓸지 추가 학습과 최종 평가용으로 나눌지 사용자 검토가 필요한 단계에 도달해 종료한다. 앞선 실행의 시간 보호 중단·새 입력0건과 원인 미확인 사실은 [이전 실패 기록](control/desktop-sessions/20261027T055238Z-44667b/report.md)에 보존했다. 전체 연구 완료가 아니다.
