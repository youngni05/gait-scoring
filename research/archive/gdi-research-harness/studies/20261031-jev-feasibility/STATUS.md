# Jev 보행 예측 가능성 예비실험 — 2026-10-31

**2,040건의 Jev 응답을 수집하고 요청·분할·오차 검산을 통과했다. 이번 입력과 질문에서는 기존 수치 특징에 Jev 판단을 추가해도 TUG·GDI 예측이 뚜렷하게 개선됐다는 근거를 얻지 못했다.** 일부 보조 모델의 작은 개선과 모든 Jev 방식의 가능성을 구분한다. 검산 근거는 `verification.json`이다.

## 무엇을 비교했는가

보행 특징 → Jev의 좌우 차이·불규칙성·움직임 제한·몸통 움직임·측정 문제 판단 → 실제 점수를 학습한 예측 모델의 흐름이다. Jev 자체를 추가 학습하지 않았다. Jev 판단은 전문가가 붙인 움직임 정답이 아니며, 그 판단의 정확성은 별도로 검증하지 않았다.

- **TUG:** 기존 OpenCap 195명의 6초 직선 보행 특징 17개와 별도 검사에서 기록된 실제 TUG 시간이다. 여러 카메라에서 복원한 3D 기반 값이며 단일 카메라 검증이 아니다. 기존 자료에서 제외한 sub-283은 다시 포함하지 않았다.
- **GDI:** 기존 개발 자료 695명·1,064기록의 앞 124프레임 2D 좌표를 이용했다. 사람마다 관측 가능한 좌표 변화·투영 무릎 각도·추적 품질을 요약했다. 정답은 **사람별 모든 기록과 좌우 GDI의 평균**이다. 기존 연구의 좌우·기록별 오차를 먼저 평균한 지표와 다르므로 기존 7.6점대 수치와 직접 비교하지 않는다. 보호된 평가 자료는 사용하지 않았다.
- TUG는 기존 다섯 반복 분할 중 첫 번째, GDI는 기존 사람별 5분할을 유지했다. 매번 평가 사람을 빼고 나머지 사람으로만 예측 모델을 학습했다. 결측 보충과 표준화도 학습 사람 안에서 수행했다.
- RF는 나무 128개·잎 최소 인원 5·난수 20261031, Ridge는 규제값 10으로 고정했다. Jev 추가 전후 설정은 같다. 평가 결과를 보고 설정을 고르지 않았다. 기존 튜닝 RF와 PLS는 별도 참고값이다.

| 비교 | 적용 범위 | 확인하려는 내용 |
|---|---:|---|
| 숫자 요약 / 같은 수치를 문장으로 표현 | TUG195명·GDI695명 전원 | 입력 표현에 따른 차이 |
| 수치만 / Jev 판단만 / 둘을 함께 사용 | 같은 사람·같은 분할 | Jev 판단의 추가 예측 정보 |
| 점수 구간 직접 선택 | 모든 요청 | Jev가 점수 구간을 제시할 수 있는가 |
| 요약에 짧은 시계열 추가 | 자료별 25명 | 시간 순서 정보의 영향 |
| 가까운 학습 사례 6개와 점수 제공 | 자료별 25명 | 정답 예시가 있을 때의 반응 |
| 동일 요청 반복 / 선택지 역순 / 1.13과 1.14 | 자료별 25명 | 응답의 안정성과 버전 차이 |
| 관측 전부 없음 | 자료별 5회 | 근거가 없을 때 보류하는가 |

부분집합은 정답을 보지 않고 사람 식별자의 해시 순서로 선택했다. 학습 사례는 평가 사람과 다른 분할에서만 찾았다. 주요 입력은 다른 사람의 특징이나 정답에 의존하지 않는다. 문장 입력은 수치를 정해진 영어 문장으로 바꾼 것이며 **별도 영상 설명 모델이 생성한 설명은 아니다.**

## 예측 결과

사람별 평균절대오차(MAE)이며 작을수록 좋다. TUG 단위는 초, GDI 단위는 점이다.

| 방법 | TUG195명 | GDI695명 |
|---|---:|---:|
| 학습 사람 중앙값 | 2.743 | 8.905 |
| 수치만 사용하는 RF | 2.291 | 7.044 |
| RF + 숫자 입력 Jev 판단 | 2.287 | 7.043 |
| RF + 문장 입력 Jev 판단 | 2.263 | 7.066 |
| 숫자 입력 Jev 판단만 사용하는 RF | 2.514 | 8.209 |
| 문장 입력 Jev 판단만 사용하는 RF | 2.491 | 8.025 |
| 수치만 사용하는 Ridge | 2.499 | 7.035 |
| Ridge + 숫자 입력 Jev 판단 | 2.561 | 6.878 |
| Ridge + 문장 입력 Jev 판단 | 2.474 | 6.969 |
| 기존 튜닝 RF / 기존 PLS를 같은 사람 지표로 계산 | 2.309 | 6.479 |

주분석 RF의 오차 차이(추가−기존)와 조건부 95% 구간은 다음과 같다. 음수면 오차 감소다.

- TUG 숫자: −0.004초 [−0.049, +0.040], 문장: −0.028초 [−0.082, +0.028].
- GDI 숫자: −0.001점 [−0.112, +0.115], 문장: +0.022점 [−0.082, +0.124].
- 보조 분석 GDI Ridge 숫자는 −0.157점 [−0.320, +0.008]이었다. 기존 PLS보다 좋은 결과는 아니었다.

모두 0을 포함한다. 구간은 저장된 사람별 예측의 오차 차이를 10,000회 재추출한 탐색적 구간이며, 새 자료·모델 재학습·여러 분석 중 선택의 불확실성을 모두 포함하지 않는다. 이번에는 반복 분할 하나만 평가했다.

긴 TUG(20초 이상 8명)의 RF 오차는 9.985→9.718초(숫자)·9.574초(문장)로 조금 줄었으나 큰 오차가 남았다. 낮은 GDI(60점 미만)의 RF 오차는 12.954→13.241점·13.195점으로 늘었다. 이 구분은 오차 분석용이며 임상 판정 기준이 아니다.

## 직접 점수 판단과 안정성

- TUG는 숫자·문장 입력 각각 195명 전원에서 점수 판단을 보류했다. 시계열·학습 사례 추가도 각각 25명 전원에서 보류했다. **이번 질문 조건에서 답을 얻지 못했다는 결과이며, 프롬프트와 무관한 불가능 판정이 아니다.**
- GDI 숫자 입력은 695명 중 2명만 구간을 선택했고 둘 다 실제 구간과 달랐다. 문장 입력은 전원 보류했다. 시계열 추가 25명도 전원 보류했다.
- GDI 학습 사례 추가 25명은 모두 구간을 선택했다. 구간 중앙값으로 근사한 오차는 8.940점, 같은 25명의 수치 RF는 8.663점이었다. 응답 수집 후 추가한 진단 대조군인 **같은 학습 사례 6개의 점수 중앙값**은 8.726점이었다. 사례 대조군은 사전에 정한 주분석 모델이 아니다.
- 직접 점수 방식의 보류는 학습 사람 중앙값으로 대체한 전체 오차와 답한 사람만의 오차·응답 비율을 따로 기록했다. 구간 중앙값은 연속 점수의 정밀한 예측이 아니며 확률을 보간해 점수로 만들지 않았다.
- 동일 입력을 다시 보냈을 때 일부 움직임 판단은 바뀌었다. TUG 불규칙성 선택 일치율은 84%, GDI 좌우 차이는 88%였다. 선택지 순서를 뒤집으면 TUG 불규칙성은 72%, GDI 좌우 차이는 76%로 낮아졌다. 각 수치는 25명에 대한 탐색 비교다.
- 관측 없는 요청은 자료별 5회 모두 점수 판단을 보류했다. 이들은 같은 결측 상태를 반복한 것이므로 10개의 독립 상황 검증으로 해석하지 않는다.

## 실행·검산과 남은 범위

Jev1.14를 기본으로 하고 부분집합에서 기존1.13과 비교했다. 참가자 자료 요청은 2,040건, 오류는 0건, 입력은 3,678,454토큰이었다. [공시 단가](https://docs.typesafe.ai/models) 기준 입력 비용은 약 0.1545달러다. 별도의 합성 연결 확인 1건은 333토큰이며 이 합계에 포함하지 않았다. 실제 청구 내역을 조회한 값은 아니다.

사용자의 외부 전송 범위 확인 후 진행했다. 이름·식별자·영상·파일명은 요청에 포함하지 않았다. 일부 비교에서 다른 분할의 학습 사례 특징과 점수를 제공했다. API 키는 기존 환경 파일에서 메모리로만 읽으며 요청 결과에 저장하지 않았다.

`test_study.py`의 정답 누출·다른 사람 입력 의존·숫자와 문장의 정보 일치·선택지 순서·잘못된 응답 거부 검사 5개를 통과했다. `verify.py`로 요청 2,040개의 본문 지문을 재생성하고, 원본 파일 지문·사람 분할·예측 방법 28개 묶음의 오차 계산을 확인했다. 모델 전체의 독립 재학습 재현이나 실제 영상에서 움직임 판단의 정확도 검증은 수행하지 않았다.

현재 결과는 **같은 수치를 Jev로 다시 판단하게 하는 경로의 추가 가치가 작았다**는 예비 근거다. 영상에서 새 관측을 추출하는 설명 모델, 이미지 입력, 원래 좌우별 GDI 목표에 대한 강한 모델과의 결합은 이번 범위에 포함되지 않았다. 그 가능성까지 부정하거나 기존 예측 모델을 교체하는 결론을 내리지 않는다.

재실행 경로: `study.py prepare` → `test_study.py` → 승인된 범위의 `study.py run` → `evaluate.py` → `verify.py`. 준비 파일은 덮어쓰지 않으며 응답은 완료된 요청을 건너뛰어 이어서 수집한다. 전체 조건·결과·통제 비교는 `protocol.json`, `results.json`, `controls.json`, 검산은 `verification.json`에 남긴다.
