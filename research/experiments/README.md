두 행의 ‘지금 할 일’은 병렬로 진행할 수 있다. 사람 판독처럼 담당자가 수행할 작업은 ‘지금 할 일’에 쓴다. ‘사람이 결정할 일’에는 비교 기준이나 연구 방향을 선택해야 하는 질문을 적는다.

### 새 실험을 등록하거나 이어받을 때

1. 질문·자료·비교 조건을 기존 실험 및 열린 등록 PR과 대조한다. 진행 중인 실험은 담당과 다음 단계를 확인하고 이어받는다. 같은 자료를 다시 쓰는 실험은 새로 확인할 차이를 적는다.
2. 실행 전에 이 표에 행을 추가하고 `<실험 ID>.md`에 질문 번호, 담당, 시작일, 선행 실험, 자료와 비교 조건, 원본 파일 위치를 기록한다. 질문 페이지에도 같은 상세 기록으로 연결되는 **진행 중** 한 줄을 남긴다. 등록 변경이 최신 `main`에 반영된 것을 확인한 뒤 실행한다.
3. 다른 모델이 이어받을 수 있도록 상세 파일에 집계 결과, 검산 여부, 남은 작업과 원본 위치를 갱신한다. 개인별 자료와 대용량 파일은 기존 보관 위치에 둔다.
4. 시작·중간 결과·보류·재개·완료 때 이 표의 현재 상태와 상세 기록을 맞추고 질문 페이지에 날짜와 한 줄 요약을 남긴다. 보류하면 재개 조건을, 완료하면 확인 범위를 쓴다. 주요 답이 달라지면 [연구 목차](../README.md)도 갱신한다.

### 여러 실험을 동시에 운영할 때

- 운영 담당은 각 실험에서 바로 할 일과 먼저 필요한 자료·실험 ID를 적는다. 선행 결과가 준비된 작업끼리 배정하고, 기다리는 단계에는 무엇이 도착하면 시작할지 적는다. 같은 조건의 재현은 기존 실험에 검산으로 연결한다.
- 실행 담당은 사용한 입력·코드 버전·비교 기준과 결과 파일을 상세 기록에 남긴다. 검산 담당은 같은 조건에서 재계산해 일치 여부와 확인 범위를 적는다. 저장값 대조, 독립 재실행, 실제 정답과의 비교 중 무엇을 확인했는지 표에도 짧게 쓴다.
- 운영 담당은 합의된 기준 안의 후속 작업을 이어간다. 기준 변경, 검산 불일치의 해석, 주요 질문의 답을 바꿀 판단이 필요하면 사람이 결정할 한 문장과 근거 링크를 남긴다. 결정되면 상세 기록에 결론을 보존하고 표를 갱신한다.
- 운영 방식의 효율을 비교할 때는 묶음별로 같은 기간·연산 예산에서 검산을 마친 서로 다른 질문 수와 사람이 결과 확인에 쓴 시간을 함께 기록한다. 시간 기록이 없으면 ‘미기록’으로 둔다.
