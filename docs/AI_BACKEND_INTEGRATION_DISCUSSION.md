# 백엔드–AI 모듈 연동 협의 요청

작성일: 2026-11-20 · 상태: 협의용 초안

대상: AI·백엔드·프론트엔드 담당자

이 문서는 기존 서비스 요구사항과 2026-11-20에 확인한 GitHub AI 모듈을 기준으로 연동 결정을 요청하는 문서입니다. **확정된 서비스 요구사항, 확인된 모듈 현황, 협의가 필요한 항목을 구분합니다.** 제안은 합의 전까지 구현 계약으로 취급하지 않습니다. 문서 작성만으로 코드·DB·API 계약을 변경하지 않습니다.

## 1. 확정된 서비스 요구사항

2026-11-20 변경: 촬영 시각 대신 분석한 날짜를 저장한다.
분석 시작일과 해당 날짜의 만 나이를 사용하도록 확정·구현했다. 날짜 표시와 나이 계산은 한국 시간 기준이다.
세부 내용은 [AI 연동 규격 초안의 날짜 요구사항 변경](AI_INTEGRATION_SPEC_DRAFT.md#2026-11-20-날짜-요구사항-변경)을 따른다.

| 항목 | 확정 내용 |
| --- | --- |
| 영상 처리 | 앱에서 영상을 선택하고 클라이언트에서 관절 좌표 추출 |
| 서버 전송·보관 | 서버에는 좌표 JSON만 전송. 앱과 서버에서 원본 영상을 별도로 영구 저장하지 않음 |
| 인증·접근 | 로그인한 복지사는 모든 어르신과 촬영·분석 기록에 접근. 등록자·측정자는 기록하되 담당자별 접근 제한에 사용하지 않음 |
| 어르신 정보 | 신규 등록 시 성별(남/녀), 생년월일, 키 필수. 기존 데이터의 신규 컬럼 NULL은 허용 |
| 촬영 관계 | 어르신 1명에게 여러 촬영 기록 연결 가능 |
| 결과 관계 | 촬영 1건당 최종 결과 최대 1건. 동일 촬영의 여러 재분석 결과를 관리하지 않음 |
| 조회 흐름 | 어르신 선택 → 촬영 목록 → 촬영별 결과지 |
| 기록 날짜 | 촬영 시각은 저장하지 않고 분석한 날짜를 저장·표시. 촬영 시각 메타데이터를 필수로 요구하지 않음 |
| 결과지 나이 | 한국 시간 기준 분석 시작일의 만 나이를 서버에서 계산·보존 |
| 결과지 키 | 현재 어르신 정보에 등록된 키 표시 |
| 보행 지표 | 연구용 GDI 추정 점수, 평균 `stride_length_cm`(cm), `cadence_spm`(분당 걸음 수) |
| 그래프 | 고관절·무릎·발목 그래프 제공 목표. JSON 세부 구조는 미확정 |
| 일부 지표 산출 실패 | 미산출 지표는 NULL로 저장하고 결과 화면에서 숨김. 산출된 지표만 표시 |
| 버전 기록 | 좌표 추출기 이름·버전과 분석 모델 버전 저장 |
| GDI 의미 | 임상 진단값이 아닌 연구용 추정값 |

결과지에 표시할 현재 키와, AI가 계산에 사용할 키의 기준 시점은 별개입니다. 키가 분석 입력에 필요하다면 입력 시점과 보존 방법을 협의해야 합니다.

## 2. GitHub에서 확인한 AI 모듈 현황

확인 대상은 `codex/ai-module-integration-20261119` 브랜치의 `ai-module/`입니다. 확인 시점에 해당 패키지는 main에 병합되지 않았습니다. 다음은 코드·문서 확인 결과이며, 이번 조사에서 모델 실행이나 압축파일 내부 검증은 수행하지 않았습니다.

| 구분 | 확인한 내용 |
| --- | --- |
| 실행 서버 | 별도 Python HTTP 서버, 기본 주소 `127.0.0.1:8877`. 로그인·DB 저장 기능 없음 |
| API | `GET /health`, `POST /v1/analyze`, `POST /v1/compare-history` |
| 입력 | 앱의 `coords-1`과 AI의 `measurement-pose/1` 사이에 형식 차이 존재 |
| 분석 기능 | 보행 후보 구간·진행 방향 검출, 무릎 지표·곡선, Cadence·걸음 시간 계산 코드 |
| GDI | `gdi_adapter.py`가 별도 연구 코드·가중치·보정 파일에 의존. 모델별·좌우별·구간별 출력 구조 |
| 부분 실패 | `complete`, `partial`, `unavailable` 및 지표별 NULL·불가 사유 표현 |
| 합성 데이터 | 분석 요청과 방문 이력 비교용 fixture 제공 |
| 가중치 | 별도 Release에 고정54개·정상100 추가75개 모델의 추론용 가중치 게시 |
| 재현 상태 | README는 Release와 패키지만으로 전체 GDI 추론을 재현하는 절차가 아직 검증되지 않았다고 명시 |
| 미확인 기능 | 확인한 걸음 계산 코드에 평균 stride 길이 계산은 없음. 고관절·발목 그래프 전체 구현도 확인되지 않음 |

main에 병합된 GDI 입력 호환성 검토·후보 좌표 변환 코드는 별도 작업입니다. 후보 변환의 `readyForInference: false`는 실제 추론 준비가 완료되지 않았음을 나타냅니다.

## 3. 협의 필요: 좌표 입력 규격

| 결정할 항목 | AI 담당자와 확인할 내용 |
| --- | --- |
| 변환 책임 | 앱이 AI 규격을 직접 생성할지, 백엔드가 `coords-1`에서 변환할지 |
| 관절 구성 | 현재 `[x, y, z, visibility]`와 AI의 `[x, y, z, visibility, presence]` 차이. presence 미제공 시 NULL 처리·분석 영향 |
| 시간·프레임 | 원본 프레임 번호·시각, 단위(ms), 시간 기준, 프레임 누락·간격 보존 방식 |
| 좌표·영상 방향 | 정규화 좌표와 영상 크기, 회전 보정, 반전 여부, 해부학적 좌우 보장 단계 |
| 미검출 | 프레임을 보존하고 landmarks를 NULL로 전달하는 방식과 허용 기준 |
| 추출기·추적 정보 | 모델·버전·해시·설정·실행 환경·tracking 이력 중 필수 필드와 unknown 허용 범위 |
| 입력 제한 | 허용 촬영 길이·용량·프레임 수·촬영 조건과 제한 초과 시 동작 |
| 추가 신체 정보 | 키 등이 필요한지, 필요한 경우 촬영 당시 값의 확보·보존 방식 |

**백엔드 제안 — 미확정:** 입력 기준 규격을 하나로 정하고 백엔드는 필요한 형식 변환만 수행합니다. 확보하지 못한 값을 임의의 0이나 1로 채우지 않습니다. 프레임 보간·재표본화·좌우 교환은 AI가 승인한 처리만 적용합니다.

## 4. 협의 필요: GDI 실행 환경과 재현성

AI 담당자에게 아래 자료를 요청합니다.

- 서비스에서 사용할 최종 모델과 선택 이유: baseline, normal100 또는 별도 선택
- 필요한 가중치·연구 코드·보정 파일의 정확한 목록, 버전·해시, 확보 경로
- 개인 PC의 절대 경로에 의존하지 않는 실행 절차
- Python·전체 의존성·CPU/GPU·메모리 요구사항과 사용 조건
- 고정 입력, 예상 출력, 수치 비교 허용 오차
- MediaPipe→학습 관절 매핑, 누락 보간, 프레임 선택·샘플링 방식의 검증 범위
- 실패를 재현할 수 있는 입력과 기대 오류·불가 사유

Release의 모델 전체 개수와 서비스가 실제 선택하는 구성은 구분해 확정해야 합니다. 가중치 파일이 있다는 사실만으로 서비스 실행 환경이 완성된 것으로 보지 않습니다.

**완료 기준 제안 — 미확정:** 별도 환경에서 안내된 파일과 절차만으로 고정 입력의 예상 결과를 재현합니다.

## 5. 협의 필요: GDI 결과 매핑

현재 서비스의 `gdi_score`와 AI의 모델별·좌우별·구간별 결과를 어떻게 연결할지 결정해야 합니다.

| 항목 | 결정할 내용 |
| --- | --- |
| 대표 점수 | 단일 점수를 유지할지, 좌우별 결과를 표시하도록 서비스 계약을 변경할지 |
| 모델 | 결과지에 사용할 모델 또는 조합과 버전 식별법 |
| 구간 집계 | 여러 보행 구간을 촬영 대표 결과로 만드는 방식과 가중치 |
| 진행 방향 | 방향별 결과 선택·표시·집계 기준 |
| 부분 성공 | 한쪽 또는 일부 구간만 성공했을 때 제공할 값 |
| 숫자 표현 | 단위·소수점 자릿수·유효성 기준 |

**백엔드 제안 — 미확정:** 임의로 좌우 평균을 내거나 점수를 0~100으로 제한하지 않고 AI 담당자가 정의한 규칙을 적용합니다. 여러 내부 구간 결과가 있어도 촬영 1건의 결과지로 묶습니다. 좌우별 표시가 필요하면 기존 서비스·DB·API 계약 변경을 별도로 합의합니다.

## 6. 협의 필요: 평균 보폭·Cadence·그래프

| 지표 | 확인·결정할 내용 |
| --- | --- |
| 평균 `stride_length_cm` | 동일 발의 연속 착지 사이 거리인 stride를 뜻하는지 확인. cm 환산 방법, 키·보정 정보 필요 여부, 유효 stride 선택·평균 기준 |
| `cadence_spm` | 최소 유효 걸음 수, 여러 구간의 촬영 대표값 집계 방식 |
| 무릎 그래프 | 현재 곡선 중 서비스에 사용할 값, 각도 정의·단위 |
| 고관절·발목 그래프 | 제공 가능 여부, 계산 방법, 제공 일정 |
| 공통 JSON | X축(시간 또는 보행 주기 %), Y축·단위, 좌우 구분, 표본 수, 결측값 표현 |

**요청:** 실제 출력 가능한 그래프 JSON 예시를 공유해 주세요. 세부 규격은 해당 예시를 기준으로 프론트와 함께 확정합니다. 평균 stride 계산에 필요한 정보가 좌표만으로 부족하면 추가 촬영·보정 조건을 명시해 주세요.

## 7. 협의 필요: 부분 성공·실패와 저장

미산출 지표를 NULL로 저장하고 화면에서 숨기는 것은 확정 사항입니다. 아래 운영·저장 규칙은 별도 협의가 필요합니다.

- AI의 `complete`, `partial`, `unavailable`과 서비스의 결과 존재 여부·처리 상태를 구분하는 방법
- 지표별 불가 사유 코드와 의미, 재시도 가능 여부
- 모든 지표가 산출 불가한 촬영의 결과지 상태·문구
- 입력 검증 실패, 데이터 품질로 인한 분석 불가, 서버 장애의 구분
- 처리 중·실패 상태의 저장 위치와 최종 결과 행 생성 시점
- 모델·전처리·응답 규격 버전 등 재현에 필요한 메타데이터
- AI 전체 응답 보존 여부와 화면용 필드 매핑 범위
- 예상하지 못한 응답·비유한 숫자·규격 버전 불일치의 처리

**백엔드 제안 — 미확정:** 값이 없는 경우 JSON null을 사용하고 실제 0과 구분합니다. 화면에 지표를 숨기더라도 산출 불가 사유는 저장합니다. 성공 응답이라도 HTTP 상태 코드만 보고 모든 지표가 산출된 것으로 판단하지 않습니다.

## 9. 우선 전달받을 자료와 협의 순서

1. 실제 GDI까지 실행 가능한 파일 목록·패키지와 설치·실행 절차
2. 최종 입력 JSON 예시와 필수 메타데이터 목록
3. 전체 성공·부분 성공·전체 산출 불가 응답 예시
4. 서비스용 GDI 선택·좌우·구간 집계 규칙
5. 평균 stride 길이와 고관절·발목 그래프 제공 여부·일정
6. 처리 시간·동시성·실행 자원

**진행 순서 제안 — 미확정:** 촬영 1건의 분석·저장·조회 연결을 먼저 완료하고, 업로드된 과거 이력 비교 API는 별도 범위로 협의합니다. 이력 비교의 기준 방문·동일 인물 식별·비교 가능 조건·집계 방식도 이후 명시해야 합니다.
