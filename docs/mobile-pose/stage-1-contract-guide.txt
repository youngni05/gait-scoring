  import { validateCoords } from './contracts/coords-1/validate';
  const result = validateCoords(parsedJson, {
    expectedSubjectId: serverSubjectId,
    durationSeconds: decodedDurationSeconds,
  });
  if (!result.ok) console.log(result.issues);

민감한 좌표 전체를 제품 로그에 출력하지 말 것.
검증기는 입력을 수정/반올림/보간하지 않음. 직렬화 전에 실행해야 함.
NaN/Infinity는 JSON.stringify가 null로 바꾸기 전에 거부해야 함.

계약 규칙
- 성공 프레임은 MediaPipe 순서 33관절, 각 관절 [x,y,z,visibility].
- x/y는 비율 좌표이며 화면 밖 값도 허용. z는 상대 깊이이며 미터가 아님.
- visibility는 0..1. 원본을 자르거나 다른 신뢰도로 대체하지 않음.
- frames 최소 60개. t는 초, 0 이상, 엄격하게 증가. 고정 FPS 강제 없음.
- 프레임 미검출은 lm:null. 모든 lm이 null이어도 형식 검증은 통과 가능하며
  이는 분석 가능성/품질/임상 정확도를 뜻하지 않음.
- 키 100..220cm, ID는 비어 있지 않은 문자열. 실제 서버 발급 여부와
  소유권/인증은 서버 책임. UUID를 subject ID에 강제하지 않음.
- recorded_at은 시간대 포함 날짜/시각. 로컬 검증은 RFC3339 date-time 사용.
- width/height는 회전 적용 후 양의 정수. orientation은 허용 열거값 검사.
- marks는 둘 다 null이거나 0 <= 시작 < 끝. durationSeconds를 주면 실제
  영상 길이를 상한으로 검사하며 마지막 프레임도 그 안에 있어야 함.
  길이를 주지 않으면 마지막 관측 프레임 시각을 보수적인 상한으로 사용함.
- capture.mode는 기존 계약 호환용 guided/fixed 모두 검사. MVP 생성은 guided.
- 좌표 소수점 최대 5자리 직렬화는 6단계 구현 사항. 검증기는 추출 원본의
  추가 자릿수를 손상시키지 않음. 시간 정밀도는 별도 보존.

로컬 구현 정책과 미정 사항
- 알 수 없는 필드는 로컬에서 거부하여 제안 메타데이터의 본문 혼입을 방지함.
  이것을 서버의 추가 필드 정책으로 확정하지 않았음. 소비자 승인 필요.
- 촬영일 출처·회전·검출 상태/사유/버전·모델 자산 버전은 ProcessingMetadata.
- 모델·모델 자산·tasks-vision 버전·delegate는 아직 선정/설치하지 않음.
- 합성 샘플의 모델 이름은 형식 예시일 뿐 선택 결정이 아님.
- 실제 API URL, 토큰, 응답 형식, 확장 필드 수용 여부는 미정.

모듈 경계 (ports.ts는 내부 연결 초안이며 HTTP 계약이 아님)
1. VideoSource
   로컬 선택 핸들과 AbortSignal -> VideoSession(info, frames, dispose).
   순차 디코딩·회전 적용·실제 표시 시각·자원 정리 책임.
   DecodedFrame.pixels는 어댑터가 정의할 불투명 핸들. 프레임 사용 후 release,
   성공/취소/실패 모두 finally에서 session.dispose를 호출할 예정.
2. PoseExtractor
   DecodedFrame과 AbortSignal -> 원본 시각의 PoseFrame 또는 lm:null.
   실제 모델/엔진/delegate 설정 노출. 취소는 오류, 검출 실패 null과 구별.
   인증·DB·UI를 알지 않으며 추출 후 입력 프레임 자원은 호출자가 해제.
3. StandDetector
   원본 PoseFrame 배열, 영상 길이, AbortSignal -> StandDetection.
   detected 또는 not_detected; 실패 시 marks 둘 다 null 및 사유 제공.
   내부 오류/취소는 예외로 분리. 원본 좌표 수정 금지. 알고리즘은 5단계.
4. CoordsSerializer
   서버 입력(subjectId,heightCm,recordedAt,출처), 영상 메타정보, 좌표, marks
   -> 검증 결과 및 JSON 문자열. recordingId는 선택 건 생성 시 부여·재사용.
   생성/반올림 구현은 6단계. 출처 등의 로컬 정보는 본문에 넣지 않음.
5. UploadGateway
   coords, 별도 metadata, requestId, AbortSignal -> 내부 접수 결과.
   접수 ID와 mock/server 구별은 내부 포트 설계이며 서버 응답 형식 아님.
   인증 주입은 향후 어댑터 구성 단계에 한정. 영상 모듈로 토큰 전달 금지.
   재시도 시 recording_id/requestId 유지. 접수는 분석 완료와 다름.
   실제 HTTP 전송에서 metadata를 보낼지는 서버 계약 승인 후 결정.
