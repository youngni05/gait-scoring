3단계 보강: 전체 프레임 오프라인 추출 검증
확인일: 2026-11-16 / 개발 빌드 0.3.1 (Android versionCode 4)
이 기록이 stage-3-verification.txt의 재생 관측 방식 및 누락 한계를 대체한다.
사용자 요청대로 4단계 MediaPipe 영상 관절 추출과 갤럭시 실기기 시험은 수행하지 않았다.

구현과 지원 범위
- mediabunny 1.66.0 고정. 로컬 BlobSource → MP4 demux → WebCodecs VideoSampleSink 순차 디코딩.
- HTML video는 미리보기 전용. play/seek/requestVideoFrameCallback에 의존하지 않는다.
- 현재 지원 범위는 MP4의 기본 비디오 트랙 H.264(AVC), 해당 환경에서 canDecode가 성공하는 파일.
- 파일 패킷의 PTS를 전부 수집해 표시 순서로 정렬한다. 출력마다 해당 PTS와 대조한다.
- WebCodecs 마이크로초 반올림을 고려한 비교 허용 오차 1.1us. 반환 t는 파일의 원본 PTS(초)를 보존한다.
- 빈 목록, 음수/중복 시각, 출력 누락/추가/순서 오류, 프레임 크기 변경은 오류로 처리한다.
- 전체 개수와 모든 시각이 일치한 정상 종료에서만 complete=true. 취소/오류/조기 반복 종료는 성공이 아니다.
- 캔버스 한 개를 재사용하고 샘플은 매 반복 finally에서 close. 입력은 종료 finally에서 dispose.
- 이미지는 전체 누적하지 않는다. PTS 목록만 O(N) 메모리를 사용하며 라이브러리에는 제한된 선행 디코딩 버퍼가 있다.
- 취소는 입력을 dispose하고 재시작은 새 입력/디코더를 만든다. 재선택/해제는 미리보기와 blob URL도 해제한다.
- 원본 영상, 프레임 이미지, 좌표를 서버로 보내거나 저장하는 기능은 추가하지 않았다.

PC 실측 검증
독립 기준: Python PyAV로 합성 MP4를 다시 디코딩하여 모든 PTS를 expected.json으로 기록.
각 영상의 전체 캔버스 프레임에서 움직이는 빨간 도형의 위치도 검사(중심 허용 오차 1px).
검증 화면: http://127.0.0.1:5173/offline-qa.html
아래 각각 일반 처리와 프레임당 40ms 지연 처리 모두 통과:
  landscape: 180/180, 첫 0초, 끝 5.966666666666667초, B-frame 131개
  portrait:   90/90, 첫 0초, 끝 2.966666666666667초, B-frame 66개
  variable:   90/90, 첫 0초, 끝 4.433333333333334초, B-frame 65개
  high-fps:  300/300, 120fps, 첫 0초, 끝 2.4916666666666667초
모든 프레임 PTS의 PyAV 정답 대비 최대 오차 = 0초.
모든 프레임 도형 위치 검사 통과. RGB 전체 비트 일치 검사는 아니며 코덱 색 변환 차이는 허용한다.
모든 영상에서 5프레임 후 취소 → 미완료 확인 → 같은 세션 재시작 → 전체 개수 일치.
추가 통과: 열기 즉시 취소, 대기 중 세션 dispose, 중복 dispose, 동시 반복 거절,
반복기 조기 return 후 재시작, 손상 파일 거절, 미리보기 DOM 정리.
실제 사용자 화면에서도 variable.mp4 선택 → 90/90 → 전체 프레임 검증 완료 표시 확인.

자동 검사
npm test: 76개 통과, 실패/건너뜀 0.
기존 81개에서 재생 콜백 전용 시험을 제거하고 오프라인 완전성 검사를 추가했으므로 개수 감소는 검사 실패가 아니다.
누락, 추가, 중복, 시각 오차, 비정상 원본 목록, 부분 완료 방지와 기존 계약/입력 검사를 포함한다.
npm run typecheck:mobile 통과. 루트 TypeScript 검사는 npm test의 build:contracts에서 통과.
외부 WebCodecs 선언과 TypeScript 7 DOM 선언 충돌 때문에 skipLibCheck=true를 적용.
자체 소스의 strict 검사는 유지. ESNext.Disposable 타입 선언을 추가했으며 명시적 close/dispose를 사용한다.

검증의 한계
- 지원하는 유효 MP4/H.264에서 완전성 검사가 성공한 결과만 전체 추출로 인정한다.
- 모든 손상 파일/특이 edit-list/다중 영상 트랙/HEVC/임의 컨테이너를 지원한다는 의미가 아니다.
- 회전 메타데이터를 적용하지만 이번 합성 입력은 0도다. 실제 회전 태그 휴대폰 영상은 후속 시험 대상이다.
- Galaxy Wide5 Android 13의 WebView/하드웨어 코덱, 장시간·고해상도 메모리/성능/백그라운드 동작은 미검증.
- Android 빌드 성공과 기기 실행 성공은 구분한다. 실기기 검증은 사용자 요청대로 보류했다.
