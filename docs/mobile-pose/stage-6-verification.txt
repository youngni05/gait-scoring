6단계: coords-1 생성·검증·개발용 JSON 다운로드·mock 전달
버전 0.6.0 / Android versionCode8
수동 서 있기 정답 비교와 갤럭시 실기기 검증은 사용자 요청으로 계속 보류한다.

구현
- JsonCoordsSerializer가 ProcessingInput/VideoInfo/PoseFrame/marks를 받아 계약의 허용 필드만 구성한다.
- capture.mode=guided는 기존 개발 시험 계약의 모드다. 실제 영상이 촬영 프로토콜을 준수했다는 판정이 아니다.
- 원본값을 먼저 검증한 후 좌표 x/y/z/visibility만 최대 소수점5자리로 반올림한다.
- NaN/Infinity/범위를 벗어난 visibility/관절수 오류는 반올림으로 숨기지 않고 실패한다.
- 원본 배열은 변경하지 않는다. t는 원본 숫자를 그대로 사용하고 JSON parse 왕복으로 보존한다.
- 미검출 lm:null, 서 있기 미검출 양쪽null을 유지한다.
- 촬영일 출처·회전·자동 검출 상태/사유/규칙버전·모델 자산버전은 별도 로컬 metadata이며 coords-1에는 추가하지 않는다.
- 본문에는 영상/음성/이미지/파일명/로컬 경로가 없다. JSON Schema의 additionalProperties=false와 명시적 필드 구성을 사용한다.
- 전달 경계에서 본문과 메타데이터의 허용 키·검출 구간 일치 등을 다시 검사한다.

UI와 식별자
- 아래 시험 입력의 ID·키·촬영일·출처를 JSON 생성 시 스냅샷으로 고정한다. 촬영일 미입력은 실패.
- 파일 선택 때 recording_id UUID 생성. 같은 영상의 관절 재추출이나 mock 재시도에서 유지한다.
- JSON 새 생성 때 requestId 생성. 오류/취소 뒤 단순 재시도에서는 recording_id/requestId/본문이 모두 유지된다.
- 입력값 변경 시 기존 JSON과 대기 mock 작업을 폐기한다. 다른 파일 선택/해제/새 추출 시 이전 결과도 폐기한다.
- 다운로드는 좌표 본문 JSON만 생성하며 메타데이터를 본문에 합치지 않는다. 생성 Blob URL은 교체/입력변경/해제 때 정리한다.
- 파일명은 개발용임을 표시하고 원본 영상 파일명을 사용하지 않는다. 다운로드 파일을 Git에 넣지 않도록 화면에 안내한다.
- 생성 완료, mock 대기, mock 실패/취소, mock 접수 성공을 분리한다. 실제 서버 접수·분석 완료라는 메시지는 없다.

mock과 실제 연결 경계
- MockUploadGateway는 fetch/XHR/토큰/DB/실제 서버를 사용하지 않는다. 1초 대기로 성공/시간초과/네트워크/인증 오류를 재현한다.
- 타임아웃은 mock 실패 시나리오이며 실제 HTTP 제한시간 구현이 아니다.
- 동일 요청ID/동일 본문의 성공 재시도는 같은 mock receipt를 반환한다. 동일 요청ID에 다른 본문은 conflict.
- 테스트 상황을 실패로 바꾸면 이전에 성공했어도 실패를 재현할 수 있고, 다시 성공으로 바꾸면 기존receipt를 반환한다.
- mock의 수명 내 중복 접수 시험일 뿐, 모바일이나 실제 서버의 중복 방지를 보장하지 않는다.
- InjectedUploadGateway는 명시적으로 제공한 transport만 호출하는 연결 경계다. UI에서 생성하지 않는다.
- 실제 HTTP URL/토큰/인증/응답 포맷은 팀원 계약 확정 후 transport가 구현해야 한다. 현재 실서버 연결 대기.
- 기존 로컬-only CSP를 유지한다. 추후 실서버 연결 시 명시적인 정책 검토가 필요하다.
