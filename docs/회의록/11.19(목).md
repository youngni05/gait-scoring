## 회의 내용

### 사회복지사의 앱 사용 흐름 정리

앱 이름은 **‘자동보행분석기’**로 두고, 사회복지사가 휴대폰에서 대상자를 선택한 뒤 필요한 작업을 바로 시작할 수 있도록 화면 흐름을 정리함. 로그인 후 대상자 목록에서 한 사람을 선택하면 **‘이전 결과 조회’와 ‘영상 업로드’** 중 하나를 선택하도록 구성함.

- **이전 결과 조회** — 선택한 대상자의 평가 기록을 목록으로 표시하고, 기록을 누르면 해당 평가의 결과지를 확인할 수 있도록 함.
- **영상 업로드** — 대상자의 보행 영상을 선택하면 분석 진행 상태를 표시하고, 분석이 끝나면 결과지를 확인하고 다운로드할 수 있도록 함.
- **대상자 등록·수정** — 신규 대상자는 이름, 성별, 생년월일, 키를 입력해 등록하고, 이후에도 해당 정보를 수정할 수 있도록 함.

### 보행 분석 결과지 및 모바일 디자인 시안

결과지 상단에는 대상자의 이름, 나이, 성별, 키를 표시하고, 주요 평가 결과로 **GDI 점수, 분당 걸음 수(케이던스), 좌우 대칭성**을 제시하는 방향으로 정리함. 고관절·무릎·발목의 움직임은 그래프로 표시해 점수와 함께 살펴볼 수 있도록 함.

휴대폰 화면에 맞는 디자인 초안을 만들기 위해 Stitch와 UX Pilot의 활용 방안을 검토함. 특히 UX Pilot에 사용할 프롬프트에는 로그인부터 결과 다운로드까지의 화면 흐름과 결과지에 들어갈 항목을 구체적으로 정리함.

### 로컬 실행 환경 점검

Docker Compose로 **FastAPI 서버와 PostgreSQL 데이터베이스가 로컬에서 실행되는 것을 확인함.** API 서버는 8000번 포트로 실행되었고, 데이터베이스는 정상 상태로 표시됨.

다음 점검 항목은 데이터베이스 초기 설정, 테스트용 사회복지사 계정 생성, API 문서 확인으로 정리함. 이후 프론트엔드에서 로그인과 영상 처리 흐름을 테스트하고, 실제 GDI 점수 산출은 모델을 연결한 뒤 확인하기로 함.
