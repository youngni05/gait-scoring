## 회의 내용

### 앱 디자인 검토 및 결과 화면 구성

UX Pilot에서 제작한 **‘해피에이징’ 디자인 시안 22개 화면**을 현재 앱과 비교함. 기존 React·Vite·Capacitor 개발 환경을 유지하고, 사회복지사가 사용하는 순서에 맞춰 로그인, 대상자 목록, 대상자 상세 화면부터 시안을 적용하는 방향으로 정리함.

결과지 구현에 앞서 모델이 제공하는 값과 화면 표시 항목을 맞출 필요가 있음을 확인함. 현재 앱에는 GDI·보폭·케이던스가 표시되며, 시안에 포함된 좌우 대칭 지표와 관절 그래프는 계산 방식과 필요한 데이터를 먼저 정리하기로 함. 모델이 좌우 다리의 GDI를 각각 예측하므로, 이를 결과지에서 대표 점수 하나로 표시할지 좌우 점수로 나누어 표시할지도 검토 사항으로 남김. 또한 관절 좌표 저장이 끝난 시점과 모델 분석이 시작된 시점을 구분해 실제 진행 상태를 안내할 필요가 있음.

### 발표용 시스템 구조도 및 관절 추출 방식

발표 자료에는 통합 후의 시스템을 기준으로 **영상 선택 → 관절 좌표 추출 → GDI·보행 지표 분석 → 결과 저장 → 대상자별 결과 조회** 흐름을 담기로 함. 백엔드는 로그인, 대상자 관리, 분석 요청과 결과 저장을 담당하고, AI 분석은 별도 서비스에서 수행하는 방안을 검토함. 두 서비스를 처음에는 같은 컴퓨터에서 실행하는 안이 제안되었으며, 실행 위치와 연결 방식은 추가 논의 사항으로 남김.

현재 방식은 휴대폰에서 MediaPipe로 관절 좌표를 추출해 서버로 전송하는 구조임. OpenPose로 변경할 경우에는 휴대폰에서 처리할 수 있는지 먼저 확인하고, 서버에서 추출해야 한다면 원본 영상을 전송하는 방식도 검토하기로 함. 추출기 선택 시에는 관절 좌표의 품질과 최종 GDI 예측에 미치는 영향을 함께 비교하기로 함.

### 측정·저장 과정의 오류 점검

측정 중 화면을 벗어나는 경우, 저장 응답이 늦게 도착하는 경우, 목록 조회 요청이 과도하게 발생하는 문제, 값이 0일 때 그래프가 잘못 표시되는 문제를 검토하고 로컬 작업본에 수정함. 자동 테스트 157개와 타입 검사, 배포용 빌드는 통과함. 실제 브라우저와 데이터베이스를 연결한 통합 테스트는 후속 확인 사항으로 남았으며, 수정본을 팀 검토용 브랜치와 PR로 공유하는 작업은 GitHub 쓰기 권한 오류로 당일 완료하지 못함.
