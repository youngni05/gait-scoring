## 회의 내용

### 팀원 간 데이터 공유 및 AWS 배포 현황

한 팀원이 등록한 대상자가 다른 팀원의 화면에 보이지 않는 원인을 점검함. 각자 PC에서 Docker를 실행하면 서로 다른 데이터베이스를 사용하므로, 팀원들이 휴대폰에서 같은 대상자와 보행 기록을 조회하려면 공용 백엔드와 데이터베이스에 접속해야 함을 확인함.

당일 배포 점검에서는 **AWS 시드니 리전의 EC2 인스턴스 한 대**에서 모바일 웹, FastAPI 백엔드, PostgreSQL 데이터베이스, 보행 분석 프로그램이 실행 중인 것을 확인함. API와 데이터베이스가 연결되었고, 분석 프로그램이 샘플 관절 좌표에서 분당 걸음 수를 계산하는 것까지 확인함. 다만 외부 휴대폰에서 영상을 선택한 뒤 최종 모델의 GDI 점수가 결과지에 표시되는 전체 과정은 추가 검증 항목으로 남김.

### 분석 결과 저장 기능 점검

통합된 코드의 자동 테스트와 브라우저 테스트 결과를 확인함. 특히 네트워크가 끊겨 **저장 버튼을 눌렀지만 결과가 저장되었는지 알기 어려운 상황**을 검토함. 사용자가 다시 시도할 때 같은 요청이 중복 실행될 가능성을 줄이고, 처리 상태가 불분명한 요청을 복구할 수 있도록 데이터베이스 구조 변경 없이 보완 커밋을 작성함. 해당 수정은 로컬 테스트를 통과했으며, 공용 환경에 반영한 뒤 동작을 다시 확인할 필요가 있음.

### 중간발표 시스템 구조도 및 기업 인계 일정

11월 23일 중간발표에서는 **복지사가 휴대폰에서 보행 영상을 선택한 뒤, 나중에 같은 대상자의 결과지를 다시 열어보기까지**의 흐름을 구조도로 설명하는 방향을 정리함. 휴대폰은 영상에서 2D 관절 좌표를 추출하고, 서버는 전달받은 좌표로 GDI 점수와 보행 지표를 계산한 뒤 해당 촬영 기록에 결과를 저장하는 구조임.

향후 일정의 **기업 인계** 단계에서는 문서가 먼저 준비되어 있어야 한다는 점을 고려해, 기존의 ‘가이드 작성·명세 작성’을 **‘운영 가이드 및 시스템 명세서 전달’**로 수정하는 방안을 논의함.
