## 회의 내용

### 휴대폰 영상 처리 및 서버 분석 방식

복지사가 휴대폰에서 대상자의 보행 영상을 선택하면, 기기에서 MediaPipe로 33개 관절의 좌표를 추출하기로 함. 원본 영상은 휴대폰에 두고, 서버에는 `coords-1` 형식의 JSON 좌표 데이터만 전송하기로 함. 서버에서는 이 좌표를 이용해 모델로 GDI 점수를 예측하고, 규칙 기반 분석으로 세부 보행 지표를 계산하기로 함. **GDI 점수와 세부 보행 지표를 모두 1차 앱의 필수 결과로 정함.**

분석에 사용할 영상은 카메라를 측면에 고정하고, 한 사람이 보조기 없이 걷는 조건을 기준으로 삼음. 영상에서 대상자가 서 있는 구간은 앱이 자동으로 찾아내는 방식으로 정리함.

### 1차 앱의 기능 및 개발 환경

복지사가 이메일로 가입·인증한 뒤 대상자를 등록하고, 대상자별로 보행 분석 결과를 저장·조회할 수 있도록 함. 같은 대상자의 이전 평가 기록을 다시 열어 점수와 보행 지표의 변화를 살펴볼 수 있도록 개발 범위를 정함.

앱은 **React·Vite·TypeScript와 Capacitor**로 개발하고, 서버는 **FastAPI**, 데이터베이스는 **PostgreSQL**을 사용하기로 함. 1차 목표는 **3주 안에 안드로이드 휴대폰에 APK로 설치해 테스트할 수 있는 앱을 만드는 것**으로 정함.

### 팀원별 개발 및 통합 계획

팀 공용 GitHub 저장소인 `gait-scoring`에서 담당 작업을 별도 브랜치로 진행하고, 팀원들의 코드가 준비되면 통합하는 방향을 논의함. 모델 입력에 필요한 좌표 변환과 검증은 분석 담당 범위로 두고, 앱과 서버는 모델 개발을 기다리지 않고 좌표 전송, 대상자 관리, 결과 조회 기능부터 개발할 수 있도록 준비하기로 함.

개발에 들어가기 전, 코딩 에이전트에 작업을 요청할 순서와 각 단계에서 담당자가 직접 확인할 항목을 문서로 정리하기로 함.
