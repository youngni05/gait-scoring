# 대상자 등록·수정 화면

2026-11-18 · `feature/participant-management`

기준 main: `19b9ebcaa2f3ae79c9b4873fcec691bc99b183a1` (PR #8 병합 후).
이번 변경은 프론트 코드, 테스트, 문서이며 백엔드와 DB 마이그레이션은 변경하지 않는다.

## 동작

- 로그인 후 ‘새 대상자 등록’으로 이름·성별·생년월일·키를 입력한다. 등록 성공 응답을 확인하면 목록에 반영하고 해당 대상자를 선택한다.
- 기존 대상자는 ‘선택한 대상자 수정’에서 변경한다. 기존 정보가 비어 있으면 함께 채운다. 필드 4개를 검증하지만 PATCH에는 변경한 필드만 보낸다. 변경 사항이 없으면 요청하지 않는다.
- 이름은 앞뒤 공백 제거 후 1~100자, 날짜는 유효한 달력 날짜이면서 한국 기준 오늘 이하여야 한다. 키는 백엔드 프로필 규격에 맞춰 0 초과~999.99cm, 소수 둘째 자리까지 허용한다.
- 프로필 등록 범위와 영상 처리 범위는 다르다. 키 100~220cm 밖에서는 현재 영상 처리 제한을 안내한다.
- 수정은 `/participants/{id}`에만 전송한다. 기존 측정 ID·촬영 당시 나이·좌표·측정 요청 본문을 수정하지 않는다. 진행 중인 영상 측정의 키 입력도 덮어쓰지 않는다. 다음에 대상자를 다시 선택하면 갱신된 기본 키로 시작한다.
- 등록 완료로 대상자를 바꾸기 전에 기존 측정 상태를 확인하도록 안내한다. 수정 화면에서는 대상자 변경·목록 새로고침을 막아 입력 도중 대상자가 뒤바뀌지 않게 한다.
- 중복 클릭을 막고 화면이 사라진 뒤 늦게 도착한 저장 응답은 무시한다. 목록 조회의 오래된 응답이 저장 결과를 덮어쓰지 않도록 조회를 취소한다.

## 오류와 재시도

대상자 POST에는 측정 저장과 달리 중복 방지 키가 없다.
타임아웃·네트워크 오류·5xx·잘못된 성공 응답이면 이미 저장되었을 수 있으므로 저장 버튼을 막는다.
‘닫고 목록 확인’으로 목록을 새로고침한 뒤 실제 반영 여부를 확인한다. 자동 재등록은 하지 않는다.
401은 같은 계정으로 인증을 갱신한 뒤 입력을 유지한 채 다시 시도할 수 있다.
422는 입력을 수정해 다시 시도하며 서버의 원본 입력이나 민감한 상세 오류를 화면에 반사하지 않는다.
다른 사용자가 같은 대상자를 동시에 수정하는 경우의 버전 충돌 감지는 기존 API가 지원하지 않으므로 이번 변경에 포함되지 않는다.

## 검증

- 기존 테스트와 신규 8개 사례를 포함한 `npm test`: 141개 통과.
- 계약·모바일 TypeScript 검사와 모바일 production 빌드 확인.
- 신규 사례: 한국 날짜 경계, 윤년·미래일·잘못된 날짜, 이름·성별·키 검증, 변경 필드 PATCH, JSON 등록, 잘못된 응답, 응답 유실 시 자동 재등록 방지.
- 자동 테스트는 가짜 HTTP transport를 사용한다. 실제 서버와 브라우저 UI·갤럭시 검증은 사용자가 요청한 대로 후속 통합 단계에 남겨 둔다.

서버 준비 후 확인 순서:

1. 합성 대상자 등록 → 자동 선택 → 서버 목록에 1건 표시.
2. 생년월일·키 수정 → 목록 반영 → 기존 측정 기록의 나이가 유지되는지 확인.
3. 영상·좌표가 준비된 상태에서 프로필 수정 → 기존 촬영 당시 키와 저장 요청이 유지되는지 확인.
4. 등록 응답 유실 시 바로 재등록할 수 없고 목록 확인으로 연결되는지 확인.
5. 로그인 만료 → 같은 계정 인증 갱신 → 입력 유지 후 저장.

Frontend CI와 Backend CI가 모두 통과한 뒤 PM이 PR을 최종 검토하고 병합한다.
