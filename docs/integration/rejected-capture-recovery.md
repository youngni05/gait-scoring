# 저장 요청 복구 및 안전한 다시 시작 (DB 변경 없음)

브랜치: codex/rejected-capture-recovery. 기존 b7d5150 커밋의 재검토 결과를 반영한 후속 수정입니다.

## 동작

- 저장 응답을 잃으면 요청 ID와 전송 본문을 보관합니다. 다시 시도할 때 서버 조회를 먼저 수행하고, 저장돼 있으면 결과를 열며 없으면 동일 ID/본문으로 재전송합니다.
- 이전 버전의 정상적인 요청 본문도 그대로 복구합니다. 로컬 본문이 손상됐더라도 서버의 결과가 확인되면 결과를 엽니다. 서버에도 없고 본문도 손상된 경우는 보존하고 담당자 확인을 안내합니다.
- 413/415/422만으로 정리 가능하다고 판단하지 않습니다. 정상 JSON 오류이며 현재 API의 알려진 거절 사유와 일치해야 합니다. 이전 응답 유실이 있거나 전송 이력을 모르는 요청은 정리하지 않습니다.
- `다시 분석하기`를 누르면 원본 영상/이전 결과는 유지된다는 확인창을 표시합니다. 정상 API의 `Measurement not found` 응답일 때만 임시 요청을 정리합니다. 200 null, HTML 404, 알 수 없는 오류는 보존합니다.
- 동시 시작은 대기열에 넣지 않고 두 번째 실행을 거절합니다. Web Locks가 없어도 IndexedDB 트랜잭션으로 동시 실행을 차단합니다.
- 기기 내 작업 잠금은 90초 유효기간, 20초 갱신 주기를 사용합니다. 오래된 작업을 인계하면 기존 요청은 불확실 상태로 보존합니다. 만료된 작업은 소유자 검증에 실패해 데이터를 수정/삭제할 수 없습니다. 화면이 비정상 종료된 경우 잠시 기다린 뒤 다시 시도해야 할 수 있습니다.
- 새 요청은 전송 전 본문 크기(현재 서버 한도 8,000,000바이트)를 확인합니다. 초과하면 저장/전송하지 않고 짧은 영상 선택을 안내합니다. 촬영일은 미래 또는 생년월일 이전 날짜를 차단합니다.
- 네트워크 오류는 연결 확인 후 재시도를 안내합니다. 데이터 형식 오류가 반복되면 담당자 확인을 안내하며, 재분석이 모든 오류를 해결한다고 안내하지 않습니다.

## 변경하지 않은 범위

서버 DB 테이블/마이그레이션, 백엔드 런타임, 클라우드 설정, 모델 계산/가중치는 변경하지 않았습니다. 브라우저의 기존 IndexedDB 저장소를 사용합니다. 서버의 기존 요청 ID 중복 방지 기능을 그대로 활용합니다.

연결이 끊긴 상태에서는 서버 저장 여부를 확정할 수 없습니다. 불확실한 요청의 강제 삭제와 서버 차원의 영구 취소는 이번 범위에 포함하지 않습니다.

## 검증

- 모바일 타입 검사/제품 빌드 및 Python E2E 문법 검사.
- 기존 Node 테스트 174개.
- 실제 Chromium + 제어된 HTTP 응답으로 오류 응답 시 보존, 동시 요청 1회 저장, Web Locks 미지원, 만료 소유자 차단, 이전 버전 본문 복구, 손상 본문 보존, 크기 제한 및 기존 저장·복구 흐름 검증.
- CI용 모바일 테스트에 잘못된 응답, IndexedDB 동시 실행, 만료 소유자, 크기 초과 시나리오를 추가했습니다. 실제 API/DB 통합 CI는 push 후 확인해야 합니다.
