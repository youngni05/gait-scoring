# 거절된 저장 요청 정리 및 새 분석

기준 main: 9d82b6c (PR #19). 브랜치: codex/rejected-capture-recovery.

## 사용자 동작

서버가 저장 요청을 명확히 거절하면 응답 코드와 안내를 표시합니다. 안전한 경우에만 `실패한 요청 정리하고 새로 분석` 버튼을 제공합니다. 확인창에서 취소하면 보존합니다. 동의한 경우 서버를 다시 조회해 기존 결과가 있으면 그 결과로 이동하고, 404이면 기기의 임시 요청만 정리하여 영상 선택으로 돌아갑니다. 원본 영상과 서버 결과는 삭제하지 않습니다. 연결/권한/서버 오류 또는 계정 변경 시 정리를 중단합니다.

## 안전 범위

- 이번 버전에서 생성한 요청의 전송 상태를 IndexedDB에 기록합니다. 전송 직전에 unconfirmed를 먼저 저장합니다.
- 이전 응답 유실이 없는 요청이 413/415/422로 거절된 경우에만 rejected로 기록합니다. 401/403/409/429/5xx, 중단, 연결 실패는 정리 근거가 아닙니다.
- 이전 버전의 요청과 응답 유실 이력이 있는 요청은 이후 거절되더라도 정리를 허용하지 않습니다. 서버 기록 확인/담당자 조사가 필요합니다.
- Web Locks로 같은 계정/API/대상자의 전송과 정리를 탭 사이에서 직렬화합니다. Web Locks 미지원 환경에서는 정리 기능을 제공하지 않습니다.
- UI는 동시 정리를 막고 화면 이탈 시 확인 요청을 취소합니다. 같은 요청 ID인 경우에만 임시 데이터를 지웁니다.
- 모든 오류를 해결하는 강제 삭제 기능이 아닙니다. 서버 저장 여부가 불확실한 데이터는 계속 보관합니다.

백엔드, DB, 클라우드 배포 설정, 모델 계산 로직은 변경하지 않았습니다.

## 검증

모바일 타입 검사와 제품 빌드, Python E2E 문법 검사가 통과했습니다. 새 브라우저 시나리오 4개와 기존 저장·복구 시나리오 7개가 통과했습니다. 브라우저에서 거절 후 새로고침/확인창 취소/정리, 확인 오류 시 보존, 기존 결과로 이동, 응답 유실 후 거절 시 정리 차단을 검증합니다. HTTP 응답은 제어된 테스트 응답을 사용합니다.

기존 Browser Integration CI에 새 모바일 테스트 3개를 추가했습니다. 실제 CI 결과는 PR에서 확인해야 합니다.
