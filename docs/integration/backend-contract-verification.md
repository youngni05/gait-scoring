# 백엔드 측정 저장 계약: 구현 및 검증

2026-11-18 · 브랜치 `feature/backend-measurement-contract`

## 구현 범위

- `processing_metadata` JSONB 컬럼과 사용자별 요청 키 테이블을 추가했다. 기존 측정 데이터는 유지하며 기존 클라이언트의 4필드 요청도 지원한다.
- 신규 요청은 메타데이터와 UUID `Idempotency-Key`를 함께 제출한다. 서버는 coords-1 구조, 유한한 숫자, 시간 순서, 관절 개수, 촬영 시각·추출기·검출 구간의 일치를 검사한다.
- 측정 저장과 요청 키 저장은 하나의 트랜잭션이다. 같은 사용자·키·대상·본문 바이트의 재전송은 200과 기존 응답을 반환한다. 최초 저장은 201이다. 다른 본문이나 대상은 409이다.
- 동시 요청은 PostgreSQL의 고유 제약으로 처리한다. 경쟁에서 진 측정 행은 롤백한다. 잠금 대기 2초 초과는 409 `REQUEST_IN_PROGRESS`와 `Retry-After: 2`를 반환한다.
- CORS에 요청 키를 허용하고 Retry-After를 노출했다. 422 검증 오류에서 원본 입력을 제외해 좌표 반사와 NaN 직렬화 오류를 방지한다.
- API 명세와 전송 계약을 갱신했다. 기존 결과 조회 형식과 AI 실행 흐름은 변경하지 않았다.

## PR에서 확인할 검증

Backend CI는 PostgreSQL 17에서 기존 마이그레이션 왕복·스모크 검사에 더해 14개 통합 테스트를 실행한다.
기존 데이터 유지, 로그인·저장·조회, 메타데이터 보존, 재전송, 사용자별 키 범위, 대상 변경 충돌,
한국 시간 기준 나이, 잘못된 요청·인증, 동시 저장, 실제 잠금 대기·롤백 후 재시도, CORS를 포함한다.
테스트 작성 완료와 테스트 통과는 다르므로 CI 성공 전 병합하지 않는다.

테스트 DB는 이름이 `_ci`로 끝나고 `GAIT_TEST_DB_WRITES=1`이어야 한다.
테스트는 임의 UUID 이름의 격리 스키마만 생성·정리한다. 운영 DB에 실행하지 않는다.

## 병합과 후속 통합

1. 브랜치를 게시하고 main 대상 PR을 만든다. 기존 프론트 계약 PR은 main에 병합된 상태이다.
2. Backend CI 및 프론트 CI 결과와 diff를 확인하고 PM이 최종 병합한다.
3. 테스트 서버에서 `alembic upgrade head`를 적용한 뒤 새 API를 배포한다. 마이그레이션의 downgrade는 신규 메타데이터와 요청 키를 삭제하므로 데이터 보존용 롤백 수단으로 사용하지 않는다.
4. 프론트 HTTP 어댑터를 별도 PR로 연결한다. 재시도는 prepareMeasurement의 동일한 body 문자열과 키를 재사용한다. 저장 성공 응답 전에 완료 표시나 receipt를 만들지 않는다.
5. 실제 테스트 서버에서 로그인 → 대상 선택 → 영상 처리 → 저장 → 재시도 → 목록·결과 조회를 확인한다.
6. GDI 연결은 모델 입력·출력, 버전, 실패 상태 계약을 확정한 뒤 진행한다. 현재 좌표 검증 통과가 GDI 계산 가능성이나 정확성을 보증하지 않는다.

기존 기관 내 공유 접근 정책은 유지했다. 사용자별 요청 키 범위가 환자·기관별 접근 권한을 새로 구현한 것은 아니다.
모바일 실기기 및 테스트 서버 검증은 이 로컬 검증 결과에 포함되지 않는다.
