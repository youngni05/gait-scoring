# 한국어 이슈 양식

제목에는 사용자에게 보이는 문제나 바꾸려는 행동을 한 문장으로 씁니다. 아래의 설명은 작성 안내이며, 실제 이슈에는 해당하는 내용만 남깁니다.

## 버그

```markdown
## 현재 동작
어느 화면에서 무엇을 하면 어떤 문제가 생기는지, 사용자에게 어떤 영향이 있는지 적습니다.

## 재현 방법
1. 시작 조건과 화면을 적습니다.
2. 문제를 일으키는 행동을 순서대로 적습니다.

## 기대 동작
같은 상황에서 사용자가 볼 수 있어야 하는 결과를 적습니다.

## 확인 범위
사용자 보고·코드 확인·실행 재현 중 어디까지 했는지 적습니다. 확인한 기기나 버전이 있으면 덧붙입니다.

## 완료 기준
- [ ] 같은 조건에서 기대 동작이 나타나는지 확인합니다.
- [ ] 수정으로 영향을 받을 수 있는 기존 동작을 확인합니다.
```

## 기능 개선

```markdown
## 사용 상황
누가 어떤 일을 하다가 불편을 겪는지 적습니다.

## 제안
사용자가 무엇을 할 수 있게 되는지 적습니다.

## 완료 기준
- [ ] 사용자가 개선된 흐름을 끝까지 수행할 수 있습니다.
- [ ] 해당하는 빈 상태·오류·취소 상황의 동작을 확인합니다.
```

## 개발 작업

```markdown
## 목표
변경이 필요한 이유와 작업이 끝난 뒤의 상태를 적습니다.

## 작업 범위
바꿀 부분과 바꾸지 않을 부분을 구분합니다.

## 완료 기준
- [ ] 확인 가능한 변경을 항목별로 적습니다.
```

관련 이슈가 있으면 `## 관련 이슈`에 번호를 연결합니다. 증거는 공개 가능한 예시만 사용합니다.
